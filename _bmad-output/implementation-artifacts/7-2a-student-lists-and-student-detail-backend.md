## Story

As a Teacher or Admin/Owner,
I want a role-scoped student roster read model (center-wide for admin/owner, own-classes for teachers) with performance aggregates and an at-risk signal, a per-student detail composition, and a teacher-notes surface,
so that the s42/s10a/s10 UI (Story 7-2b) can render and operate student monitoring over a correct, tenant-isolated, role-scoped, aggregation-in-SQL backend.

Backend slice only. The **s42 center-wide list / s10a teacher roster / s10 detail UI + notes composer is 7-2b**. Per D14 the read shapes are **provisional** — co-finalized when 7-2b is designed against the real generated `client.ts` — but the backend behavior + tests are fully built here.

## Decisions (D1–D14 — all SPEC; D1/D4/D8/D9 are Ducdo rulings 2026-09-06)

- **D1 — Split (Ducdo).** 7.2 → **7-2a (Backend, this)** + **7-2b (Frontend s42/s10a/s10 + notes UI)**. 7-2a is the keystone: read models + derivations + at-risk + notes + pagination so 7-2b is UI wiring. Re-keys sprint-status (`7-2` → `7-2a`+`7-2b`). Mirrors 7-1a/7-1b.
- **D2 — Students are `center_members` rows with `role='student'` ⋈ `users`, NOT a `students` table.** There is no students table (recon-confirmed). Center-wide roster = every `center_members` row of the tenant with `role='student'` joined to `users` for name/email/avatar. Enrollment rows (`enrollments`, 3.4.5) link a student to classes. Reuse the **`staff.sql` LATERAL-aggregate + split-response + clock-bound-arg** pattern (7-1a) verbatim in shape — do NOT invent a new roster idiom.
- **D3 — ONE role-scoped `GET /api/students`, not two endpoints. s42 and s10a are the same endpoint scoped by caller role.** admin/owner → center-wide (all `role='student'` members); **teacher → ONLY students with an `enrollments` row in a class where `classes.teacher_id = callerUserID`** (the new authz axis — R-SEC). Query params (XL-2 snake_case): `page`, `page_size`, `class_id?` (filter), `teacher_id?` (admin/owner only — a teacher's `teacher_id` filter is ignored/forbidden, they are already self-scoped). Response = `{ data: StudentListItem[], meta: { pagination } }`. Each `StudentListItem`: `studentId, name, email, avatarUrl, enrolledClasses[]{classId,className,teacherName}, teachers[] (distinct names), overallBand (nullable), atRiskStatus ∈ {good,normal,at_risk}, atRiskReasons[], activeEnrollmentCount, archivedAt (nullable), joinedAt`. The **client** derives the tab sets from these fields (D5) — the backend returns rows + the raw status, not pre-filtered tabs.
- **D4 — At-risk = a clock-injected `AtRiskDetector` service (Ducdo), NOT a DB view.** `internal/service/at_risk_detector.go` (the `clock.go:12` named-but-unbuilt stub). Signals (thresholds are named constants, CQ-3), any one trips `at_risk`:
  1. **Attendance floor** — `(present+late)/total_marked < AtRiskAttendanceFloor (0.70)` over the student's attendance rows for sessions of the caller-visible classes. `total_marked=0` → this signal is **not** tripped (insufficient data, not at-risk).
  2. **Consecutive missed** — `≥ AtRiskConsecutiveMissed (2)` most-recent-by-due-date assignments (of the student's active enrollments, `due_at <= clock.Now()`) with NO submission in `{submitted, ai_processing, graded}`. Order by `due_at DESC`; count the leading run of misses.
  3. **Band drop** — over the last `AtRiskGradedWindow (4)` **released** grades (`current_grades`, ordered by `graded_at`/version), `first.overall_band − last.overall_band ≥ AtRiskBandDropDelta (1.0)` (a downward slide, not volatility). `< 4` graded → not tripped.
  `AtRiskDetector.Classify(inputs) → {status, reasons[]}` is pure Go over inputs the roster/detail queries supply as columns (attendance num/denom, the leading-miss run length, the last-4 band slice) — **so the roster classifies the whole page set-based, NO per-row N+1** (dev may run ≤3 batch queries keyed on the page's student-id set; document the seam). Good/Normal split (UX PerfPill has Good/Normal/At-risk, epic defines only at-risk): `at_risk` if any signal; else `good` if `overallBand != null AND overallBand >= class target_band` (on track); else `normal`. The Good/Normal cut is a **spec-fill** (epic silent) — dev-tunable, documented at the detector.
- **D5 — Tabs are CLIENT-derived from D3 fields (7-2b), not backend routes.** s42 tabs = All / At-risk / New / Unassigned / Archived; s10a tabs = All / At-risk / New / By-class (UX ux:466,478 — deliberately different sets). Backend supplies the inputs: `at_risk` = `atRiskStatus=='at_risk'`; `new` = `joinedAt` within `NewStudentWindowDays` (client compares, or backend flags — dev may add a bound-`now` `isNew` if cleaner); `unassigned` = `activeEnrollmentCount==0`; `archived` = `archivedAt != null`; `by-class` = client groups `enrolledClasses`. Mirror `ClassesPage.countByStatus` client-side counting (7-1b D5).
- **D6 — Per-skill band DERIVED via submission → `assignments.exercise_id` → `exercises.skill`; NO stored per-skill column.** `overall_band` (one score/submission) lives on `grades`; `current_grades` (view, `security_invoker=true`, DISTINCT ON submission latest version) is the canonical current-grade reader. `overallBand` = avg of the student's last `OverallBandWindow (5)` **released** current grades. `perSkill{reading,listening,writing,speaking}` = per skill, avg of the student's released current grades whose `submission.assignment.exercise.skill = <skill>`. The `exercises.skill` enum is `reading|listening|writing|speaking|grammar|vocabulary|general` — the breakdown surfaces **only the 4 IELTS skills** (grammar/vocabulary/general excluded from the 4-box breakdown; still counted in `overallBand`). A skill with no graded submission → `null` (not 0).
- **D7 — `student_notes` (net-new table) + list/create/flag/soft-delete; attachments COLUMN ships empty.** Cols (epic §7.2): `id, center_id, student_id (→users), author_id (→users), content text, flagged boolean DEFAULT false, attachments jsonb DEFAULT '[]', created_at, updated_at, deleted_at (nullable — soft-delete per [[feedback_soft_delete_user_authored_content]])`. 4-policy RLS grid on `center_id` (clone enrollments/attendance). Endpoints: `GET /api/students/{id}/notes` (chronological ASC, non-deleted), `POST /api/students/{id}/notes {content, flagged?}`, `PATCH /api/students/{id}/notes/{noteId} {flagged}` (flag toggle), `DELETE /api/students/{id}/notes/{noteId}` (soft-delete, author-or-owner/admin). Notes are **staff-visible only** — a student caller never reads/writes notes (403). Author name resolved for the log.
- **D8 — Defer attachments + @mention (Ducdo).** The `attachments jsonb` column ships (forward-compatible, defaults `'[]'`) but **no R2 presign wiring and no @mention parse/notify in 7-2a** — those need a user-search + a notification spine that overlaps Epic 10 Inbox. **Flagging ships** (epic-specified + UX flag/warn variants). Tracked as **FU-7-2-A** (attachments) + **FU-7-2-B** (@mention) → deferred-work.md.
- **D9 — Trend/projection deferred to Epic 8 (Ducdo); detail ships band+per-skill+attendance+stats + a lightweight delta.** `GET /api/students/{id}` returns band/per-skill/attendance%/submission-stats NOW, plus `currentVsFirstDelta` (avg of last N released − avg of the student's first-month released grades) and the enrolled classes' `target_band` for a client target comparison. The **`BandTrendSparkline` + projected-to-reach-target-by-week-N algorithm are OUT (→ Epic 8 analytics, component-inventory ci:15/25/203 already defers them)**; likewise `StudentMistakesList`/`RecommendationsList` (ci:207-208, Epic 8). Class `target_band` is on the **`classes`** table (confirmed arch:303/313); there is **no per-student target** in v1 (only class-level).
- **D10 — Roster pagination (CR-3-4-5-3, Ducdo 2026-07-24) lands HERE.** Add `page`/`page_size` + `{data, meta:{pagination}}` (XL-2: `OFFSET (page-1)*page_size LIMIT page_size`, plus a total count) to **BOTH** the new `GET /api/students` AND the existing `GET /api/classes/{classId}/enrollments` (`ListEnrolledStudentsByClass` currently returns the full active roster with no LIMIT — deferred-work.md:558/578). Defaults `DefaultPageSize (20)`, `MaxPageSize (100)` (reuse the app-wide pagination constants/meta shape if one exists; else mirror the shipped list endpoints).
- **D11 — Read authz: `RequireRole("owner","admin","teacher")` at the chain + role row-scoping in service; note mutations re-validate.** Students cannot list/read the roster or notes (403 `INSUFFICIENT_ROLE` at the edge). In-service: teacher scopes to own-classes' enrolled students; a teacher requesting `GET /api/students/{id}` for a student **not in any class they teach → 404 `STUDENT_NOT_FOUND`** (non-disclosure, never 403). Reads follow the app-wide policy (JWT-claim `RequireRole` for reads; the 15-min TTL bounds staleness — 7-1a deferred note). Note **writes** (create/flag/delete) re-validate the caller's `center_members.role` + visibility from the DB (SEC-1) inside the tx.
- **D12 — Detail composition (`StudentDetail`).** profile `{studentId, name, email, avatarUrl, languagePref, joinedAt}`, `enrolledClasses[]{classId, className, teacherName, targetBand}`, `performanceSummary {overallBand, perSkill{reading,listening,writing,speaking}, attendanceRate, pendingCount, missingCount, onTimeRate, currentVsFirstDelta}`, `atRisk {status, reasons[]}`, `notes[]{noteId, authorName, content, flagged, createdAt}` (chronological). Role-scoped exactly as D11. `pendingCount` = assignments due-or-upcoming with no submission yet; `missingCount` = past-due with no submission; `onTimeRate` = submissions submitted `<= due_at` / total submitted.
- **D13 — RLS / tenancy (GO-1, PERF-1, TEST-BE-1).** Every store method takes `TenantContext`; every mutating tx `SET LOCAL app.current_tenant_id`. The cross-table read (`center_members`+`users`+`enrollments`+`classes`+`attendance`+`submissions`+`assignments`+`grades`/`current_grades`+`student_notes`) rides the existing per-table `center_id` grid; `users` reads are keyed by ids already tenant-filtered upstream (a student is only read for a userId proven a center member first). No aggregate subquery escapes the tenant GUC. `student_notes` gets the standard 4-policy grid.
- **D14 — Read wire contracts PROVISIONAL (mirror 7-1a D10 / 6-4a D16).** 7-2a is the producer; **7-2b is the sole consumer**. Build `StudentListItem`, `StudentDetail`, `StudentNote`, the pagination meta, and the notes request/response as working contract with full tests, but mark the new **read** shapes **provisional** in `api.yaml` — 7-2b co-finalizes (strips markers + regen) when the UI validates every field end-to-end. The notes **mutation** endpoints are stable (not provisional).

## Acceptance Criteria

### A. Student roster read — `GET /api/students` (role-scoped, paginated)

1. **Given** an Admin/Owner calling `GET /api/students?page=1&page_size=20`, **When** it runs, **Then** it returns `{ data: StudentListItem[], meta: { pagination: {page, pageSize, total, totalPages} } }` where `data` = center-wide `center_members` rows (role=`student`) ⋈ `users`, each carrying `enrolledClasses[]`, `teachers[]`, `overallBand` (nullable), `atRiskStatus`+`atRiskReasons[]` (D4), `activeEnrollmentCount`, `archivedAt` (nullable), `joinedAt` — page-sliced, `total` = the full tenant student count for the applied filter (D3/D10).
2. **Given** a **Teacher** calling `GET /api/students`, **Then** `data` contains ONLY students with an `enrollments` row in a class where `classes.teacher_id = callerUserID` (never another teacher's roster), still paginated, at-risk/aggregates scoped to the caller-visible classes. **And** a `teacher_id` query param from a teacher is a no-op (they are already self-scoped).
3. **Given** a **Student** calling `GET /api/students`, **Then** 403 `INSUFFICIENT_ROLE` (the roster is staff-only; `RequireRole("owner","admin","teacher")` fires before the handler).
4. **Given** filters, **Then** `class_id` narrows to students enrolled in that class (in-tenant; a class the teacher does not teach → empty/own-scope, never another teacher's data); `teacher_id` (admin/owner only) narrows to that teacher's enrolled students. Unknown/foreign `class_id`/`teacher_id` → empty page, not another tenant's rows.
5. **Given** pagination bounds, **Then** `page<1`→1, `page_size` clamped to `[1, MaxPageSize(100)]`, default `DefaultPageSize(20)`; `OFFSET (page-1)*page_size` (XL-2). An out-of-range page → empty `data` with correct `meta.total`.

### B. Student detail read — `GET /api/students/{id}`

6. **Given** an Admin/Owner calling `GET /api/students/{id}` for a `role='student'` member of this center, **Then** it returns `StudentDetail` per D12: profile, `enrolledClasses[]{classId,className,teacherName,targetBand}`, `performanceSummary {overallBand, perSkill{reading,listening,writing,speaking}, attendanceRate, pendingCount, missingCount, onTimeRate, currentVsFirstDelta}`, `atRisk{status,reasons[]}`, `notes[]` (chronological).
7. **Given** a **Teacher** calling `GET /api/students/{id}` where the student is enrolled in a class the teacher teaches, **Then** the detail returns **scoped to the teacher's classes** (enrolledClasses/attendance/aggregates over the caller-visible classes only). **Given** the student is NOT in any class the teacher teaches (or the id is not a student / not a center member) → **404 `STUDENT_NOT_FOUND`** (non-disclosure, never 403, D11).
8. **Given** a Student caller, **Then** 403 `INSUFFICIENT_ROLE`.

### C. Per-skill band + attendance + submission aggregates (query correctness)

9. **Given** the band aggregates (D6), **Then** `overallBand` = avg of the last `OverallBandWindow(5)` released current grades (`current_grades`, `released_at IS NOT NULL`); `perSkill[skill]` = avg released band for that `exercises.skill` (only reading/listening/writing/speaking surfaced), `null` when no graded submission for that skill; a student with zero released grades → `overallBand=null`, all `perSkill=null`. Only the caller-visible classes' submissions count for a teacher.
10. **Given** the attendance aggregate (D6/3.5b), **Then** `attendanceRate = (present+late)/total_marked` over the student's attendance rows for caller-visible sessions; `total_marked=0` → `attendanceRate=null` (not 0). `onTimeRate` = submissions with `submitted_at <= assignment.due_at` / total submitted; `pendingCount`/`missingCount` per D12. Cross-tenant + other-teacher sessions excluded.
11. **Given** the at-risk classification (D4), **Then** `atRiskStatus='at_risk'` iff any of: attendance `<0.70` (with `total_marked>0`); `≥2` consecutive most-recent past-due missed assignments; band drop `≥1.0` across the last 4 released grades. `reasons[]` names each tripped signal. Insufficient data (no attendance / <4 grades / no past-due assignments) does **not** trip that signal. Else `good` when `overallBand>=class target_band`, else `normal`. All thresholds are named constants.

### D. Teacher notes — `student_notes`

12. **Given** `POST /api/students/{id}/notes {content, flagged?}` from a Teacher (for a student in their class) or Admin/Owner, **Then** a `student_notes` row is created (`author_id=caller`, `flagged` default false, `attachments='[]'`, `deleted_at=null`), 201 with the note (incl. `authorName`). Empty `content` → 422 `VALIDATION_ERROR`.
13. **Given** `GET /api/students/{id}/notes`, **Then** non-deleted notes for that student return chronological ASC with `{noteId, authorName, content, flagged, createdAt}`, role-scoped (a teacher only for a student they teach → else 404); a Student caller → 403.
14. **Given** `PATCH /api/students/{id}/notes/{noteId} {flagged:true}` from a staff caller with visibility, **Then** the note's `flagged` toggles, 200. **Given** `DELETE …/{noteId}` from the **author** or an **Owner/Admin**, **Then** `deleted_at=now()` (soft-delete), 204; a teacher deleting another author's note (non-owner) → 403 `FORBIDDEN`; the note vanishes from subsequent list reads. Note attachments/@mention are NOT accepted (D8) — an `attachments` field in the request is ignored/rejected.

### E. RLS / tenancy / role-scope (adversarial — TEST-BE-1)

15. **Given** cross-tenant access, **Then** tenant A can neither READ (`GET /api/students`, `/students/{id}`, `/notes`) nor WRITE (create/flag/delete note) tenant B's students/notes — every store method takes `TenantContext` (GO-1), every mutating tx sets the tenant GUC (PERF-1). An adversarial test asserts A's roster omits B's students and each B-targeted note action 404s/403s with the **B row byte-unchanged**.
16. **Given** the NEW teacher-scope axis (R-SEC), **Then** teacher T1 (classes C1) and teacher T2 (classes C2, disjoint) in the SAME tenant: `GET /api/students` as T1 omits every T2-only student; `GET /api/students/{s2}` for a T2-only student as T1 → 404 `STUDENT_NOT_FOUND`; T1 cannot create/read a note on a T2-only student (404). Admin/Owner see both. This is the story's headline authz test.

### F. Migrations

17. **Given** the migrations, **Then**: (a) `{ts}_create_student_notes.{up,down}.sql` — the D7 table + the 4-policy `center_id` RLS grid + `idx_student_notes_center_student (center_id, student_id, created_at)` + FKs (`student_id`/`author_id`→users, ON DELETE per convention); reversible down. (b) An index for the center-wide roster only **if EXPLAIN needs it** — check `center_members(center_id, role)` and reuse the pre-built `idx_enrollments_center_student` (3.4.5, "for Story 7.2") before adding. No data backfill. Latest existing migration is `20260903120000_create_attendance` → new timestamps must exceed it.

### G. Security & tests (WF-8 HARD GATE — red-first before in-progress)

18. **Given** WF-8 (risk 7), **Then** `//go:build atdd_red_phase` reds exist on the branch BEFORE `in-progress`, covering at minimum (★ = the risk-driver reds that separate "reds prove the risk" from "reds prove the happy path"):

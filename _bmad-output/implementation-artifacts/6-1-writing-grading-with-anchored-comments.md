## Story

As a **Teacher**,
I want **to grade a Writing submission by highlighting spans of the student's essay and pinning inline comments to them, entering the four IELTS criterion band scores, and releasing the grade with one action**,
so that **I can give precise, contextualized feedback and the student is notified their grade is ready — and this story lays the `grades` keystone that 5-5b, 6.2, 6.3, and 6.4 all build on.**

**Scope:** The **teacher** Writing grading surface (screen **s23**, desktop-only) + the full backend grading keystone. Backend: new append-only `grades` table + `current_grades` view, the `submission_immutable_after_release` trigger, `POST /api/submissions/{id}/grade` (create + release, atomic, transactional-outbox for the notification), revise-&-re-release (version=N+1), teacher grading-read + grading-queue reads, and the `grade` block added to the frozen `/result` contract (flips `released` for 5-5b). Frontend: `src/features/grading/` — wire behavior into the static `WritingGradingSurface`/`CommentCard` shells; highlight-and-pin over plain-text offsets; 4 criterion inputs with server-authoritative overall band; durable client draft; prev/next queue.

**Explicitly NOT in this story:** AI-assisted grading (6.2); Speaking (6.3); auto-grading (6.4); the **student-facing** graded display incl. mobile s79 inline comments (**Story 5-5b** — this story only makes the `/result` grade *data* available). See **Out of Scope**.

## Decisions (folded from party-mode pre-dev review, 2026-08-18)

These four were the panel's block-list — decided here so dev does not reopen them:

- **D1 — Release-fact ≠ grade-fact (Winston, Murat B4).** `grades.released_at` is **NULLABLE**. Writing (6.1) sets it `= now()` at INSERT (grade+release atomic — behavior unchanged). The keystone **reader contract is `released ⇔ latest grade version has released_at IS NOT NULL`**, NEVER "a grade row exists" and NEVER `submission.status='graded'`. This is what stops 6.4 (auto-grade stored-then-released) from needing a migration: because `grades` is append-only (no UPDATE), 6.4's later release is an **INSERT into a `grade_releases(grade_id, center_id, released_at, released_by)` append-only event table** — introduced in *6.4*, not built here, but the reader contract is written now so it is forward-compatible. 6.1 does not build `grade_releases`; it just never encodes "grade exists ⇒ released."
- **D2 — Transactional outbox, no in-tx side effects (Winston, Murat B1).** The grade tx contains **only DB writes**: grade insert + submission `submitted→graded` + audit rows + a **durable notification-outbox row** (idempotency key = `grade_id`). The `event.GradeReleased` publish and the Resend email send happen **strictly after COMMIT**, driven off the outbox with at-least-once + dedup on `grade_id`. Nothing external (event fire, SMTP, in-memory channel) executes inside the tx. Reuse the 4.3a jobs/worker infra for the outbox row + post-commit dispatch (do not invent a second async mechanism).
- **D3 — Anchor offsets are UTF-16 code units (Winston §8, Murat B2).** `anchorStart`/`anchorEnd` are **UTF-16 code-unit offsets** into `submission.content.text` (matches the browser that produces and consumes them). Go converts the essay to UTF-16 for range validation/slicing. The offset contract is documented in the `comments` JSONB schema. A **shared multibyte fixture** (essay with emoji + accented char) is asserted on **both** sides via round-trip substring equality. Offsets are **normalized** (trailing whitespace/newlines trimmed) before store.
- **D4 — Durable client draft; explicit draft-vs-published boundary (Sally #8/#9, John).** The in-progress grade (band scores + comment list + open composer) is persisted client-side to **IndexedDB/localStorage per submission**, surviving refresh AND queue navigation. A grade is **draft (private, never student-visible)** until the teacher explicitly clicks Submit/Release — "Next student" navigates and auto-persists the draft but **never publishes**. Prev/Next is a **lossless round-trip** within a session.

## Acceptance Criteria

### A. Backend keystone — grades data model & immutability

1. **`grades` table (append-only) + `current_grades` view.** Migration creates `grades`: `id uuid PK`, `submission_id uuid NOT NULL` (FK `submissions` **ON DELETE RESTRICT** — never CASCADE; the append-only ledger must outlive a submission delete, Murat B5), `center_id uuid NOT NULL` (RLS), `graded_by uuid NOT NULL` (FK `users`), `version int NOT NULL DEFAULT 1`, `criterion_scores jsonb NOT NULL`, `overall_band numeric(2,1) NOT NULL`, `comments jsonb NOT NULL DEFAULT '[]'::jsonb`, `feedback text`, `released_at timestamptz` (**NULLABLE — D1**), `created_at timestamptz NOT NULL DEFAULT now()`. **`UNIQUE (submission_id, version)`** (this is what makes version-by-new-row race-safe — Winston/Murat B3); read index `(center_id, submission_id, version DESC)`. **NO `deleted_at`** — this is an append-only ledger, the soft-delete convention does not apply (Murat B5). Ship SQL view **`current_grades`** = `DISTINCT ON (submission_id) … ORDER BY submission_id, version DESC` so 5-5b/6.2/6.3 cannot each hand-roll "which row is current." `version` is added deliberately (epic omitted it; revise-flow needs it — Dev Notes).
2. **grades RLS = append-only, both policies explicit (Murat B5).** `ENABLE`+`FORCE ROW LEVEL SECURITY`; `grades_select` (`USING center_id = NULLIF(current_setting('app.current_tenant_id',true),'')::uuid`) **and** `grades_insert` (**explicit `WITH CHECK`, same predicate** — USING and WITH CHECK are separate; forgetting WITH CHECK lets a tenant write rows attributed to another) — **no UPDATE/DELETE policy** — plus `REVOKE UPDATE, DELETE, TRUNCATE ON grades FROM classlite_app`. Adversarial tests: cross-tenant **read** isolation; cross-tenant **INSERT** rejected (WITH CHECK); **null-tenant GUC → zero rows / rejected insert** (fail-closed, not fail-open); UPDATE/DELETE rejected.
3. **`submission_immutable_after_release` trigger (R16 / NFR-6; first trigger in repo).** `BEFORE UPDATE` on `submissions`, `RAISE EXCEPTION` (a **named SQLSTATE**, e.g. `P0001` with message `submission_immutable_after_release`, mapped by the store to a typed error → **409**, never a bare 500 — Murat B4) when `OLD.status = 'graded'`. The `submitted → graded` transition itself (`OLD.status='submitted'`) MUST pass. Also block DELETE of a graded submission (FK RESTRICT from grades covers it — AC1). Tests (both directions): (a) the legitimate `submitted→graded` UPDATE succeeds; (b) UPDATE of an already-graded row RAISEs the named error AND the row is byte-for-byte unchanged; (c) the store maps the SQLSTATE to the typed 409. Convention note required (Winston): document the trigger precedent (`<table>_<invariant>` naming, migration placement) so 6.4's second trigger doesn't invent a new style.

### B. Grade write & release

4. **`POST /api/submissions/{submissionId}/grade` — create + release, atomic, outbox (D2).** Teacher-only. Body: `{ "criterionScores": { "taskResponse", "coherenceCohesion", "lexicalResource", "grammaticalRange" }, "comments": [{ "type", "criterion", "anchorStart", "anchorEnd", "text" }], "feedback": string|null }`. **`overallBand` is NOT accepted from the client — the server computes it and IGNORES any client-sent value (AC7).** In ONE transaction (**DB writes only**): insert `grades` (`version=1`, `released_at=now()`), UPDATE submission `submitted→graded`, audit `grade.created`+`grade.released` (`AuditService.LogWithinTx`), and a durable **notification-outbox row** (key `grade_id`). **After COMMIT:** publish `event.GradeReleased` and dispatch the Resend email off the outbox (at-least-once, dedup on `grade_id`). Returns `201 { data: Grade, meta }`. Concurrency: a second grade on an already-`graded` submission → **409 `SUBMISSION_ALREADY_GRADED`**; the check is inside the row lock (`SELECT … FOR UPDATE`), not a TOCTOU pre-check (Murat B3); the `UNIQUE(submission_id,version)` index is the backstop; the losing writer commits **zero** side effects (no event, no email).
5. **Validation (422) + anchor normalization (D3).** `criterionScores` must contain **all four** keys, each a number **1.0–9.0 on a 0.5 grid**. `comment.type` ∈ {error, praise, suggestion}; `criterion` ∈ the four keys. Anchors are **UTF-16 offsets** into `content.text` (D3): a span comment requires `0 ≤ anchorStart < anchorEnd ≤ utf16Len(text)` **after trimming trailing whitespace/newlines**; a whole-essay comment has both `null`. **Out-of-range anchors are demoted to whole-essay (null/null), never dropped** (mirrors 6.2 orphan rule). `feedback` and every `comment.text` are teacher-authored free text — a second XSS surface (Murat): they are escaped on render (AC13), never trusted as HTML.
6. **`POST /api/submissions/{submissionId}/grade/revise` — revise & re-release (D1/B3).** Body = AC4 body + `"reason": string` (required). Inserts a NEW `grades` row `version = MAX(version)+1`, `released_at=now()`; the prior row is untouched; **the submission row is NOT UPDATEd** (it stays `graded`; the trigger would RAISE otherwise — D1 keeps "current version" in the `current_grades` view, never on the submission). Concurrency: two concurrent revises both computing `version=N+1` → the `UNIQUE` index rejects the loser; the handler maps `23505` to a **409 retry**, and the loser emits zero side effects (Murat B3). Audit `grade.revised`+`grade.re_released` with performer+timestamp+`reason`; re-publish + re-notify via the same outbox (post-commit, D2).
7. **Overall band — server-authoritative, integer arithmetic (AC/Murat B6).** `internal/service/grading/scorer.go` computes `overallBand = round_ielts(mean(4 criteria))`. Four half-band inputs average to **eighth granularity**; the rule: `.125→.0`, `.25→.5`, `.375→.5`, `.625→.5`, `.75→next whole`, `.875→next whole` (i.e. `.25→.5` and `.75→next whole` special-cased, everything else nearest-half). **Compute in integer quarter-band space (×4), NOT `float64`** — `6.125` in float rounds the wrong way and flips 6.0↔6.5. Pure, table-driven test over **all eight** boundary fractions. The persisted value is always the server's; the client preview mirrors it (AC14) but never sends it.

### C. Reads — teacher grading view, queue, and the /result grade block

8. **`GET /api/submissions/{submissionId}/grading` — teacher grading read.** Teacher-only (AC11). Returns `{ submission (FULL content, NOT answer-stripped), assignment, student: { id, fullName }, exercise, grade: Grade|null (latest version via current_grades) }`. Distinct from the student `GetAttemptBundle` — do not reuse it (wrong principal, strips content).
9. **Release notification — outbox → Resend email + event (D2).** On release (AC4) and re-release (AC6) the outbox row drives, post-commit: (a) `event.GradeReleased` on the `event.Bus` (payload = submission/assignment ids, never logged — PII); (b) a Resend email via `RenderGradeReleasedEmail(studentName, assignmentTitle, resultURL)` where `resultURL` deep-links `/assignments/{assignmentId}/submission` (the 5-5a page — a **real, reachable** page today). Delivery is idempotent on `grade_id` and never fails the grade. **The email send is behind a config flag `GRADE_RELEASE_EMAIL_ENABLED` (D-notify)** so Ducdo can hold student-facing delivery until 5-5b renders the grade block (John: don't notify a student to open a page that doesn't yet show their grade). Default the flag per Ducdo at dev time; the grade still *persists and releases* regardless.
10. **`/result` grade block (unblocks 5-5b; reader contract D1).** `GET /api/assignments/{assignmentId}/result` gains `grade: StudentGradeView|null`; **`released` flips true iff the latest grade version has `released_at IS NOT NULL`** (D1 — NOT off `submission.status`, or 6.4 breaks it). `StudentGradeView = { overallBand, criterionScores, comments:[{type,criterion,anchorStart,anchorEnd,text}], feedback, gradedAt }` — **excludes `graded_by` teacher identity** (privacy default, hard to walk back once clients render it — Winston §7). Ungraded → `grade:null` + `released:false` (unchanged 5-5a). This story adds only backend data; 5-5b renders it and owns the `/result` FE route + s79.
11. **Authz — teacher-of-assignment (SEC).** All grading endpoints require the caller be a `teacher`/`admin`/`owner` **AND** assigned to the class the submission's assignment belongs to. Non-member class → `403 FORBIDDEN`; non-teacher role → `403 INSUFFICIENT_ROLE`; a submission not in `submitted`/`graded` (e.g. `in_progress`, or no submission for that queue slot) → `404`/`409` resolved within RLS first (no cross-tenant existence oracle). All store methods carry `TenantContext` (GO-1).

### D. Frontend — s23 teacher Writing grading surface (desktop-only)

12. **Route + role gate.** `/classes/:id/grading/:aid/:sid` added to `routes.tsx` as a **full-bleed sibling** (attempt-route precedent), lazy deep-named-import (own chunk), `RouteRoleGate allowedRoles={['owner','admin','teacher']}`; student → role-copy, surface **absent from DOM** (TEST-FE-6). Component `WritingGradingPage`; reads `useGradingSubmission(sid)` (`gradingKeys` TS-3; Loading-skeleton/Empty/Error trilogy). **Empty submission** (queue slot with no submission / `in_progress`) → a "nothing to grade yet" state, NOT a blank pinnable essay pane (John).
13. **Essay render + highlight-and-pin (plain text; D3).** Essay is plain text (`content.text`, `{schemaVersion:1,text}`), rendered read-only `white-space: pre-wrap`. **On selection-end, immediately snapshot UTF-16 offsets to state and paint our OWN persistent highlight — never depend on live `window.getSelection()` in the composer** (Sally #1). Highlights render across wrapped lines via **`Range.getClientRects()` multi-rect** painting (no full-width gutter bleed). Offsets **normalized** (trim trailing whitespace/newlines). **Overlapping comments are allowed** — layered/blended bands; clicking an overlap focuses the innermost/shortest span (Sally #3/#4). **Reciprocal pin↔card focus:** clicking a pin scroll-focuses its `CommentCard`; hovering a card pulses its pin (Sally #5 — the core interaction). Highlight HTML is built by **HTML-escaping** the text, inserting `<mark class="cl-anchor-{error|praise|suggest}">` at sorted offsets, then `asSafeHtml()` → `WritingGradingSurface.essayHtml`. **Never** inject unescaped student text (XSS); comment bodies (AC5) are likewise escaped on render.
14. **Comment composer + band inputs + live overall (Sally #2/#3).** Selecting a span opens a **composer popover at the selection** (keeps eyes on the text): pick type (default **Error**; classify after typing is allowed), pick criterion (**optional/inherit — not a forced per-comment dropdown**), write body; `Esc` cancels, `Enter`/`Cmd+Enter` commits. Four criterion inputs (i18n `criterion.*` exist) accept 1.0–9.0 in 0.5 steps (build from `src/components/ui/`). The overall band is **read-only, recomputed LIVE on every criterion change**, and **shows its math** (e.g. "avg 6.38 → 6.5") on hover/subhead so "automatic" reads as trustworthy, not a locked box. Each criterion annotates its pinned-comment count (UX §6.1 evidence). (A future "override overall with reason" is a known deferral — build the field so it can become editable later without a rewrite.)
15. **Durable draft + draft/published boundary (D4).** Working grade (scores + comments + open-composer text) persists to **IndexedDB/localStorage per submission**, surviving refresh AND queue nav; follow the attempts-spine cache-as-store draft pattern under `gradingKeys`. A grade is **draft/private** until Submit/Release; there is no server grade row until release. Navigating away or refreshing must never lose the draft and never publish it.
16. **Submit / revise / lossless queue nav.** "Submit grade & notify student" → `useGradeSubmission` → `POST …/grade`; confirm step states the student will be emailed. Already-`graded` → load the existing grade read-only + a "Revise & re-release" affordance (`reason` required) → `useReviseGrade` → `POST …/grade/revise`. **Prev/Next student** navigates the route `:sid` without returning to the list, with "N of M graded" progress and arrow-key shortcuts; **navigating with an open composer auto-saves the draft comment or prompts — never silent-discards** (Sally #9); Prev revisiting rehydrates scores+comments exactly (lossless — D4). Mutations invalidate `gradingKeys.detail(sid)` + queue on settle (release is not optimistic — awaits server).
17. **Grading queue + desktop-only seam (Sally #5-mobile).** `useGradingQueue(classId, assignmentId)` reads `GET /api/classes/{classId}/grading-queue?assignmentId=…` → rows `{ submissionId, studentName, assignmentTitle, className, isOverdue }`. Below the desktop breakpoint show an honest **"Open on desktop to grade"** seam that **also offers "copy grading link / email it to me"** (the first touch is often a phone email tap — a dead-end wall is a broken promise); read-only essay+queue viewing on mobile is acceptable but authoring is desktop-only. **Name the exact breakpoint and the tablet decision** (iPad landscape ≈1024px — is it desktop?) rather than letting "desktop" silently exclude it.
18. **Teacher preview of the student artifact (John).** The teacher surface must render the anchored comments **against the essay** such that the teacher can verify the anchors resolve before releasing — the in-text pins + rail cards (AC13) satisfy this; add an explicit "this is what the student will see" framing so a grader never releases blind into the 5-5b view they don't build here.
19. **i18n + a11y.** Extend `writingGrading.*`, add `grading.queue.*`/`grading.release.*`/`grading.revise.*`/`grading.comment.*`/`grading.mobileSeam.*` in **both** `en.json` and `vi.json` (`i18n-parity`); reuse `criterion.*`/`commentCard.*`. `axe` clean; keyboard flow span-select→composer→pin (`Esc`/`Enter`); `<title>`+focus-on-heading; role-negative (student absent).

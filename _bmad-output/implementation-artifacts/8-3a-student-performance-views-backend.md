## Story

As a teacher, admin, or owner, I want `GET /api/analytics/students/{id}` returning one student's band progression (per skill, over time), per-skill breakdown, submission/pin stats, and repetitive-mistake patterns across all four skills — scoped so I only ever see students in classes I'm allowed to analyze,
and as a student I want `GET /api/analytics/me` returning that same shape for myself with all class-average/peer data stripped,
so that individual progress and recurring patterns are visible and actionable, and no student can ever see another student's data or a class average (FR-49, FR-50).

Backend keystone only. This story mints the two READ endpoints + the PROVISIONAL `StudentPerformance` contract (8-3b co-finalizes), extends the done 8-2a analytics spine with a per-student SQL family (incl. a teacher-only cohort `classAvgBand` comparison stripped on `/me`, D11), builds **FU-8-2-A** (the immutable-grade `answer_errors` snapshot) so Reading/Listening auto-graded mistakes become mineable, and — per the party-mode F3 ruling — unions that source into the 8-2a **class** endpoint too (D12) so both Mistakes tabs are symmetric. NO frontend, NO recommendations engine (deferred to 8-3c, D2), NO mutations — analytics stays read-only here.

## Acceptance Criteria (BDD)

### A. `GET /api/analytics/students/{id}` — teacher/owner/admin (AC ↔ FR-49, D4)

1. **Given** an Owner or Admin calling `GET /api/analytics/students/{id}` for a student enrolled in their center, **Then** the response is `200` with the `{data: StudentPerformance, meta}` envelope (GFW-5); `framing: "teacher"`.
2. **Given** a Teacher calling `GET /api/analytics/students/{id}`, **When** the student is enrolled in one of the teacher's OWN classes (`analyticsTeacherScope`), **Then** `200`; **when** the student is NOT in any of the teacher's classes (or the id does not exist in the center), **Then** `404 STUDENT_NOT_FOUND` (non-disclosure — the teacher cannot distinguish "other teacher's student" from "no such student").

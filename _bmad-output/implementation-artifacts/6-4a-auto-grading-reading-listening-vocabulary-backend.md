## Story

As a Teacher,
I want objective (Reading/Listening/Grammar-section, incl. Vocabulary-skill) submissions auto-marked against the exercise answer key the instant the student submits, with a per-answer breakdown I can override before I release,
so that objective assessments are graded instantly while I retain final control and the student only ever sees a grade I have released.

Backend slice only. The **s25 teacher review/override/release UI is 6-4b**; the **student per-question-correctness result view is FU-5-5b-QUIZ**. Per D16 the override/release **wire contract is provisional** — co-finalized when 6-4b is designed — but the backend behavior + tests are fully built here.

## Decisions (D1–D16 — all SPEC; D1/D2 + the four v0.2 product calls are Ducdo rulings 2026-08-26)

- **D1 — Split (Ducdo).** 6.4 → **6-4a (Backend)** + **6-4b (Frontend s25 UI)**. Student per-question view stays **FU-5-5b-QUIZ** (`deferred-work.md:792`).
- **D2 — Grades-at-release-only (Ducdo).** Provisional result + per-answer overrides live in a **new mutable, RLS-scoped `auto_grade_results` table**; the submission stays `status='submitted'` until release. **Release writes the `grades` row** (`graded_by = TEACHER`, `released_at = now()`) + flips submission→graded, reusing 6.1's atomic grade+release path. Rejected the epic-literal design (grades v1 `graded_by:"system"` at submit + flip-to-graded + POST/release UPDATEs released_at) — it is impossible against 3 shipped primitives: `grades.graded_by` is `NOT NULL FK→users(id)` (`migrations/20260818120000_create_grades.up.sql:27`); the immutability trigger fires on `OLD.status='graded'` (`migrations/20260818130000_add_submission_release_trigger.up.sql:25`); `grades` is append-only. D2 → **no system user, no `grade_releases` table, no `grades` migration, no existing-trigger rework, override is a cheap UPDATE.**
- **D3 — Objective = "has gradable question groups", not skill label.** Auto-grade runs on any exercise whose sections carry `QuestionGroups` (reading/listening/grammar section types). `promptOnlySectionTypes` = `{writing, speaking}` (`internal/store/exercise_content_validate.go:72-75`) → never auto-graded. The `vocabulary` **section type is NOT enabled** (`validSectionTypes`, `exercise_content_validate.go:63-69`) and 6-4a does not enable it. "Vocabulary" is covered as an exercise **skill** using objective section types. (Retitled from the epic's "Reading/Listening/Vocabulary" per party-mode — honest about what ships.)
- **D4 — Synchronous auto-grade inside the submit tx** (`internal/service/submission_service.go:541-605`), right after the `submitted` flip — pure comparison, no Gemini (PERF-3 N/A). Fault boundary in **D13**.
- **D5 — Answer blob shape + normalization + variant match (recon-verified).** The student's answers persist as the FE-authoritative `AttemptContent`: `{ schemaVersion:1, answers: Record<Handle,string>, flagged: Handle[] }` (`classlite-web/src/features/quiz-attempt/lib/attemptContent.ts:26,33-37`). **`Handle` = colon-joined `"{sectionIndex}:{groupIndex}:{questionIndex}"`** (`attemptContent.ts:51-57`) — 6-4a's `questionRef` MUST use this exact colon form, byte-for-byte (NOT `s{i}.g{j}.q{k}`). Each answer value is a **single string**: MCQ = the chosen **option text** (compares directly to `CorrectAnswer`), TFNG = `"true"|"notGiven"|"false"`, fill_in_blank/short_answer = free text, **matching = per-row heading string** (each matching row is its own handle). Unanswered = handle absent OR blank-after-trim. Submit carries **no body** — the graded blob is the last autosave PUT. Comparison normalizes both sides: `TrimSpace` → collapse internal whitespace runs to one space → strip hyphen variants (`-` ‐‑‒–—) → NFC; **case-folded unless `Settings.CaseSensitive`** (`internal/store/exercise_content.go:144-148`; hyphen/ws normalization is fixed always-on, `exercise_content.go:142-143`, FU-4-2-A). Match iff the normalized answer equals the normalized form of **any** of `{Question.CorrectAnswer} ∪ Question.AcceptedVariants` (`exercise_content.go:130-136`). The student's own `flagged[]` (self-flag "review later") is informational only — surface it to the teacher, it does NOT affect marking. **Backend `AttemptContent` accessor is greenfield** — no BE type/zod exists (`store.SubmissionContent` is opaque, `submission_content.go:50-57`); model it on `attemptContent.ts`, NOT on the non-canonical test blobs in `internal/test/attempt_read_test.go:212`.
- **D6 — Grading `needs_review` (renamed from "flagged" to avoid collision with the student `flagged[]`).** Per free-text answer (fill_in_blank/short_answer ONLY): exact-after-normalization match ⇒ `correct`; else if it is a **near-miss** ⇒ `needs_review`; else ⇒ `wrong`. Near-miss = Levenshtein distance `d` (over the **normalized** student vs each normalized accepted answer; take the min `d` and the max length `L` of that pair) with `1 ≤ d ≤ min(2, ceil(L/5))`, **OR** the two differ only by diacritics (equal after also stripping combining marks). MCQ/TFNG/matching are exact-choice → `correct` or `wrong`, never `needs_review`. **Scoring direction (Ducdo v0.2): `needs_review` is EXCLUDED from the provisional denominator** — it is neither correct nor wrong until the teacher resolves it. Provisional = `resolvedCorrect / (maxScore − unresolvedNeedsReview)`. The frozen golden table (Dev Notes) is the contract for this classifier.
- **D7 — Band = computed-only (Ducdo v0.2).** `provisionalBand` (and the released band) is always derived from the override-adjusted percentage via the documented percentage→band table (a named `[]struct{MinPct float64; Band string}`). **No manual band-override field in 6-4a** — the teacher controls per-answer marks; a manual band field is deferred. Exercises are arbitrary-length so the fixed IELTS 40q raw-count tables do NOT apply (a per-exercise real band table is a future additive facet).
- **D8 — `grades` reuse WITH discriminator (Winston).** The objective grade reuses `grades` columns unchanged: `criterion_scores` jsonb holds the objective shape `{"kind":"objective","schemaVersion":1,"rawScore":int,"maxScore":int,"percentage":number}` — the explicit `kind` discriminator is **mandatory** so every future reader branches on data, not guesswork. `overall_band` = final band; `comments` = `'[]'::jsonb`. **No `grades` migration.**
- **D9 — Second immutability trigger + race lock (R16, Winston).** `auto_grade_results_immutable_after_release` — `BEFORE UPDATE` on `auto_grade_results`, raises `P0001` (stable named message) when a released grade exists for the submission: `EXISTS(SELECT 1 FROM grades WHERE submission_id = NEW.submission_id AND released_at IS NOT NULL)`. WF-2 convention (`<table>_<invariant>_fn()`, own migration after the table); store maps `(P0001, name)` → typed 409. **Add a partial index `idx_grades_submission_released ON grades(submission_id) WHERE released_at IS NOT NULL`.** The trigger's `EXISTS` runs under the tx tenant GUC — acceptable because every writer path sets `SET LOCAL` (PERF-1). **Close the release/override MVCC race:** both the release path and the override path take `SELECT … FOR UPDATE` on the submission row first, so a release committing concurrently with an override cannot slip a post-release override through a stale snapshot.
- **D10 — Release endpoint.** `POST /api/submissions/{submissionId}/release` — objective-only (409 `SUBMISSION_NOT_OBJECTIVE` for writing/speaking). Reuses `insertGradeRow`-style write + guarded `GradeSubmission` flip (`grading_service.go:796-834`, `queries/submissions.sql:101-105`) + `auditGrade("grade.created")` + `auditGrade("grade.released")` + `enqueueGradeReleaseOutbox` (`grading_service.go:884-906`). **Unresolved-`needs_review`-at-release policy:** release is allowed; any unresolved `needs_review` counts as **wrong** in the definitive released grade (the pre-release provisional excluded them — the definitive grade must be final). 409 `SUBMISSION_ALREADY_RELEASED` on re-release; 409 `AUTO_GRADE_NOT_FOUND` if no working row.
- **D11 — Override endpoint.** `POST /api/submissions/{submissionId}/auto-grade/overrides` body `{ "questionRef": "0:1:2", "mark": "correct" | "wrong" }`. Takes `SELECT … FOR UPDATE` on the submission (D9), recomputes effective raw/max/percentage/band, mutates `auto_grade_results` in place, writes `audit_logs` `autograde.override` (`{questionRef, from, to}`), returns the updated result. Blocked after release by the D9 trigger AND a service-layer release guard.
- **D12 — Teacher read (additive).** Extend `GET /api/submissions/{submissionId}/grading` (`GetSubmissionForGrading`, `grading_service.go:494`) with an additive `autoGrade` block (per-answer breakdown incl. `correctAnswer` + `acceptedVariants` + `studentFlagged`) for objective submissions. `correctAnswer` is teacher-only: the **store returns it always; the handler strips it for non-staff serialization** — never leak to the student bundle (the student path already strips it in `attempt_view.go`; do not touch that).
- **D13 — Submit-tx fault boundary via SAVEPOINT (Winston/Murat/Amelia — resolves the D4-vs-AC3 collision).** In pgx v5 any failed statement poisons the whole tx. Auto-grade runs inside a **SAVEPOINT** within `Submit`'s tx: (a) the pure engine returns `(result, nil)` or `(nil, nil)` for malformed/zero-question content — it NEVER returns an error for bad data; (b) if the engine OR the `auto_grade_results` insert fails for any reason, the code **rolls back to the savepoint** and the outer submit **still commits** as `submitted` (ungraded) — a grading defect must never block a student's submit. The failure is logged (EDGE-4-safe, no PII), never surfaced. A fault-injection red proves the submission row lands even when grading panics.
- **D14 — No snapshot; grading reads LIVE `exercises.content` (recon-verified — resolves BLOCK-3).** There is no exercise-content snapshot and none is needed: an exercise is `EXERCISE_LOCKED` the instant the FIRST submission exists (any status incl. `in_progress`) — content edits + soft-delete are rejected (`internal/service/exercise_service.go:670-685`, `queries/exercises.sql:202-211`). So the positional colon-handles in the frozen student blob align 1:1 with the frozen exercise forever. Grading reads the live exercise via a **privileged store read** of `exercises.content` (`store.UnmarshalExerciseContent`) for `CorrectAnswer`/`AcceptedVariants` — NOT the answer-stripped `attempt_view.go` bundle. Defensive guard: if a handle does not resolve to a current question (should be impossible under the lock), skip that answer + log — never mis-map.
- **D15 — Pure engine seam + tx ownership (Winston/Murat layering).** The grading engine is a **pure, storeless** package function `Grade(content store.ExerciseContent, answers AttemptContent, settings ExerciseSettings) → AutoGradeResult` (normalize, match, needs_review, score, band) — no DB. This is the golden-table unit seam (fast, table-driven). **`SubmissionService` owns the `auto_grade_results` write** (via an injected store it calls with the active querier); no service→service tx propagation.
- **D16 — Override/release wire contract PROVISIONAL (Ducdo v0.2).** 6-4a builds the engine + storage + grading-read as **frozen contract**, and implements + tests the override/release **behavior** fully, but the override/release **request/response JSON shapes are provisional** — co-finalized during 6-4b design so the one UI consumer validates them before they harden. Mark them so in api.yaml; expect refinement.

## Acceptance Criteria

### A. Auto-grade on submit (engine hook)

1. **Given** a student submitting an **objective** assignment (exercise has ≥1 section with `QuestionGroups`), **When** `POST /api/submissions/{id}/submit` succeeds, **Then** the submission is auto-marked synchronously in the same tx (D4) inside a SAVEPOINT (D13) and one `auto_grade_results` row is written (UNIQUE per submission). **And** a writing/speaking submission is unaffected (no row, submit path byte-identical to today).
2. **Given** an objective submission, **When** auto-graded, **Then** the result records per-answer `autoMark ∈ {correct, wrong, needs_review}` keyed by the colon `questionRef` `"{sec}:{grp}:{q}"` (D5), the student's raw answer, the student's own self-`flagged` marker (informational), and the cached **rawScore / maxScore / percentage / provisionalBand** (D6/D7). `maxScore` = count of gradable questions across all objective groups.
3. **Given** exercise content missing/malformed/zero-question OR any grading/insert failure (D13), **When** submitted, **Then** submit STILL COMMITS as `submitted` (ungraded); the SAVEPOINT is rolled back; the failure is logged, never surfaced as a submit error. A fault-injection test proves the submission row lands even when grading panics.

### B. Answer matching / normalization / band (pure engine — no DB, D15)

4. **Given** the matcher, **Then** it normalizes per D5 (trim → collapse ws → strip hyphen variants → NFC; case-folded unless `Settings.CaseSensitive`) and matches against `{CorrectAnswer} ∪ AcceptedVariants`. The engine parses the `AttemptContent` blob by colon-handle (D5) and reads the answer key from the live exercise (D14).
5. **Given** each question type (D5 value shapes), **Then**: `true_false_not_given` → student ∈ {true,false,notGiven} matched to `CorrectAnswer`; `multiple_choice` → the chosen option TEXT matched to `CorrectAnswer`; `matching` → per-row heading string matched to that row's `CorrectAnswer`; `fill_in_blank`/`short_answer` → union-matched with D6 `needs_review`. Choice types never yield `needs_review`.
6. **Given** the D6 classifier, **Then** it matches the frozen golden table (Dev Notes) exactly, incl. the len-boundary rows (L=5→thr 1, L=10→thr 2), a diacritics-only pair, a combined edit+diacritic pair, and an empty/blank input (→ wrong/unanswered, never needs_review). `needs_review` is EXCLUDED from the provisional denominator (D6).
7. **Given** the scorer, **Then** `percentage = resolvedCorrect / (maxScore − unresolvedNeedsReview) * 100` (guard denom=0 → 0%) and `provisionalBand` comes from the documented percentage→band table (D7, computed-only). The function is pure and unit-tested against the frozen table.

### C. Working-table store + RLS + immutability (R16)

8. **Given** the migration, **Then** `auto_grade_results` exists: `id`, `submission_id uuid NOT NULL UNIQUE FK→submissions ON DELETE RESTRICT`, `center_id uuid NOT NULL FK→centers`, `raw_score int NOT NULL`, `max_score int NOT NULL`, `percentage numeric NOT NULL`, `provisional_band numeric(2,1) NOT NULL`, `answers jsonb NOT NULL` (typed struct + `schemaVersion`, GO-7), `created_at`, `updated_at` — with the **4-policy FORCE RLS grid on `center_id`** (mirror `submissions`/`grades`). Plus the D9 partial index on `grades`.
9. **Given** cross-tenant access (TEST-BE-1), **Then** tenant A can neither READ nor WRITE tenant B's `auto_grade_results` row (adversarial read AND write).
10. **Given** the D9 trigger: **(a)** UPDATE of a row whose submission has a **released** grade → `P0001` → typed **409**, and the row is **unchanged** (data-unchanged assert); **(b)** UPDATE **before** release **succeeds** (the positive twin — overrides must work pre-release; proves the trigger discriminates, not rejects-always); **(c)** two concurrent releases → the second gets the guarded no-op flip → **409 `SUBMISSION_ALREADY_RELEASED`**, never 500 (the D9 `FOR UPDATE` lock serializes them).

### D. Teacher review read (breakdown)

11. **Given** staff calling `GET /api/submissions/{id}/grading` for an objective submission, **Then** the response includes an additive `autoGrade` block: `rawScore`, `maxScore`, `percentage`, `provisionalBand`, `released` (bool), and `answers[]` each with `questionRef`, `questionText`, `studentAnswer`, `studentFlagged`, `correctAnswer`, `acceptedVariants`, `autoMark`, `overrideMark` (nullable), `effectiveMark` (D12).
12. **Given** a writing/speaking submission, **Then** the grading read is unchanged (no `autoGrade` block) — additive, zero regression to 6.1/6.3a reads; the schema field is optional so existing contract tests don't break.

### E. Override (recompute + audit)

13. **Given** `POST …/auto-grade/overrides {questionRef, mark}` from staff on an **unreleased** objective submission, **Then** the answer's `overrideMark` is set, effective raw/max/percentage/band are recomputed (maxScore fixed; `rawScore = Σ(exact-correct) + Σ(override==correct)`; unresolved `needs_review` excluded from provisional denom), and the updated `autoGrade` block returned — reflecting the override immediately.
14. **Given** an override, **Then** an `audit_logs` row `autograde.override` (`{questionRef, from, to}`, entityType `submission`) is written in the same tx via `AuditService.LogWithinTx` (`internal/service/audit.go:98-108`).
15. **Given** an override on a **released** submission / a writing-speaking submission / an unknown `questionRef`, **Then** 409 `SUBMISSION_ALREADY_RELEASED` / 409 `SUBMISSION_NOT_OBJECTIVE` / 422 `INVALID_QUESTION_REF` respectively (negative-assert each).

### F. Release (grades write + flip + notify)

16. **Given** `POST …/release` from staff on an unreleased objective submission with a working row, **Then** in one tx: a `grades` row is inserted (`graded_by` = caller's teacher UUID from `revalidateStaffRole`; `criterion_scores` = objective shape WITH `kind` discriminator, D8; `overall_band` = final band; `comments`=`[]`; `released_at`=now()), unresolved `needs_review` counts as wrong in the definitive grade (D10), the submission flips `submitted → graded` (guarded), and `grade.created` + `grade.released` audit rows are written (mirror `grading_service.go:223-237`).
17. **Given** release, **Then** the grade-release outbox job is enqueued in-tx (`enqueueGradeReleaseOutbox`); the post-commit `worker/grade_release.go` sends the notification (email gated by `GRADE_RELEASE_EMAIL_ENABLED`, event `grade.released` always published) — reused unchanged.
18. **Given** a released objective submission, **When** the student reads `GET /api/assignments/{id}/result`, **Then** `released == true` and the grade is present (reader contract `released ⇔ latest grade released_at IS NOT NULL`, `attempt_service.go:130-142`); **BEFORE** release (even with a computed provisional) the student sees pending (`released=false`, `grade=null`). **Negative (leak-guard):** the serialized student result asserts **field-ABSENCE** (not empty) of `correctAnswer`, the per-answer breakdown, and `graded_by` — including that a `needs_review` answer never leaks the correct answer.
19. **Given** re-release / release of a non-objective / un-auto-graded submission, **Then** 409 `SUBMISSION_ALREADY_RELEASED` / `SUBMISSION_NOT_OBJECTIVE` / `AUTO_GRADE_NOT_FOUND`. **And** the existing 6.1 status='graded' immutability trigger continues to freeze the submission row after the release flip (regression assert).

### G. Security & tests (WF-8 HARD GATE, R16 — red-first before in-progress)

20. **Given** WF-8, **Then** `//go:build atdd_red_phase` reds exist on the branch BEFORE `in-progress`, covering at minimum: **the D13 fault-injection red** (submission lands even when grading fails — the highest-impact scenario); the D9 trigger 3-twin (after-reject-unchanged / before-succeeds / concurrent-release-409); cross-tenant read+write on `auto_grade_results`; the **frozen D6 golden table** as a table-driven unit fixture; auto-grade correctness incl. colon-handle parse + per-type values + normalization; override recompute+audit; release grade-write+flip+notify+reader-contract; the AC18 field-absence leak-guard; the objective-only guards. ### Decision-needed (RESOLVED)

- [x] [Review][Patch] **Post-release teacher `autoGrade` block must recompute to DEFINITIVE scoring** [auto_grade_service.go `buildAutoGradeView`/`populateAutoGrade`] — _Decision (Ducdo 2026-08-26): recompute to definitive on release._ `buildAutoGradeView` always derives rawScore/percentage/provisionalBand from `provisionalScore()` (needs_review EXCLUDED from denom), ignoring `released`.

## Story

As a user (owner, admin, teacher, or student) on any screen,
I want a Cmd+K / Ctrl+K command palette that searches my classes, students, exercises, assignments, and Knowledge-Hub files in real time and lets me jump straight to any result,
so that I can find and navigate to any resource I'm allowed to see without hunting through menus (FR-67).

Frontend overlay only. The role×type scope, cross-tenant isolation, accent-insensitivity, min-length floor, and result limits are ALL enforced by the done 8-4a backend — **this story renders whatever `GET /api/search` returns and never re-derives scope** (R-1). It wires the already-shipped `SearchPill.onActivate` + shadcn `command.tsx` `CommandDialog` into a live palette: a global ⌘K/Ctrl+K listener + a capped platform glyph swap, a net-new ~300ms debounce hook + a TanStack-Query `signal` stale-response guard, a `features/search/` query slice, 5 grouped result categories with FE-composed deep-link hrefs and a per-category "See all →" doorway into the existing list views, the Loading/Empty/Error + "type more" state machine, and full keyboard-nav a11y. It co-finalizes (strips the PROVISIONAL marker from) the contract 8-4a minted. **NO** Q&A category (FU-8-4-QA), **NO** k6 SLO rig (FU-8-4-PERF), **NO** net-new mobile search affordance (FU-8-4-MOBILE), **NO** recent-search history (FU-8-4-RECENTS), **NO** mutations.

## Acceptance Criteria (BDD)

### A. Trigger, open/close, glyph (AC ↔ epic block 1 + D1/D6; R-3)

1. **Given** any authenticated user on any screen, **When** they press ⌘K (Mac) or Ctrl+K, **Then** the palette opens with the input auto-focused and the browser default prevented (`e.preventDefault()`); the listener is GLOBAL (fires regardless of focus location); re-press / Escape / backdrop-click closes it and returns focus to the trigger. The keydown `useEffect` uses an empty dep array + functional/ref reads (D1).
2. **Given** the topbar `SearchPill` (s06), **When** clicked, **Then** the same palette opens — `SearchPill.onActivate` is wired at `AppLayout.tsx:137` (today unpassed). Test asserts clicking `[data-testid="search-pill"]` opens it.
3. **Given** the `SearchPill` `<kbd>` hint, **Then** it renders `⌘K` on a Mac platform and `Ctrl K` on non-Mac (D6, `isMacPlatform()`), via i18n keys inside a real `<kbd>` (no hardcoded glyph); a test stubs `navigator.platform`/`userAgentData` both ways and asserts the rendered glyph + resolved i18n key.

### B. Query, debounce, min-length, stale-guard (AC ↔ epic block 2 + D2/D3/D4/D13/D14; R-2) — RED-FIRST

4. **Given** the open palette, **When** the user types, **Then** the query is debounced ~300ms before `GET /api/search?q=` fires — a burst of N characters within the window issues exactly ONE request for the FINAL value (fake-timer test asserts BOTH `toHaveBeenCalledTimes(1)` AND the URL carries the final `q`, `encodeURIComponent`-escaped); a superseded in-flight request is aborted via the Query `signal` (D13) and never clobbers fresher results.
5. **Given** a query of **< 3 runes** (blank / `"ab"` / a single combining-mark rune), **Then** a spied `/api/search` handler is called **0 times** (`enabled:false`, measured by a `vi.fn()` spy — NOT by MSW-throws, which can't distinguish disabled from absent) and the idle prompt shows; **Given** ≥ 3 runes (`"abc"`), the POSITIVE control asserts the spy is called exactly ONCE with `q=abc`.
5a. **Given** the rune-count rule (D14), **Then** a test table pins expected fire/no-fire using code-point length (`[...q.trim()].length`): a VN combining/precomposed accent near the 3-boundary and a surrogate-pair rune each assert the agreed fire/no-fire (matches the backend rune floor — the one FE↔BE divergence point).
6. **Given** results are loading after a query change, **Then** previously-rendered results stay visible (no empty-flash) via `placeholderData: keepPreviousData` — proven by a held-PENDING state-machine test (resolve query A, hold B's response pending, assert A's items STILL render and "no results" is absent, then resolve B → B replaces A), NOT a timing race.

### C. Grouped results, anatomy, deep-links, doorway (AC ↔ epic block 2 + D5/D11/D12; R-4)

7. **Given** a `SearchResults` payload, **Then** the palette renders one `CommandGroup` per NON-EMPTY category (Classes, Students, Exercises, Assignments, Knowledge-Hub files) in that order with i18n headings; an empty category is omitted. Headings resolve in both locales.
8. **Given** each item, **Then** it renders a per-`type` icon (D11), `title`, and `subtitle` (`null`→omitted, never "null"); `CommandItem.value = ${type}:${id}`; cmdk's built-in filter is disabled (`shouldFilter={false}`) so server `similarity DESC` order is preserved.
9. **Given** a result is selected (Enter/click), **Then** the FE navigates to `resultHref(item, role)` and closes the palette: `class`→`/classes/{id}`, `student`→(teacher `/students/{id}` | owner/admin `/people/students/{id}`), `exercise`→`/exercises/{id}/edit`, `assignment`→`/classes/{classId}/assignments`, `file`→`/knowledge-hub/files/{slug}`. A table test covers all 5 types × the student role-branch, asserts `classId` non-null before composing an assignment href and `slug` for a file, and has NEGATIVE rows (the wrong href is never produced).
10. **Given** a category whose `hasMore` is `true`, **Then** an actionable "See all matches for '{q}' →" row (D12) renders under that group; selecting it closes the palette and navigates to that category's existing list view (`classes`→`/classes`, `students`→role-branched, `exercises`→`/exercises`, `assignments`→`/assignments`, `files`→`/knowledge-hub`), prefilling `?q=` where the list supports it; `hasMore:false` renders no doorway.

### D. Scope trust — FE never re-derives (AC ↔ 8-4a D5; R-1) — RED-FIRST

11. **Given** a canned `SearchResults` payload, **Then** the result-list renderer emits it VERBATIM: rendered categories === `Object.keys(payload)` and per-category rendered item count === `payload[cat].items.length`, element-by-element in server order — any `.filter`/`.slice`/role-branch a future dev inserts drops a count or reorders → RED (this replaces the vacuous "render a students category for a student" test). Backed structurally: the renderer's props type has NO `role` field (a scope filter is unexpressible); `role` lives only in `resultHref` (asserted separately, AC9).

### E. States — trilogy + idle (AC ↔ UX-1 + D10)

12. **Given** `q`≥3 and every category empty, **Then** an "No matches for '{q}'. Check spelling or try fewer words" empty state renders (interpolated i18n, role-neutral, calm-recovery — never "No data found").
13. **Given** the request errors, **Then** a human i18n message (never an HTTP code/stack) + a single Retry button that re-fires the CURRENT query (`refetch()`) render; retry-success renders results (three-state coverage, TEST-FE-2).

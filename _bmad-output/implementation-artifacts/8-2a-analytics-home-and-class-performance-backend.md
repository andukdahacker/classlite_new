## Story

As a teacher, admin, or owner,
I want two `GET /api/analytics` endpoints — a role-scoped home that lists the classes I'm allowed to analyze, and a class-performance read that returns cohort band-over-time, a Writing-criteria×week heatmap matrix, mined repetitive-mistake patterns, the at-risk list, and the on-time submission rate — all computed as bounded SQL aggregates from the tables we already have,
so that the analytics screens (Story 8-2b) render in one round-trip per screen without N+1 amplification, and teachers see only their own classes.

Backend slice only. This is the **second consumer** of the Epic-8 R31/PERF-2 keystone (`CountingDBTX` + `dashExplainNoSeqScan`, built in 8-1a): it reuses both harnesses **unchanged** and proves they generalize beyond the dashboard. No frontend, no new UI, no charting. The endpoints compose mostly-new lightweight aggregates over `current_grades` / `submissions` / `attendance` plus `AtRiskDetector.Classify` reused unchanged. `POST`/mutations are out of scope (analytics is read-only). The student `/my-performance` page and `/api/analytics/me` are **Story 8.3** (D4).

## Party-Mode Hardening (v0.2 — 2026-09-18; D13–D16 carry Ducdo product rulings)

- **D13 — Heatmap JSONB is TYPE-GUARDED (Winston BLOCKER).** Never a bare `(criterion_scores->>'x')::numeric` — a present-but-non-numeric value (`""`, `"N/A"`, a holistic artifact) throws `22P02` and errors the WHOLE class heatmap on real data (clean fixtures never hit it). Aggregate only survivors: `avg(...) FILTER (WHERE jsonb_typeof(criterion_scores->'x') = 'number')`, and `sampleCount` counts survivors. A correctness test seeds a partial/malformed `criterion_scores` (only 2 of 4 keys, one non-numeric) and asserts the heatmap still returns (absent/invalid → `null` cell, not a 500).
- **D14 — Mistake `instanceCount` derives student identity from `submissions.student_id`, NOT a submission→enrollment inner join (Winston BLOCKER).** Story 7.3 shipped transfer/withdraw → a student can hold MULTIPLE `enrollment` rows per class; an inner join multiplies `count(*)` (silent on clean fixtures, wrong after any transfer). `instanceCount = count(*)` over unnested `comments`; `affectedStudentCount = count(DISTINCT submissions.student_id)`; touch `enrollment` ONLY as an `EXISTS` semi-join if cohort-membership filtering is needed, never an inner join that fans out rows.
- **D15 — Contract shape pins (Murat/Sally BLOCKERS).** (a) **Heatmap empty cell = `avgBand: null`, NEVER 0** — null = "no Writing grade that criterion+week", 0 = "graded, scored zero"; the FE colours them differently. (b) **DENSE SHARED week axis** — `bandOverTime[].weekStart` is the SAME contiguous Monday-anchored set as `skillHeatmap.weeks[]` (no omissions, no "dev discretion"); empty weeks carry `avgBand: null, submissionCount: 0` / `sampleCount: 0` so the FE aligns the sparkline and heatmap columns and draws the target line across the full range. (c) **Nullable typing is explicit in api.yaml** — `submissionRate.rate`, `bandOverTime.avgBand`, heatmap `cell.avgBand`, `cohortAvgBand/Delta`, `targetBand` all `nullable: true`; a T8 handler test asserts the serialized `"rate": null` (not omitted, not 0) shape.
- **D16 — Mistake-source LABELING + follow-ups registered (John BLOCKER).** `mistakePatterns` block carries `coveredSources: ["writing","speaking"]` + `excludedSources: ["auto_graded"]` so 8-2b renders "Reading/Listening/Vocab patterns not yet available" instead of a blank that reads as "no problems" — silent omission of the objective source misleads the teacher (value defect). Register **FU-8-2-A** (auto-graded answer-error mistake mining — needs a schema change to persist per-answer errors into the immutable released grade) and **FU-8-2-B** (per-skill heatmaps beyond Writing) as real tracked deferrals (Out of Scope). NOTE FR-47's "student redirected to My Performance" is only FULLY realized when Story 8.3 ships `/api/analytics/me` + the `/my-performance` page; until then the student experience is the 403/404 of D4 (name this dependency; 8-2b registers a minimal placeholder so the redirect never 404s).
- **DR-A — Pattern co-gate (RULED Ducdo 2026-09-18).** A mistake pattern surfaces only when `instanceCount >= MIN_PATTERN_INSTANCES` (=3) **AND** `affectedStudentCount >= MIN_PATTERN_STUDENTS` (=2) — so "class-wide" means genuinely multi-student; one chatty student's repeated flags belong to their individual view (8.3), not a class pattern. Both named consts, tunable. `type='praise'` groups obey the same gate (the "calm praise variant" is a TEACHER class-level signal — NOT the 8.3 softened student "Patterns" framing; confirmed in-scope here).
- **DR-B — Trend window (RULED Ducdo 2026-09-18).** `trend` compares the pattern's instance count in `[now-4wk, now)` vs `[now-8wk, now-4wk)`: `worsening` = recent > prior, `improving` = recent < prior, `stable` = equal OR insufficient data. Both windows named consts (`TREND_WINDOW_WEEKS = 4`); the trend clock is the SAME injected `clock.Clock` as `AtRiskDetector` (deterministic tests — a comment exactly on a window boundary is pinned by an injected-clock test, not wall-clock).
- **DR-C — Keep `cohortAvgDelta` = `cohortAvgBand − avg(first non-empty week in range)` (RULED Ducdo 2026-09-18).** Defined baseline (mirrors 7-2b's `BandScoreChart` "vs first month" precedent); drives the s46 4-up stat delta. Not vs-target (the target-band line already shows that gap).
- **DR-D — Writing-only heatmap OK for v1 + self-labeled (RULED Ducdo 2026-09-18).** The payload/label scopes itself as "Writing criteria × week"; a Speaking/Reading-focused center sees an all-empty grid BY DESIGN, and the `hasWritingContent: bool` flag (D15/AC7) lets the FE show "heatmap covers Writing — this class focuses on Speaking" rather than a misleading blank. Per-skill heatmaps → FU-8-2-B.
- **W1 — Query-count is SIZE-INVARIANT, not just ≤N (Winston/Murat).** N against one small fixture is meaningless (a 2-student N+1 stays under N). Assert `count(cohort=small) == count(cohort=large) <= N`; the synthetic-N+1 RED fixture MUST be ≥ N+1 students so N+1 genuinely exceeds N. The counting boundary is the tx the service runs on — the sqlc `*Queries` MUST be bound to the counting-wrapped tx (`q` from `generated.New(countedTx)` / `WithTx`), NOT the raw pool (the 8-1a false-pass). `evidence/analytics-query-count.json` carries the ITEMIZED per-query budget per (endpoint, role) (e.g. `1 SET LOCAL + 1 class-auth + 1 bandOverTime + 1 heatmap + 1 mistakes + 1 atRisk-batch + 1 submissionRate = 7`). **THREE** synthetic-N+1 injections, one per fan-out surface: per-student at-risk loop (AC9), per-week heatmap loop (AC7), per-grade comment re-query (AC8).
- **W2 — Aggregation shape rules (Winston §4/§5/§6).** Each class-perf aggregate is ONE set-based query (`GROUP BY week_start` inside an already range-filtered set — NEVER one query per week). The class-scoped at-risk LATERAL is a SEPARATE query with a literal `class_id = $1` (keeps the index sargable; do NOT bolt a nullable `class_id` narg onto the hot `ListStudents` path) returning exactly ONE row per student (per-student rollups in SQL; classify O(students) in Go). Week bounds are computed in Go from the center `time.Location` and passed as sargable `[rangeStart, rangeEnd]` UTC instants (NOT `date_trunc(... AT TIME ZONE tz)` on the column). The tx runs `SET LOCAL app.current_tenant_id` BEFORE the first `current_grades` touch (else the `security_invoker` view returns empty / R1). EXPLAIN + size-invariance fixtures MUST be seeded at realistic cardinality (≈30 students × 12 weeks × 4 skills) — planner choices on 3-row fixtures are noise.
- **W3 — Budget for a `grades(submission_id, version DESC)` index (Winston §6).** `current_grades`'s `DISTINCT ON(submission_id) … version DESC` likely needs this composite to avoid a Seq Scan/expensive sort under `enable_seqscan=off`; if Task-6 EXPLAIN surfaces it, THAT is the D12 migration — flag first, then `migrate.sh` + re-`codegen.sh` (WF-2/WF-3). Plan for it rather than treating no-migration as the base case.

## Acceptance Criteria (BDD)

### A. Endpoints & chain

1. **Given** the analytics routes, **When** `main()` wires them, **Then** both `GET /api/analytics` and `GET /api/analytics/classes/{id}` are registered on the ungated `dashboardChain` shape (`extractTenant → requireVerified → requireCenter → ErrorMapper`, NO `RequireRole`), constructed via `service.NewAnalyticsService(pool, clock.RealClock{})` + `handler.NewAnalyticsHandler(...)`; `id` is read with `r.PathValue("id")` and 422 `VALIDATION_ERROR` on a non-UUID.

### B. Analytics home (role-branched — AC ↔ FR-47)

2. **Given** a Teacher caller of `GET /api/analytics`, **Then** `data.role == "teacher"` and `data.classes` lists ONLY classes the teacher teaches (`teacher_id = caller`), each `AnalyticsClassSummary`: `{ classId, className, studentCount, avgBand (nullable), atRiskCount, onTimeRate (nullable) }`.
3. **Given** an Admin or Owner caller, **Then** `data.role ∈ {admin, owner}` and `data.classes` lists ALL center classes (NULL `teacher_id` scope) — center-wide, distinct from the teacher's own-only list.
4. **Given** a Student caller of `GET /api/analytics`, **Then** the service returns **403 `INSUFFICIENT_ROLE`** (D4) — students have no analytics home; the FE redirects them to `/my-performance` before calling (Story 8.3).

### C. Class performance payload (AC ↔ FR-48)

5. **Given** an authorized caller of `GET /api/analytics/classes/{id}`, **Then** `data` is a `ClassPerformance`: `{ classId, className, targetBand (nullable — `classes.target_band`), cohortAvgBand (nullable), cohortAvgDelta (nullable — DR-C, vs first non-empty week in range), onTimeSubmissionRate (nullable), atRiskCount, hasWritingContent (bool — DR-D/D15), bandOverTime[], skillHeatmap, mistakePatterns, atRiskStudents[], submissionRate }` — all GO-5 explicit nulls.
6. **Given** `bandOverTime`, **Then** it is an array of `{ weekStart (ISO date, Monday-anchored in center tz), avgBand (nullable), submissionCount }` — the cohort avg of `current_grades.overall_band` (released only) per week (D8). **The week axis is DENSE and CONTIGUOUS (D15b)**: every Monday-anchored week in the range is present (empty weeks → `avgBand: null, submissionCount: 0`), and `bandOverTime[].weekStart` is the SAME set as `skillHeatmap.weeks[]` so the FE aligns sparkline + heatmap and draws the target line across the full range. No omissions.
7. **Given** `skillHeatmap`, **Then** it carries `criteria: ["taskResponse","coherenceCohesion","lexicalResource","grammaticalRange"]`, `weeks: [weekStart...]` (≡ AC6 axis), and `cells: [{ criterion, weekStart, avgBand (nullable), sampleCount }]` — each cell = **type-guarded** avg `avg((criterion_scores->criterion)) FILTER (WHERE jsonb_typeof(criterion_scores->criterion)='number')` over released **Writing** grades (`exercises.skill='writing'`) in that class+week (D2/D13). Empty/invalid cell → `avgBand: null, sampleCount: 0` (NEVER 0-band — D15a); one malformed grade must not 500 the heatmap (D13). NO colour in the payload. `hasWritingContent` (AC5) distinguishes "Writing class, no grades yet" from "no Writing content" (DR-D).
8. **Given** `mistakePatterns`, **Then** it is `{ coveredSources: ["writing","speaking"], excludedSources: ["auto_graded"], patterns: [{ skillSource (writing|speaking), criterion, type (error|praise|suggestion), instanceCount, affectedStudentCount, trend (improving|worsening|stable) }] }` (D16 labeling), mined from released `grades.comments` only (D3/D11); `instanceCount = count(*)` over unnested comments with student identity from `submissions.student_id` (D14, never an enrollment inner join); a pattern surfaces only when `instanceCount >= MIN_PATTERN_INSTANCES` (3) **AND** `affectedStudentCount >= MIN_PATTERN_STUDENTS` (2) (DR-A); `trend` = recent-4wk vs prior-4wk, clock-injected (DR-B); ordered deterministically by a TOTAL order (`instanceCount DESC, skillSource, criterion, type` — asserted positionally, no ties).
9. **Given** `atRiskStudents`, **Then** it is `AtRiskDetector.Classify == "at_risk"` over the class's students (D5), each `{ studentId, name, attendanceRate (nullable), overallBand (nullable), reasons[] slugs }`, classified in Go over a one-row-per-student LATERAL with NO per-student query fan-out (W2); `atRiskCount` is the count within the documented scan scope.
10. **Given** `submissionRate`, **Then** it is `{ onTimeCount, totalDue, rate (nullable) }` — `totalDue` = assignments due to CURRENTLY-ENROLLED (active, non-withdrawn per 7.3) class students; `onTimeCount` = submitted AND `submitted_at <= deadline_at` STRICT; `rate = onTimeCount/totalDue`, **`rate: null` when `totalDue == 0`** (division guard — never `0`, never NaN/500).

### D. Role scoping & non-disclosure (AC ↔ R26 / SEC-1)

11. **Given** a Teacher requesting `GET /api/analytics/classes/{id}` for a class they do NOT teach, **Then** **404 `CLASS_NOT_FOUND`** (non-disclosure — never 403, never leaking existence), with a positive control (the same teacher DOES get 200 with a NON-EMPTY payload for a class they own) in the same test body.
12. **Given** a Student requesting `GET /api/analytics/classes/{id}` for any class, **Then** **404 `CLASS_NOT_FOUND`** (D4). This is DISTINCT from AC4's **403 `INSUFFICIENT_ROLE`** on the home — same actor, two endpoints, two codes: the class endpoint hides existence (404), the home refuses the role (403). Pin BOTH as separate red tests asserting the exact status+code (Murat — a lazy impl returning 403 for both leaks that the class exists). Positive control: Owner/Admin get 200 with a non-empty payload for that same class.
13. **Given** SEC-1, **When** a caller's JWT says teacher but the DB says the class's `teacher_id` is someone else, **Then** the DB-authoritative check wins → 404; no analytics rows are computed or returned (positive control: the true class teacher gets 200 in the same test).

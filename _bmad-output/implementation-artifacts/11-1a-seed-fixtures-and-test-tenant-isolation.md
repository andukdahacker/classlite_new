## Story

As a **developer and as the Epic-11 QA loop**,
I want **a deterministic, idempotent, structurally-confessed-synthetic seeded dataset spanning Epics 1–8 across two multi-role tenants; a dedicated disposable test database owned by a `TestMain` that migrates as the production non-superuser role; every committed-row test helper refactored off the shared dev DB so parallel workers cannot leak across tenants; a per-tenant reset and a positive-proof-guarded destructive wipe; a `screens.yaml` manifest + CI lint that pins the s00–s87 vocabulary as a provenance ratchet; and a documented resource budget**,
so that **every test and every manual session starts from a known, honestly-labelled state instead of eight epics of accumulated residue; a cross-tenant leak is provable on the surface that is actually broken, not just the safe one; the 86 story files that speak in `sNN` IDs are protected by a build failure rather than a vow; and the stack does not OOM mid-run.**

**Verification infrastructure, not a feature.** No user-facing capability, no `api.yaml` change. It builds the apparatus the rest of Wave A stands on: `11-2` mints real sessions from the credentials this seed emits; `11-3a`/`11-3b` fill in the detail docs this manifest points at; `11-5a` drives the money-path smoke against this dataset. **Because it ships no feature, it has no user to catch our mistakes — a leaky clean room is worse than none** (Winston); every AC below exists to keep the clean room actually clean.

**Done when** (epic-11.md:593, scoped honestly per the DoD): a clean checkout can produce an identical multi-role center twice (content-hash-verified), and tenant A cannot observe tenant B — on the committed path, under a multi-connection concurrency race. (The Playwright per-worker runtime wiring is 11-2/11-5a — DoD §R-11-5.)

## Design decisions pinned (engineering calls + the party-mode folds; override at dev pickup only with a written reason)

- **DD1 — Seed = Go `cmd/seed` over the STORE layer; the SERVICE layer is PROHIBITED [fork 1 ruled: keep + build].** Not a migration (ships to prod — R-11-4 — and is immutable), not bash+psql (can't do bcrypt/JSONB/FK ordering/RLS cleanly). `scripts/seed.sh` → thin `go run ./cmd/seed` wrapper. **Forbidden vectors (Winston c):** cmd/seed must NOT invoke service-layer writers that emit domain events (Epic-10 bus), write `audit_logs`, send email, or enqueue jobs — those make the seed non-deterministic and pollute the "clean" tenant on first run. Reuse the **repository/store** writers + replicate pure transforms (bcrypt, derived bands) inline. **Tenant-context window is mandatory:** each tenant's inserts wrap in one tx with `store.SetTenantContext` (`SET LOCAL app.current_tenant_id`) or RLS blocks/mis-tags the write — the migration precedent needed no such window, this does, which is itself why Go-not-migration.
- **DD2 — Dataset: two deterministic tenants, full role set, Epics 1–8, idempotent-by-construction.** Reuse `TenantAID`/`TenantBID`. Each center: owner, admin, ≥1 teacher, ≥2 students; classes (active+ended, referencing the global templates); enrollments; exercises × 4 skills; assignments; submissions × 4 attempt types; released grades (folds 8.5's IELTS distributions — **as confessed-synthetic, DD12**); attendance; files; terms/rooms/holidays as needed so chapters 1–5+8 render non-empty. Speaking submissions use a seeded R2 key + the mock object store (no live R2/Gemini). Deterministic UUIDs + existence-guarded writes (ON CONFLICT DO NOTHING).
- **DD3 — `credentials.json` ≠ Playwright storageState.** The seed writes `tests/e2e/.auth/credentials.json` = `[{role,email,password,centerShortCode,centerId}]` — the raw login inputs 11-2 POSTs to `/api/auth/login`. NOT the `.playwright/auth.json` session blob (11-2's output). Gitignore `tests/e2e/.auth/`.
- **DD4 — FULL raw-pool refactor, NOW [fork 2 ruled].** The 40+ raw-pool helpers that COMMIT into shared `classlite_dev` are **the chartered defect** (R-11-5). Every one is (a) INVENTORIED, (b) CLASSIFIED `rollback | tenant-scoped-commit | raw-commit` (Winston b), (c) every `raw-commit` rewritten to tx-isolation (prefer `SetupDB`'s rollback) or, where a committed row is genuinely required (cross-process concurrency tests), a **tenant-scoped commit under `SetTenantContext`** so even committed rows are RLS-invisible cross-tenant + a deterministic teardown. The `prePurgeHooks` hand-maintained cascade is retired or reduced to the irreducible minimum. **FU-11-1A-RAWPOOL is NO LONGER deferred — it is AC7.**
- **DD5 — Two resets.** (1) **Per-tenant** `reset(centerID)` (AC3): superuser cascade scoped by `center_id` (the `PurgeUserAndOwnedCenters`+`prePurgeHooks` pattern, one center), leaving others **byte-identical**. (2) **Destructive full wipe** (AC5): positive-proof guarded — see DD13.
- **DD6 — `docs/product/screens.yaml`: a registry now; provenance is a RATCHET (DD15).** One entry per sNN (+`s10a`, DD7) from `classlite-ia.md`: `id/title/route/section/chapter/roles/implementation_status/provenance/detailDoc/last-verified/verified-by`. `implementation_status`: ch.1–5+8 `shipped`; ch.6 (`s50-s67`) `unbuilt-epic-10`; ch.7 (`s68-s73`) `unbuilt-epic-9`. `provenance`: `asserted-from-design-intent` now — `verified-against-build <SHA>` is 11-3a/b's output. `detailDoc`: null until 11-3a/b.
- **DD7 — `s10a` is a first-class entry → 89 entries; lint grammar `s\d{2}[a-z]?`.** Verbatim-ID rule (epic-11.md:255) makes `s10a` a live token.
- **DD8 — s-ID lint: repo-level Node `.mjs`, own workflow, repo-wide triggers, shape-not-provenance (Winston d).** Parse `screens.yaml`; scan `s\d{2}[a-z]?` tokens under `docs/` + `_bmad-output/` + web + api refs (reserve the archived-prototypes exclude for 11-3a); FAIL bidirectionally (token→entry AND entry→doc); **read-only, NEVER rewrites the 86 story files** (epic-11.md:276). It checks **shape / uniqueness / referential integrity**, NOT provenance correctness — flagging the known-provisional `asserted-from-design-intent` entries would get it disabled in a week. Its own `.github/workflows/screens-lint.yml` with path triggers covering **everywhere sNN appears** (ci-web's `classlite-web/**` filter would miss api-/docs-only commits — exactly the ones that orphan an ID).
- **DD9 — Staleness: STRUCTURAL guard now, git-log detector DEFERRED → FU-11-1A-STALENESS.** Real staleness ("`last-verified` predates the screen's last code change") needs `verified-against-build` SHAs that don't exist until 11-3b. - **DD11 — WF-8 red phase: AC2 red is BEHAVIORAL, not compile-fail (Murat e).** 11-1a trips ≥6 (R-11-4, R-11-5). Red before `in-progress`, Go, not Playwright. **AC1/AC3/AC6 use the `//go:build atdd_red_phase` compile-fail convention** (`[[reference_atdd_red_convention]]`). **AC2 is different:** a compile-fail red never executes the isolation assertion, so it proves nothing about the test's power to catch a leak. AC2's isolation test must compile + run and go **RED against the current leaky committed raw-pool baseline** (it sees B's residue rows), then GREEN after AC7's refactor. That red proves the assertion has teeth. Register R-11-1..6 in `test-design-architecture.md` (Task 0 — done at create-story; the ≥6 gate needs it).
- **DD12 — Every synthetic artifact STRUCTURALLY confesses it is fake (Mary b/d; echoes 11-0b's mechanism-vs-truth line).** The 8.5 band distributions and all seeded content are fake *by design*; the failure mode is **provenance collapse** — a downstream query six months on treats seeded band-7 samples as ground truth. Mitigation IN THE DATA, not a source comment: a loud marker (e.g. a `seed_synthetic`/`SEED_FAKE_`-prefixed identifier, a reserved sentinel column, or an unmistakable naming scheme) so the data confesses even when it outlives its author. **Student fixtures are unmistakably non-natural-person** — `@example.test` emails, names like `Student Fixture A7`, obviously-sentinel DOBs; NEVER a plausible real Vietnamese minor's identity shape (this is an IELTS product, population includes minors, VN jurisdiction, and 11-8a makes staging reachable — synthetic-but-minor-shaped PII in a deployable env is the compliance exposure, not the fake password).
- **DD13 — R-11-4 destructive-reset guard = POSITIVE-PROOF, not prod-shape detection (Mary a).** "Refuses a prod-shaped URL" is an allowlist pretending to be a denylist; it fails open the first time staging looks local-ish or a tunnel maps prod to `localhost`. Invert: the target must **PROVE it is disposable** before any destructive op — **(1) the database name is literally `classlite_test`** (or an explicit test-DB allowlist), **(2) a sentinel object exists** (e.g. a `__disposable_fixture_db__` table/row production can never contain), **AND (3) an explicit opt-in** (`ALLOW_DESTRUCTIVE_RESET=1` / `APP_ENV∈{dev,test}`). All three are positive assertions about the TARGET. A prod DB cannot grow a sentinel; a staging DB that "looks local" has none and is refused. Abort non-zero otherwise.
- **DD14 — AC1 oracle = content hash + committed golden digest, not self-equality (Murat a).** Row-count equality only proves cardinality idempotence; it passes while (i) a reseed uses fresh random UUIDs (dangling FKs), (ii) `ON CONFLICT DO NOTHING` masks a partial first run, (iii) an updatable column drifts and DO-NOTHING never corrects it. Oracle: after run N, `SELECT` the seeded rows in deterministic order, hash the canonical serialization, assert `hash(run1)==hash(run2)` **AND** `==` a committed golden digest (deterministic UUIDs make this free). **Idempotency means "don't duplicate", NOT "byte-identical" for bcrypt/salted columns** (Winston c) — exclude non-deterministic columns (password hashes, server-default timestamps) from the hashed canonical form, or the oracle flakes.
- **DD15 — Provenance is a RATCHET, not a label (Mary c — the dominant-risk fold).** Shipping 88 entries all `asserted-from-design-intent` codifies the epic's self-referential-oracle risk as schema. The cure is the field itself *plus a downstream gate*: the lint/manifest schema must make a later wave able to FAIL if an entry reaches post-reconciliation still `asserted-from-design-intent` without a dated exemption. 11-1a ships the enum + the structural check that provenance is one of the valid values; **the "must-upgrade-by-reconciliation" gate is wired into 11-3a/b's reconciliation lint (noted in DD17 + the FU)** so the ratchet exists the moment reconciliation starts, not as an afterthought.
- **DD16 — Test-DB lifecycle: `TestMain`-owned, migrate as the NON-superuser role, replay landmine resolved (Winston a/b/e).** (a) A `TestMain` in `internal/test` owns ensure-DB + `migrate up` so **local == CI** (a CI-yaml-only migrate step widens the divergence). (b) Migrate runs as the **same dedicated non-superuser migration role prod will use (11-8a)** — if the test migrate runs as superuser, CI never exercises the privilege model it's meant to protect and a superuser-needing migration detonates only in prod. (c) The NEW role-grant migration (WF-2 — a new pair, never editing `20260601110000`): `CREATE ROLE` guarded by `IF NOT EXISTS (SELECT FROM pg_roles …)` (cluster-global — replaying the chain on two DBs collides otherwise); GRANT via `EXECUTE format('GRANT CONNECT ON DATABASE %I TO classlite_app', current_database())` (per-DB, portable); password from `TEST_DATABASE_URL` env, not a committed literal. (d) **The replay landmine:** the immutable `20260601110000` hardcodes `GRANT CONNECT ON DATABASE classlite_dev`; a fresh `classlite_test` replaying the whole chain either errors (no such DB) or grants on a dead DB — and a later migration cannot retroactively fix an earlier hardcoded statement. **Resolution (ruled option 1):** the TestMain bootstrap `CREATE DATABASE classlite_dev` as a throwaway purely so the old GRANT replays clean, then runs tests against `classlite_test`. Documented, with a retro line that baking an env name into schema taxes every environment forever.
- **DD17 — The 11-3a race over the sNN source, resolved (John b).** `screens.yaml` sources from `classlite-ia.md`, which **11-3a archives**. Resolution: 11-1a's manifest records `classlite-ia.md` as the source + `last-verified` SHA; **11-3a, when it archives, OWNS re-pointing the manifest's source reference to the new `docs/product/` chapter docs it creates** (added to 11-3a's scope — a one-line coordination note belongs in 11-3a). 11-1a does NOT block on 11-3a; whichever lands first, the lint keys on the manifest (not on `classlite-ia.md`'s path), so an archive move does not orphan it. The DD15 provenance ratchet is wired into 11-3a/b's reconciliation lint.

## Acceptance Criteria (BDD)

### AC1: Deterministic, idempotent seed covering all roles across Epics 1–8 — content-hash oracle [epic-11.md:598-601; DD14]
Given a clean (migrated) test database,
When the seed runs **twice**,
Then a **content hash** over the seeded rows (canonical deterministic serialization, excluding non-deterministic columns like bcrypt hashes / server-default timestamps) is **identical across runs AND equal to a committed golden digest** — not merely equal row counts (which pass while the FK graph is re-randomized, a partial first run is masked, or a drifted column is never corrected);
And the dataset covers **all roles (owner/admin/teacher/student)** across **Epics 1–8 entities** (centers, center_members, classes, enrollments, exercises × 4 skills, assignments, submissions × 4 attempt types, released grades with IELTS distributions [folds Story 8.5, as confessed-synthetic per AC8], attendance, files) so chapters 1–5+8 render non-empty;
And the seed needs **no live R2/Gemini**;
And it runs via `scripts/seed.sh` / `dev.sh --seed`, delegating to `cmd/seed`, reusing the **store layer only** (no service-layer events/audit/email/jobs — DD1), each tenant wrapped in a `SetTenantContext` window.

### AC2: Cross-tenant isolation proven on the COMMITTED path, with a behavioral red [epic-11.md:603-606; R-11-5; DD11]
Given seeded tenants A and B,
When a session scoped to A queries the five 8-4a RLS tables — **classes, students (`center_members`+GLOBAL `users`), exercises, assignments, files** —
Then **zero rows of B's data are visible in either direction**, proven on **both** the tx-rollback path (RLS-policy correctness) **and the committed path** (seed A on the real pool committed, open a fresh pool connection scoped to B, assert zero A-rows + a positive B-control) — the committed path is the one the "485 residue" actually broke;
And the **students/`users` path specifically** is proven (a query joining the GLOBAL/no-RLS `users` surfaces no cross-tenant name — gated via `center_members.center_id`);
And each negative is paired with a **same-query positive control** (A sees its own sentinel) so an empty-for-everyone false pass is caught;
And the red-phase AC2 test is **behavioral**: it compiles + runs + goes RED against the current leaky committed raw-pool baseline (sees residue), GREEN after AC7's refactor (DD11).

### AC3: Per-tenant reset leaves other tenants byte-identical [epic-11.md:608-609]
Given seeded tenants A and B with recorded content hashes,
When `reset(A)` runs,
Then A's rows are gone **and B's content hash is unchanged**;
And `reset` operates per-center via the superuser cascade and is subject to the DD13 guard (cannot run against a non-disposable target).

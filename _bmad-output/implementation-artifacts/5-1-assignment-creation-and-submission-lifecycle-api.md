## Story

As a **teacher**,
I want to **create assignments (exercise + class + deadline + instructions) and manage the submission lifecycle**,
so that **students can attempt exercises and their work progresses through defined states (in_progress → submitted → ai_processing → graded), with late work flagged, hard deadlines and per-exercise time limits enforced server-side, and finalized exercises protected from edits that would corrupt in-flight attempts**.

**Scope:** Backend only. Ships the `assignments` and `submissions` tables (RLS-scoped; submissions carry JSONB `content` + `schema_version`), the assignment-management API, the submission-lifecycle API (start/resume, save-progress, submit — with server-side deadline + time-limit enforcement), and the **FR-23 exercise finalize/lock enforcement** (a BLOCKING criterion carried from Story 4.2 deferral FU-4-2-A). The four student attempt UIs (5.2–5.4) and the result view (5.5) consume this API. AI grading (`ai_processing → graded`) is Epic 6; this story only **provisions** those states + the lifecycle columns.

## Acceptance Criteria

### A. Assignment creation & management (FR-27)

1. **Create → open.** Given a teacher/admin/owner POSTs `/api/assignments` `{exerciseId, classId, deadlineAt, hardDeadlineAt?, instructions?, latePenalty?}`, When valid, Then a row is created `status='open'` and the entity returns in a `{data, meta}` envelope with **201**.
2. **Reference validation.** Given `exerciseId` does not resolve to a non-deleted exercise in the caller's center OR `classId` to a class in the caller's center, Then **422** `INVALID_REFERENCE` (FK 23503 → typed error, never 500).
3. **Teacher scope.** Given a `teacher` caller creating for a class whose `teacher_id != caller`, Then **404** `CLASS_NOT_FOUND` (teacher-sees-nothing, never 403 — `assertTeacherScope`). Owner/admin may assign any class in the center.
4. **Deadline coherence.** Given `hardDeadlineAt` present and `hardDeadlineAt < deadlineAt`, Then **422** `INVALID_DEADLINE`. `deadlineAt` required; `hardDeadlineAt` optional/nullable. CHECK written `hard_deadline_at IS NULL OR hard_deadline_at >= deadline_at` (explicit NULL arm — Winston).
5. **Close / reopen.** Given an `open` assignment, When the teacher PATCHes `/api/assignments/{id}` `{status:'closed'}`, Then it flips to `closed` (compare-and-swap on expected status) and no new attempts start (A13). `closed → open` reopen is permitted; **reopen never mutates `deadlineAt`/`hardDeadlineAt` and never un-sets an existing submission's `is_late`** (reopen = "accept more submissions," not "extend" — the extension gesture is a deadline edit, out of 5.1 scope; see D11).
6. **List & detail.** Given a caller, GET `/api/classes/{classId}/assignments` (page+pageSize, XL-2) or GET `/api/assignments/{id}`, Then only center + teacher-scoped rows return, standard envelope + pagination meta.

### B. Submission lifecycle (FR-27, FR-31)

7. **Start / resume — idempotent.** Given an `open` assignment and a **student actively enrolled** in its class, When the student POSTs `/api/submissions` `{assignmentId}`: if **no** submission exists for `(assignment, student)` → create `status='in_progress'`, server-authoritative `started_at`, empty `content` shell (`schema_version=1`), **201**; if an **`in_progress`** submission already exists → return that existing row **200** (resume, never a duplicate — Sally); if a **terminal** (`submitted`+) submission exists → **409** `SUBMISSION_EXISTS`. `started_at` is set once and **never reset on resume** (5.2's timer integrity depends on it).
8. **Enrollment gate — every write.** Given a caller **not** actively enrolled in the assignment's class (no `enrollments` row `status='active'`), When they start/save/submit, Then **403** `NOT_ENROLLED` — re-checked on **start, progress, AND submit** (a student withdrawn mid-attempt cannot submit a stale `in_progress` row — Murat #11). Non-student roles → **403** `INSUFFICIENT_ROLE`.
9. **Save progress — in_progress only.** Given an `in_progress` submission owned by the caller, When the student PUTs `/api/submissions/{id}/progress` with a `content` body, Then content persists and `updated_at` advances. The write is DB-guarded `WHERE id=$1 AND status='in_progress'` (0 rows → **409** `SUBMISSION_NOT_EDITABLE`, not an app-only check — Winston). Body over cap → **413** `PAYLOAD_TOO_LARGE`, where the cap = **serialized-JSONB bytes measured pre-decode** via `MaxBytesReader` (`MaxSubmissionContentBytes`, unit pinned — Murat).
10. **Time-limit enforcement (server-side).** Given the assignment's exercise has a non-zero `settings.timeLimit`, When a student PUTs `/progress` after `now > started_at + timeLimit + GRACE`, Then **409** `TIME_EXPIRED` and the last-saved content stands (a devtools/laggy-tab student cannot keep editing past the limit — Sally). `/submit` remains allowed after expiry (the client auto-submits at 0:00); GET/start responses expose the computed `timeBudgetSeconds` + `startedAt` so the client timer is server-anchored. Untimed exercises (`timeLimit=0/null`) skip this gate. Background auto-finalization of abandoned expired attempts is deferred (D8).
11. **Submit → submitted + late flag (atomic).** Given an `in_progress` submission, When the student POSTs `/api/submissions/{id}/submit`, Then a **single atomic UPDATE** (guarded `WHERE id=$1 AND status='in_progress'`) sets `status='submitted'`, `submitted_at` (server clock), `is_late = submitted_at > assignment.deadline_at` (strictly `>`; exactly-at-deadline is **not** late), and snapshots the penalty in-tx (A12). Status + timestamp + late + snapshot land in the same statement so Epic 6's immutability trigger drops in additively (Winston #5). No backward transition out of `submitted`.
12. **Late-penalty snapshot (point-in-time).** Given a late submission, Then `assignment.late_penalty` is snapshotted to `submission.applied_penalty` **in-tx via subquery** (`SET applied_penalty = (SELECT late_penalty FROM assignments WHERE id=…)`), immutable thereafter — a later assignment-penalty edit does **not** move a submitted row's value (Murat #7). On-time → `applied_penalty=0`, `is_late=false`. (The `raw − penalty = final` arithmetic renders in Epic 6 / Story 5.5 when a score exists; 5.1 stores inputs — D2.)
13. **Hard-deadline / closed lock.** Given the assignment's `hard_deadline_at` is set and `now >= hard_deadline_at` (lock is **inclusive** at the instant — Murat #5), OR the assignment is `closed`, When a student tries to **start / save / submit**, Then **409** `SUBMISSION_LOCKED`, no write. Past **soft** deadline only ⇒ still writable, flagged late. Omitted `hard_deadline_at` (NULL) ⇒ **no hard lock** — late accepted until the teacher closes (D3, ratified Ducdo B2).
14. **Lifecycle provisioning.** The `submission_status` CHECK admits `in_progress|submitted|ai_processing|graded`; the service permits only `in_progress → submitted`. `ai_processing`/`graded` are provisioned states Epic 6 drives — **5.1 has no path into them** (negative-tested: no lifecycle call reaches `graded`).

### C. FR-23 exercise finalize/lock — BLOCKING (FU-4-2-A discharge)

15. **Locked read-only enforcement.** Given an exercise with **≥1 submission** (any status incl. `in_progress` — an in-flight attempt must not have its exercise mutated), When a teacher PATCHes `/api/exercises/{id}` (content or metadata) OR DELETEs it, Then **409** `EXERCISE_LOCKED` (distinct code from stale-precondition `CONFLICT`), no write. The guard fires on **every** exercise-content write path, not only the top-level `Update` (audit block/question editors — Winston #3). Check + write serialize via `pg_advisory_xact_lock(hashtext(exercise_id))` taken by both this guard and the start-submission path, closing the create-during-PATCH TOCTOU (D10).
16. **Lock payload on read.** Given GET `/api/exercises/{id}`, When locked per AC15, Then the entity carries `locked: true` **plus `lockedBy: [{assignmentId, className, attemptState}]`** so the s64/s66 read-only strip can explain *why* and *which* assignments block, not shrug (Sally #4). `lockReason` enum accompanies. The exercise **LIST** returns `locked` cheaply (single `LEFT JOIN LATERAL … LIMIT 1`, not a per-row EXISTS — Winston #2); `lockedBy` detail is GET-single only.
17. **Clone escape hatch (unfinalize struck).** Given a locked exercise, When the teacher POSTs `/api/exercises/{id}/duplicate`, Then the existing 4.1 deep-copy produces an **unlocked** independent copy (**201**), unchanged. **The "or unfinalize" verb is struck from FR-23 on the record (Ducdo B2 ruling, D5):** once any submission exists, safe-unfinalize is vacuous (any submission makes editing unsafe), so clone-and-edit is the sole sanctioned path. No unlock endpoint ships.

### D. Multi-tenancy, integrity & data safety (NFR-6)

18. **RLS isolation — both tables, write-verified.** Given tenants A and B, Then for `assignments` and `submissions`: cross-tenant read = 0 rows; cross-tenant INSERT (spoofed `center_id`) rejected; cross-tenant UPDATE/DELETE = 0 rows **AND a re-read from B proves the row byte-for-byte unchanged** (0-rows alone is not proof — Murat #1); null/unset tenant = 0 rows; reparent-own-row-to-B blocked **both directions** by UPDATE `WITH CHECK`. Verbatim 4-policy `{select,insert,update,delete}` grid, `NULLIF(current_setting('app.current_tenant_id', true), '')::uuid` predicate. `applied_penalty`/`late_penalty` are column-level asserted non-writable cross-tenant.
19. **JSONB typed-struct discipline (GO-7).** `submissions.content jsonb NOT NULL DEFAULT '{}'` + `schema_version integer NOT NULL DEFAULT 1`, read through typed `SubmissionContent{ SchemaVersion int \`json:"-"\`; … }` via `store.UnmarshalSubmissionContent(raw, version)` → `model.MigrateJSONB` with an **empty (v1 passthrough) upgrader map**. Registered as a `submissions` arm in `tools/jsonbmigrate` (`Resolve` + `SubmissionsMigrator()`). **The lazy ladder is read-transform-only for non-`in_progress` rows** (never writes migrated shape back to a `submitted`/`graded` row) so migrate-on-read never collides with Epic 6's immutability trigger (Winston #5, D6).
20. **Integrity & no over-build (NFR-6, WF-2).** `submissions.assignment_id` FK is **RESTRICT** (+ app-layer 409), not CASCADE — a teacher cannot delete an assignment (or class→assignment chain) out from under graded work (Winston #6). `submissions` are **not soft-deletable in v1** (no `deleted_at`; plain `UNIQUE(assignment_id, student_id)` — D7). 5.1 provisions the enum + lifecycle columns but ships **no** `grades` table, `graded_at`/`released_at`, immutability trigger, or AI-grade enqueue (Epic 6). `event.AssignmentCreated` emitted on create; audit rows via `audit.LogWithinTx` in the create/submit tx.

- **D2 — 5.1 stores inputs (`is_late`+`applied_penalty`), Epic 6/5.5 does `raw−penalty=final`.** No score exists at submit. Sally confirmed the s63 pre-grade banner has what it needs.
- **D3 — Hard deadline = separate nullable `hard_deadline_at`; omitted ⇒ NO hard lock, late accepted until close.** (Winston: field beats offset. **Ducdo B2 ruling:** matches FR-31's primary clause "accepted but flagged"; hard lock opt-in per assignment. Late-flagging works by default.)
- **D4 — Assignment `open`/`closed` only** (`archived` deferred — additive `ALTER CHECK`, WF-2); submission full 4-state enum. **(Q3 → confirmed deferral.)**
- **D5 — "Unfinalize" STRUCK from FR-23; clone-only.** **Ducdo B1 ruling.** Safe-unfinalize is vacuous (any submission ⇒ editing unsafe ⇒ locked; no-submission ⇒ already unlocked). Duplicate is the sole edit path; no unlock endpoint. FR-23 AC amended on the record.
- **D6 — Immutability trigger + grades = Epic 6.** 5.1 provisions enum+columns only. Submissions JSONB ladder is **read-transform-only for non-`in_progress` rows** so migrate-on-read never fights the future trigger (Winston).
- **D7 — Submissions NOT soft-deletable in v1** (no `deleted_at`; plain `UNIQUE`). They are the grading audit trail. If retract-resubmit ever lands, switch to a partial unique index `WHERE deleted_at IS NULL` in that story — do NOT bolt `deleted_at` onto the plain UNIQUE (silently breaks it — Winston).
- **D8 — Server-side time-limit enforcement.** `/progress` rejects writes past `started_at + settings.timeLimit + GRACE` (`TIME_EXPIRED`); `/submit` stays open (client auto-submits at 0:00); responses expose `timeBudgetSeconds` so the client timer is server-anchored (Sally). Background auto-finalization of abandoned expired attempts **deferred** (needs a sweep — Epic 5 FE or a worker; filed as FU-5-1-A).
- **D9 — Lock payload = `locked` + `lockReason` + `lockedBy[{assignmentId,className,attemptState}]`** (Sally). Bare boolean can't drive the s64/s66 strip. List = `locked` only (cost); detail = full `lockedBy`.
- **D10 — Cross-aggregate TOCTOU serialization.** Submit/close serialize via `GetAssignmentForUpdate` (`FOR UPDATE`); exercise-edit vs start-submission serialize via a shared `pg_advisory_xact_lock(hashtext(exercise_id))` (Winston/Murat #9,#10). Closes both the submitted-under-closed and mutated-exercise-with-submission invariants.
- **D11 — Reopen ≠ extend.** `closed→open` accepts more submissions but never edits `deadline_at`/`hard_deadline_at` and never un-sets `is_late`. A true extension is a deadline edit (out of 5.1; the teacher edits the assignment). Prevents the "reopen silently un-lated three students" surprise (John).

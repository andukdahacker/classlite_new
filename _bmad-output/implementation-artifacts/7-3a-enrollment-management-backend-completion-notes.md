### Debug Log

- **WF-8 gate first.** The two DB-layer reds (`enrollment_history_rls_atdd_test.go`, `enrollment_status_coupling_atdd_test.go`) were already on-branch from `/bmad-tea AT`. Authored the two remaining red-first files (`enrollment_action_authz_atdd_test.go`, `enrollment_history_atomicity_atdd_test.go`) against the existing `setupEnrollmentHandlerTest` bare-mux harness BEFORE flipping the story to `in-progress`. Verified: normal build excludes them (exit 0); tagged build compile-fails on exactly `generated.ListEnrollmentHistoryPaged(+Params)` (the intended AC11 greenfield seam).
- **Genesis-backfill RLS trap.** `scripts/migrate.sh` connects as a superuser (`MIGRATION_DATABASE_URL`), which bypasses FORCE-RLS, so the backfill's enumerating read + INSERT succeed. Kept the per-center `set_config('app.current_tenant_id', …, is_local => true)` loop anyway so the INSERT's `WITH CHECK` is also satisfied under a non-superuser table owner. Down = documented no-op (irreversible data; the create-table down DROPs the rows).
- **FK divergence (intentional).** `enrollment_history.from/to_class_id → classes` is NO ACTION (not CASCADE): the audit trail must not vanish when a class is deleted. Consequence: a hard `DELETE FROM classes` is *restricted* while history references it; the tenant `centers` CASCADE is the only path that removes history. Added an explicit `DELETE FROM enrollment_history` to the bare-mux cleanup (before the classes delete) so the harness teardown doesn't rely on the ignored-error + centers-cascade backstop.
- **Consolidated the class read.** Replaced `GetClassTeacherRecipient` with `GetEnrollmentClass` — one read returns existence (404), status (D3 enrollable guard), name (email body), and teacher recipient (notify).
- **Coupling-CHECK regression sweep.** The new `enrollments_status_withdrawal_coupled` CHECK broke pre-existing test fixtures that wrote terminal statuses with a NULL `withdrawn_at`. Fixed the two shared seed helpers (`insertEnrollmentRaw`, `seedEnrollment`) to set `withdrawn_at` for non-active statuses, and the five `UPDATE … SET status='withdrawn'` sites in submission/lifecycle tests to also set `withdrawn_at = now()`.
- **Ctor extension** rippled to `cmd/api/main.go` (real `eventBus` + `retryQ`) and the bare-mux helper (`event.NewBus()` + nil queue — email out of the harness's scope; the service nil-guards both seams).

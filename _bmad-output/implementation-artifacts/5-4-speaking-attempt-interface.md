## Story

As a **student**,
I want **a speaking attempt surface that shows my cue card with a calm preparation countdown I can skip when ready, then lets me record my spoken response in my browser — see how long I've spoken, preview it, re-record as many times as I want, and submit — with the recording uploaded to storage and my attempt finalized, and with clear browser-specific guidance if my mic is blocked or interrupted mid-take, and an automatic retry (with a truthfully-scoped local safety copy) if the upload fails**,
so that **I can complete a speaking assignment end-to-end from any device — including my phone — without losing a good take to a flaky upload, a blocked or seized mic, an over-long recording, or a browser that can't record the format the server expects**.

**Scope:** Frontend + an additive backend cap/allowlist/gate change. Desktop + mobile speaking attempt at `/assignments/:assignmentId/speak`. Consumes the **shipped** submission backend (`POST /api/submissions` start/resume · `GET /api/submissions/{id}/attempt` draft+prompt · `PUT /progress` · `POST /submit`) and the **shared `src/features/attempts/` spine (5.2d)**, plus the **presigned-upload spine** (`POST /api/uploads/presign` → direct R2 PUT → `POST /api/uploads/confirm`, 1.2e/4.4a). The speaking `content` shape (an R2 audio KEY, not bytes) is FE-owned over the opaque `SubmissionContent` bag → **no submission api.yaml/codegen change**. Backend touch: the A9 **25 MB** speaking cap + `.m4a→audio/mp4` allowlist + speaking confirm size re-check + the **authoritative over-cap gate on `/progress`** (D12) — hand-written Go, **no api.yaml/codegen**. The student `/assignments` list (5.2c, done) already deep-links here via `attemptRouteForSkill` (stubbed `null` for `speaking` — Task 8 un-stubs). Graded Result view = 5.5; timestamp-anchored audio grading = Epic 6.

## Acceptance Criteria

### A. Bootstrap, recorder leaf & the audio-key content contract (FR-28/30)

1. **Two-call start/resume + resume.** Given a student opens `/assignments/:assignmentId/speak`, When the page mounts, Then it runs the shared bootstrap (`POST /api/submissions {assignmentId}` → 201/200, then `GET /api/submissions/{id}/attempt`). The **cue-card prompt is read from `data.exercise.sections[].content`** (speaking sections have empty `questionGroups` — 5.2a AC12); a **resumed uploaded recording** is read from `data.submission.content.audioKey`. A terminal submission → **409 `SUBMISSION_EXISTS`** on start → route to the confirmation end-state (AC22), not an error page.
2. **Recorder as an ISOLATED leaf (D6 — architecture.md:255).** The recorder's **highest-frequency state is a `requestAnimationFrame` (~60fps) level meter**, not the 1s elapsed timer — BOTH live inside an isolated recorder leaf and MUST NOT re-render the shell, the attempt clock, or the prep countdown. `getContent` reads `{audioKey,…}` from the **draft cache** at save time, never from any recorder-tick state. **Asserted** by a shell render-count spy across N recorder ticks → **0 additional shell renders** (mirror 5.3's `WritingEditorLeaf` commit-count oracle).
3. **Cue-card prompt block, bounded scroll (Sally S2).** The prompt renders as the s33 cue card — a **blockquote with a red left-border** (`--red`), `lang="en"` on the whole block. It is **bounded in its own scroll region** so a long English prompt never pushes the record control below the fold (AC21). Speaking is red-coded (`--cl-tint-red`).
4. **Content contract (5.4 OWNS the speaking shape).** `submission.content = { schemaVersion: 1, audioKey: string, contentType: string, durationSec: number }` — opaque to backend, ≤256 KiB (trivial — audio bytes go to R2 out-of-band), each save a **full replace**. **`contentType`** is stored so 5.5/Epic-6 play the right container; **`durationSec`** is stored and drives the min-duration gate (AC18) + the preview/submit display. A resumed `content` with a missing/old `schemaVersion` normalizes without throwing.
5. **Multi-codec capture; canonical MIME source (D1; Winston STRONG).** Capture uses `MediaRecorder` with feature detection (`MediaRecorder.isTypeSupported`): prefer `audio/webm;codecs=opus`, **fall back to `audio/mp4`** where webm is unsupported (iOS Safari). The key extension (`.webm`/`.m4a`), the **presigned `contentType`**, and the **stored `content.contentType`** are ALL derived from the canonical `pickAudioMimeType()` result normalized to bare `audio/webm`/`audio/mp4` — **NEVER from `blob.type`** (which reports `audio/webm;codecs=opus` or empty on iOS and would 400 the presign's exact-MIME lock). The R2 key is **`{center_id}/speaking/{uuid}.{ext}`** — **the epic AC's literal `.webm` is amended to codec-following** (Task 9). If no supported audio mime exists → a blame-free "this browser can't record audio" orientation (not a crash).

### B. Prep, recording state machine, interruption, preview & re-record (FR-28)

6. **Preparation countdown, skippable (client-side — D4; Sally S1).** Given the cue card is shown, Then a **calm** preparation countdown begins from a client-side default `SPEAKING_PREP_SECONDS` (no backend field — FU-5-4-A). It uses the `DueDateCountdown` calm model (NOT the exam amber/red-pulse ramp), numerals `aria-live="off"`, with a single `aria-live="polite"` "Prep done — you can record now" when it ends. A **"Start recording now"** affordance ends prep early (it protects nothing — D4). Separate timer from the attempt exam clock (AC19).
7. **Recording window + max-duration auto-stop (Ducdo Q2).** State machine: **idle/prep** (record disabled until prep ends OR skipped) → **recording** ("● Recording", red mono label, live elapsed `M:SS`, record button ≥48px, red per s33) → **recorded/preview**. A **soft elapsed-length indicator** is visible while recording, and recording **auto-stops at `SPEAKING_MAX_DURATION_SEC`** — a duration derived from the 25 MB budget — so the size ceiling is **never discovered post-take**. `MediaRecorder.start()` on tap; stop yields one Blob.
8. **Playback preview before submit.** Given a recording is complete, Then preview it in a native `<audio controls>` fed the Blob's object-URL (**revoked on re-record/unmount** — no leak; asserted via a `URL.revokeObjectURL` spy). No grading waveform (Epic 6).
9. **Re-record unlimited; superseded takes are ORPHANED not overwritten (John B2).** Re-record discards/revokes the prior Blob and returns to record-ready — **unlimited**. Because the server mints a fresh `{uuid}.{ext}` per presign (SEC-8), each uploaded superseded take is a **distinct orphaned R2 key** (the `content` bag simply forgets the old key; the object lingers against the A9 per-center storage cap) — **NOT "overwritten, last-take-wins."** Reaping is folded into **FU-4-4-6** (Task 9); no per-take cleanup in this story.
10. **Mic/device failure at record-arm (failure-path AC).** Given `getUserMedia({audio})` rejects, Then a blame-free orientation panel (not a bare 403) branches: **`NotAllowedError`** (denied → browser-specific re-enable steps), **`NotFoundError`** (no mic), **`NotReadableError`/`AbortError`** (device busy). It **always appends a generic fallback line** ("Allow the microphone for this site in your browser's settings") so a UA mis-detect or a redesigned browser menu still lands the student somewhere true (Sally S4). All copy i18n, both locales, VN-length-checked on mobile chrome.
11. **Mid-recording interruption (failure-path AC — NEW; Sally B2; the mobile-PRIMARY case).** Given the mic is granted and recording is **live**, When an incoming call / Siri / another app seizes the device or the user revokes permission mid-take (`MediaRecorder.onerror` or the `MediaStreamTrack` `ended`), Then the recorder **stops cleanly, drops the partial take, returns to record-ready**, and shows a blame-free **"Recording interrupted — tap to record again"** (distinct from the cold-denial panel AC10). No frozen "● Recording", no orphan recording state (A5 checklist item 3).

### C. Upload, autosave & offline resilience (R9, R43, R42)

12. **Upload chain (reuse presign→PUT→confirm).** On submit-intent: **client 25 MB pre-check** → `POST /api/uploads/presign {feature:'speaking', filename, contentType, sizeBytes}` (contentType from AC5, canonical) → **direct R2 `PUT`** (XHR, `Content-Type` locked, 0..1 progress, `AbortSignal` on unmount) → `POST /api/uploads/confirm {key}` (HeadObject verify). Server builds the key (`{center_id}` from JWT). Mirror `uploadKnowledgeFile.ts`/`useUploadImportFile.ts` in a **speaking-local** trio (`feature:'speaking'`) — do NOT import the knowledge-hub primitives.
13. **Automatic retry with an EXACT count oracle (R43; failure-path AC; Murat B1).** Given the R2 PUT (or confirm) fails, Then the upload **retries automatically: 1 initial + up to 3 retries = 4 total attempts**. On total failure, the request-count contract is **exactly 4 presign + 4 R2 PUT + 0 confirm + 0 `/progress`**, and the 4th failure emits the local-fallback state (AC15). Only `TransferError`/502 are retryable. **Unmount during a retry-backoff window fires no further presign/r2put** (abort-mid-retry — Murat STRONG).
14. **Progress save + tri-state (spine).** Given an upload succeeds, `{schemaVersion:1,audioKey,contentType,durationSec}` saves via the shared **`useAttemptAutosave`** `PUT /progress` (a **discrete** save on upload-success; the 30s dirty-flush backstops). The **Saving/Saved/Error** state shows via the shared prominent `SaveStatusIndicator`; a failed save → **Error**, never a false "Saved".
15. **Offline — record-now-upload-later, HONESTLY scoped (Sally B1; Winston B2).** `MediaRecorder` works offline; presign/upload needs network. Given the network drops, When the student records, Then recording works and a reassurance banner appears **as its own visible line** with **fragility-naming copy**: **"Recorded — keep this tab open, it'll upload when you're back online"** (NOT "saved locally" — the Blob is in-memory only, D2). While an **un-uploaded Blob is held**, a **`beforeunload` guard** makes closing/reloading cost a confirm, not a silent loss. On reconnect, a **live `online`-event handler** auto-uploads then flushes the key — **but gated on the read-only derivation**: if the attempt is read-only (e.g. `hardDeadlineAt` passed **while offline**), it does **NOT** presign/PUT (no orphan object) and surfaces **"the deadline passed while you were offline — this recording couldn't be submitted."** Reconcile is **asymmetric local-newer-wins** (D5): **server-wins whenever local has no `audioKey`; local-wins only when local HAS a differing key** (recovering a key whose `/progress` PUT failed after a successful R2 PUT) — a stale/empty local mirror must **never** blank a real server key.
16. **25 MB cap — defense-in-depth + an AUTHORITATIVE mandatory-path gate (A9; Ducdo Q4; Winston STRONG).** **(layer 1)** client pre-check → blocks + `speaking.upload.tooLarge`; **(layer 2)** server presign pre-check → **413 `FILE_TOO_LARGE`** (add the 25 MB speaking cap, Task 1); **(layer 3)** R2 `Content-Length-Range` **N/A** — dropped in 4.4a (unenforceable on presigned PUT; documented, not re-added); **(layer 4, best-effort)** speaking confirm HeadObject re-check → over-cap deletes + 413, with the confirm hardening matrix (head-error → fail-closed/502; delete-fails → orphan-telemetry — Murat STRONG); **(AUTHORITATIVE)** because confirm is skippable for speaking (unlike knowledge, it creates no `files` row), the real gate is on the **mandatory `/progress` path**: the server **HeadObjects the incoming `content.audioKey` and rejects an over-cap key** (Task 1). A client that lies `sizeBytes` at presign and skips confirm is still caught here before the key can persist.

### D. Multi-tab coordination (UX-DR19)

17. **BroadcastChannel submit-in-another-tab.** Given the same student opens two tabs, When tab 1 finalizes, Then a per-submission **`BroadcastChannel`** (`typeof BroadcastChannel !== 'undefined'` guarded; keyed `classlite:attempt:<submissionId>`; echo-guarded) notifies tab 2 → **blocking "Submitted in another session — view result" overlay**, recorder read-only, **ZERO further PUT** (presign/r2put/confirm/progress), focus moved to the primary action + announced. If tab 2 held an **un-uploaded local recording**, warn plainly it was **not** included.

### E. Submit, finalization, read-only & timer (shared spine)

18. **Submit contract — upload-then-finalize, re-entrancy-guarded (Winston B1; Sally B3).** On Submit: a **synchronous re-entrancy ref-guard** (guards the whole multi-second upload window, before the finalizer's own latch engages) → **`await ensureLatestTakeUploaded()`** (presign→PUT→confirm → write the key into the draft cache so `getContent` sees it) → **`finalizeAttempt({flush, submit, alreadyFinalized})`** (the shared finalizer stays upload-agnostic; flushes the now-current key → `POST /submit`; terminal-409-on-flush falls through to submit — 5.2b CRITICAL #1). The dialog (desktop) / **slide-up sheet** (mobile) confirms **has-recording + duration** and the **late policy**; a **sub-threshold/silent take** (`durationSec < SPEAKING_MIN_DURATION_SEC`, or absent `audioKey`) shows a non-blocking **"no usable recording — submit anyway?"** warning (Sally B3 — a silent Blob must not sail through). The no-recording path **skips the upload** and submits keyless content cleanly. A genuinely failed final flush surfaces "couldn't save — retry", never a silent lossy submit.
19. **Server-anchored timer + read-only incl. UNTIMED hard-deadline + Blob-aware flush-on-flip (shared + Winston B2).** A single `serverNow()` (**never `Date.now()`**) drives the clock + read-only gate. Read-only when `submission.status != 'in_progress'` OR `assignment.status == 'closed'` OR `serverNow() >= hardDeadlineAt`; the derivation **TICKS** so an UNTIMED attempt flips read-only mid-session at `hardDeadlineAt` (reuse the promoted `useAttemptReadOnly`). Read-only disables record/upload/submit via an **inline banner**; **on the flip: if a pending uploaded `audioKey` awaits a PUT → ONE final boundary flush then ZERO further PUT; if a pending Blob has NO key yet (offline) → it CANNOT be salvaged → warn plainly, do NOT orphan-upload, do NOT silently drop**; move focus to the banner + announce. A racing 409/413 flips read-only through the shared error map.
20. **Resume-finalize expired TIMED attempts (shared).** A **timed** attempt past `startedAt + timeBudgetSeconds` on load runs the AC18 finalizer idempotently (submitting whatever `content` exists — may be keyless if never recorded; the grader then sees no audio — document). **Untimed speaking has NO auto-finalize** (only the AC19 due-date read-only flip). "Submits only while this tab is open" note on timed attempts (FU-5-1-A).

### F. States, i18n, a11y, mobile & the real-device gate

21. **Mobile variant (UX-4; thumb-first).** Purpose-built mobile tree (single-tree-per-breakpoint via `useIsDesktop`/`matchMedia`; never both trees). **Large thumb-friendly controls** — record ≥64px (s33), stop/re-record/submit ≥48px in the thumb zone, **≥16px font on interactive controls**. **Record — not just Submit — is reachable independent of cue-card length** (AC3 bounded prompt; Sally S2). Submit always-reachable. ≥44×44 CSS px targets.
22. **Loading / Empty / Error trilogy (UX-1).** Loading = a speaking-shaped **skeleton** (cue-card + record-block placeholder — not a spinner). "Empty" N/A (an attempt always has a cue card; the pre-record state is baseline — noted so it isn't read as an oversight). Load error = inline retry for transient 5xx/network; `404`/`403 NOT_ENROLLED`/`403 INSUFFICIENT_ROLE` → **non-retryable**. Copy i18n, no raw HTTP codes.
23. **Submission confirmation end-state (shared).** Post-submit = the shared `SubmissionConfirmation`. Not a placeholder. Graded result = 5.5.
24. **i18n + a11y.** New `speaking.*` strings (+ reused `attempt.*`) in **both** locales (`assertI18nParity`), VN-length-checked on the tightest chrome (record label, prep/offline/upload lines, the **multi-step mic-recovery list**, submit sheet, overlays). Route role-gated `['student']`; teacher/owner → 403 (recorder **absent** in DOM). **Screen-reader recording path (Sally S3):** announce **"Recording started"** and **"Recording stopped — N seconds"** once each (`aria-live="polite"`); elapsed is **queryable via the stop button's `aria-label`** ("Stop recording, 0:42") — never per-second chatter. `axe` clean on every state (loading/pre-record/recording/**interrupted**/preview/error/read-only/offline/**permission-denied**/submitted-elsewhere). Keyboard flow tested as a flow incl. read-only/overlay focus-moves.
25. **Real-device release gate (A5).** The `MediaRecorder` pipeline is **NOT** covered by Playwright WebKit. Carry the **6-item real-device checklist** as an explicit release gate (record/re-record/upload on **real iPhone Safari** AND **real Android Chrome**; mic-denial UX; **incoming-call interruption → no orphan state** (AC11); survives 30s tab-backgrounding; submitted audio playable cross-device/browser). Playwright happy-path smoke is **ticketed, not a correctness gate**; do not claim "100% E2E coverage" for the recorder.

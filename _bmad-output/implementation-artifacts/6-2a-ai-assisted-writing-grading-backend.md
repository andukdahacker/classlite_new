## Story

As a **Teacher**,
I want **the backend to run AI over a Writing submission on demand — deduct a credit, send the essay + IELTS rubric to Gemini, and return proposed band scores (with rationale + confidence) and anchored inline comments as reviewable *suggestions*** ,
so that **the s23 grading UI (6.2b) can let me review AI suggestions and grade in ~3 minutes instead of ~12 — while I remain the one who commits the final grade.**

**Scope:** The backend AI writing-grade pipeline, riding the **existing 4.3a async spine with no new infra** (`jobs.type` is `text`, not an enum, precisely so Epic 6 registers a new handler — deferred-work.md:676). New: `ai_grade_writing` job type + params; `POST /api/submissions/{submissionId}/ai-grade` (enqueue + atomic 1-credit deduct); the `GradeWritingHandler` that calls Gemini, validates + normalizes, and stores **suggestions in `job.result`** (never a `grades` row); automatic refund-on-terminal-failure; and the latest suggestion surfaced through the teacher grading-read. Poll reuses `GET /api/jobs/{jobId}` **unchanged**.

**Explicitly NOT in this story:** any frontend (6.2b owns the suggestion-review UI, Accept/Edit/Dismiss, "Accept all praise", confidence badges, the >30s/>60s messaging, the non-blocking merge overlay, and the first-run "Try AI grading" card); the actual grade write (already shipped — 6.1 `POST …/grade`); Speaking AI grading (6.3); the 402 insufficient-credit gate + monthly-grant/purchase ledger reasons (6.5). See **Out of Scope**.

## Decisions (resolved during context recon — treat as spec, not suggestion)

- **D1 — The AI worker produces SUGGESTIONS, never a grade.** It does **not** call `InsertGrade` and does **not** UPDATE the `submissions` row. The result is written to `job.result` as `AIWritingGradeResult`. The teacher reviews in 6.2b, then commits via the **existing 6.1 `POST …/grade`** path (which re-validates, re-normalizes, computes the server-authoritative overall band, and inserts the append-only grade row). This mirrors 4.3a→4.3b (AI produces a fragment; the teacher inserts it). It also sidesteps the 6.1 immutability trigger (`submission_immutable_after_release`, P0001 on UPDATE of a `graded` row) — the worker never writes the submission, so a re-run on a graded submission cannot 500.
- **D2 — "Stored on submission for reference" (epic AC) is satisfied via the grading-read, not a submissions-row write.** Extend `GET /api/submissions/{submissionId}/grading` (`TeacherGradingView`) with `aiSuggestion: AIWritingGradeResult | null` = the **latest `complete` `ai_grade_writing` job's result** for that submission (new tenant-scoped sqlc query). The live in-progress case is served by the job poll; reopening the grading view rehydrates suggestions from this field. The student `/result` path is **untouched** — students never see AI suggestions.
- **D3 — Confidence + rationale live ONLY in the suggestion result.** `AIWritingGradeResult` carries per-criterion `confidence` (High/Medium) + `rationale`, and per-comment `confidence`. **None of it is persisted to `grades`** — the `grades.comments`/`criterion_scores` schema is unchanged (no confidence/rationale field). This encodes UX-DR22: "AI confidence shown to teachers, hidden from students." Once a teacher accepts a suggestion it becomes their own decision.
- **D4 — Credit: deduct in the enqueue tx; refund automatically on terminal failure; NO balance gate.** Reuse the 4.3a pattern exactly: `InsertJob` immediately followed by `InsertJobDeduction` (−1, `job_deduction`) in the **same** tenant tx (`ai_generation_service.go:58-90`). Refund (+1, `job_failed_refund`) is fired by the dispatcher's `terminalFail` (`dispatcher.go:217`) — **already wired for any terminally-failed job with a deduction**, idempotent on the full unique index `(ref_job_id, reason)`. Do **not** add a 402 insufficient-credit gate (6.5 owns it; an unfunded enqueue may drive balance negative pre-6.5 and that is acceptable — deferred-work.md:673). The "credit cost shown before confirming" is a 6.2b display concern.
- **D5 — Reuse 6.1's validation + normalization verbatim.** The worker runs `grading.ValidateCriterionScores` (1.0–9.0, 0.5 grid) and `grading.NormalizeComments` (UTF-16 anchor demotion → whole-essay) — the SAME functions the teacher grade-write uses — so any suggestion the teacher accepts is guaranteed to pass the 6.1 grade write. Out-of-range/off-grid bands → **terminal** `invalid_band_scores`; unparseable/malformed Gemini output → **terminal** `invalid_ai_response` (existing sentinel). Both terminal → refund. The worker emits `grammaticalRange` (NOT `…Accuracy`) and lowercase comment types.

## Decisions — folded from party-mode pre-dev review (Winston/Murat/John/Amelia, 2026-08-19)

These 7 close the review's block-list — decided here so dev does not reopen them:

- **D6 — Enqueue idempotency: partial unique index (B1; Ducdo-ratified).** A double-click / retry / multi-tab must NOT mint two jobs + two `-1` deducts (the refund path only covers *failures* — two *successful* jobs both keep their charge). Add ONE additive migration: `CREATE UNIQUE INDEX uq_jobs_ai_grade_inflight ON jobs ((params->>'submissionId')) WHERE type='ai_grade_writing' AND status IN ('pending','processing')`. The enqueue `InsertJob`s; a `23505` from this index rolls the tx back (so **the same-tx `InsertJobDeduction` also rolls back — zero second deduct**) and the handler returns the **existing** in-flight job (200). At most one in-flight AI grade per submission; a re-run *after* a completed run is allowed (status no longer pending/processing). This **revises the "no migration" claim** to "one additive partial-index migration; no schema/column change."
- **D7 — Essay accessor relocation (B2; import cycle).** `essayTextFromSubmission` lives in package `service`; the worker (package `worker`) cannot import it (`worker->service` cycle; `grade_release.go` proves the worker reads the DB directly via `generated.DBTX`, never through service). **Move the pure essay-text extraction to the leaf `internal/grading` package** (alongside `ValidateCriterionScores`/`NormalizeComments`/`OverallBand`); the existing `service` call site imports down. Both service and worker depend on `grading`; no cycle. Duplicating the accessor is rejected (drift).
- **D8 — Distinct terminal reason + type-based classification (B3/B8).** Both terminal modes wrap the terminal sentinel but carry a distinct prefix: `fmt.Errorf("invalid_band_scores: %w", ErrInvalidAIResponse)` and `fmt.Errorf("invalid_ai_response: %w", ErrInvalidAIResponse)`; `jobs.error_details` persists the wrapped `.Error()` so 6-2b can tell them apart (**confirm 4.3a `terminalFail` writes the caller's error string, not only the sentinel — if it writes only the sentinel, add a `reason` param**). Retry-vs-terminal classification is **type-based** (`errors.Is` on the sentinels), NEVER `strings.Contains` on the message — so a transient error whose text contains "invalid" (e.g. `"connection invalid, retrying"`) is not misclassified terminal.
- **D9 — Route/authz + read separation (B4/B5).** The route mounts on the **`aiChain`** (keeps the ~20/min AI rate limiter); teacher-of-class authz is enforced in the **service layer** — `assertTeacherOfSubmissionClass(ctx, tc, submissionID)` inside the enqueue tx, BEFORE `InsertJob` (the chain's `requireOwnerTenant` is a tenant extractor, not a teacher gate; SEC-1 — a mutating op re-validates role/membership from DB). Two reads stay separate: the **poll** `GET /api/jobs/{jobId}` is creator-private (`created_by=caller` — live progress belongs to the triggering teacher only); the **suggestion result** is class-shared via `TeacherGradingView.aiSuggestion` (D2, teacher-of-class authz), so a co-teacher/admin sees the suggestion but not the live poll. 6-2b MUST drive a non-triggering teacher's "ready?" off the grading-read, never the creator-scoped poll.
- **D10 — Result completeness + parity, the seam invariant (B9/B12).** Beyond range/grid, the worker rejects a **parseable-but-incomplete** Gemini result as terminal `invalid_ai_response`: all four criterion keys present with non-null `band`+`confidence`; every comment carrying a valid `type`+`criterion`+non-empty `text`. **Invariant the seam guarantees: anything in `job.result` with `status=complete` is a fully-valid, gradeable suggestion** — so 6.1's accept-path (in 6-2b) can trust it without re-deriving. The AI comment is structurally the 6.1 `AnchoredComment` + `confidence` (UTF-16 offsets into `content.text`, `grammaticalRange`, lowercase types); a parity fixture test pins it to the exact shape the grade write consumes.
- **D11 — Deterministic read + immutability + contract ripple (B10/B11).** The grading-read query orders `completed_at DESC, id DESC` (deterministic tiebreak on same-instant completions). Submissions are **immutable after submit** in v1 (FR-23 locked-after-submit; 6.1 FU-6-1-D flags resubmission-under-grade as not built), so the analyzed essay is stable — no version-fingerprint needed now (flagged as a future concern if a resubmission flow ever ships). `Job.result` widens to `oneOf: [AIGenerationResult, AIWritingGradeResult]` with **structurally disjoint** required keys, narrowed by `job.type`; **6-2a OWNS the 4.3b codegen ripple** — the regenerated `client.ts` turns `Job.result` into a union, so 6-2a narrows 4.3b's poll consumer by `type` (or carves it out with a tracking note) + adds a **consumer-contract golden-fixture test** proving the widening is backward-compatible for the existing `/api/jobs/{jobId}` consumer.
- **D12 — Deferred + determinism (B13/B14).** **Auto-run** ("runs automatically if configured") is **explicitly deferred** — not in 6-2a or 6-2b v1; manual teacher trigger only (-> `deferred-work.md` FU). Job **timeout->refund is already wired** — the dispatcher's 5-min `SweepStuckJobs` routes a hung `ai_grade_writing` job to `terminalFail`->refund, so a stuck AI grade refunds and surfaces the terminal state 6-2b renders as "grade manually" (make explicit; no new code). `latencyMs` is measured via the **injected `clock.Clock`** (deterministic golden in tests), never wall time.

## Acceptance Criteria

### A. Enqueue + credit

1. **`POST /api/submissions/{submissionId}/ai-grade` — enqueue, atomic deduct (AC / D4).** Teacher-only: caller is `teacher`/`admin`/`owner` **AND** assigned to the class the submission's assignment belongs to (reuse `assertTeacherOfSubmissionClass`); non-member class → `403 FORBIDDEN`, non-staff → `403 INSUFFICIENT_ROLE`. Submission must be a **Writing** exercise (`assertWritingExercise`; else `409 SUBMISSION_NOT_WRITING`) in `submitted` or `graded` status (else `409 SUBMISSION_NOT_GRADABLE`; `in_progress`/absent → `404`/`409` resolved within RLS first — no cross-tenant existence oracle). In **ONE tenant tx**: `InsertJob` (`type='ai_grade_writing'`, `params={"submissionId": "<id>"}` — **centerId is NEVER read from the body**, it comes from the tenant/row, SEC-7) immediately followed by `InsertJobDeduction` (−1 `job_deduction`, `ref_job_id`=new job). Returns **202** `{ data: { jobId }, meta }` (reuse `JobEnqueued`/`EnvelopeJobEnqueued`). **Route mounts on the `aiChain`** (keeps the AI rate limiter ~20/min, burst 20 — `main.go:630-647`); teacher-of-class authz runs in the service layer inside the tx BEFORE `InsertJob` (D9 — the chain's `requireOwnerTenant` is a tenant extractor, not a teacher gate). **Enqueue is idempotent (D6):** a second enqueue while an `ai_grade_writing` job for this submission is `pending`/`processing` hits the partial unique index `uq_jobs_ai_grade_inflight` → `23505` → the tx rolls back (deduct included — **no second `-1`**) and the handler returns the **existing** in-flight job (200); a re-run after a *completed* run is allowed.
2. **No balance gate (D4).** The deduct always inserts −1 with no non-negative guard (the 402 insufficient-credit gate is Story 6.5). A negative balance pre-6.5 is not a bug.

### B. Worker — `ai_grade_writing`

3. **`GradeWritingHandler` on the existing dispatcher (deferred-work.md:676).** Implements the `worker.GenerationHandler` contract (`JobType() model.JobType` + `ProcessTask` + unexported `generate(ctx, db generated.DBTX, gem gemini.Client, tc, payload) (json.RawMessage, error)`); registered in the `NewPoolDispatcher(...)` varargs in `cmd/api/main.go`. One additive partial-index migration (D6); no dispatcher change. The handler reads the submission's essay `content.text` **through an RLS-scoped store query on `db`** — the dispatcher has already `SET LOCAL app.current_tenant_id` from the **job row's `center_id`** (the sole trust anchor), and the essay fetch relies on RLS so a mismatched payload `centerId` physically returns 0 rows, never a hand-written query that bypasses RLS; a payload `centerId`, if ever present, is **ignored** (logged as a discrepancy signal, R3).
4. **Gemini call + result (D3).** Build the IELTS Writing rubric prompt + the student essay into a single `gemini.GenerateRequest.Prompt` (there is no structured-schema param — the rubric is embedded in the prompt; `responseMimeType: application/json` is pinned by the client). Parse into `model.AIWritingGradeResponse`: the four criteria each with `{ band, rationale, confidence }`, plus anchored `comments[]` each `{ type, criterion, anchorStart, anchorEnd, text, confidence }`, plus an optional whole-essay `overallFeedback`, plus `analyzedWordCount` + `latencyMs` (for the UX "analysed 287 words · 1.4s" line — `latencyMs` from the **injected `clock.Clock`**, not wall time, so the golden result is deterministic in tests — D12). Store the validated+normalized result in `job.result` (`result_schema_version = 1`). **The worker does NOT compute or store an overall band** — 6.2b previews it from the four AI bands via the client mirror, and the authoritative overall is computed only when the teacher commits the grade (6.1).
5. **Validation + completeness + normalization + failure classification (D5/D8/D10).** Run `grading.ValidateCriterionScores` on the four bands: any out of 1.0–9.0 or off the 0.5 grid → **terminal fail** `invalid_band_scores`. **Completeness (D10):** reject a parseable-but-incomplete result — a missing criterion key, a null `band`/`confidence`, or a comment missing `type`/`criterion`/`text` → **terminal fail** `invalid_ai_response`; the seam invariant is "anything in `job.result` at `status=complete` is fully valid + gradeable." Run `grading.NormalizeComments(comments, essayText)`: an anchor that is out-of-range OR splits a UTF-16 surrogate pair is **demoted to whole-essay (null/null), never dropped** (the epic's "orphaned comments → general feedback" rule). Unparseable Gemini output → **terminal fail** `invalid_ai_response`. **Distinct `error_details` (D8):** the two terminal reasons wrap the same `ErrInvalidAIResponse` sentinel but carry distinct prefixes (`fmt.Errorf("invalid_band_scores: %w", …)` / `"invalid_ai_response: %w"`) persisted to `jobs.error_details`; **retry-vs-terminal classification is type-based (`errors.Is`), never `strings.Contains` on the message.** Emit `grammaticalRange` and lowercase `error`/`praise`/`suggestion`.
6. **Worker writes nothing but the job (D1).** No `grades` row, no `submissions` UPDATE. The only DB writes on success are `MarkJobComplete` + the `job.result` payload (through the dispatcher).

### C. Refund + idempotency

7. **Refund on terminal failure (R23 / D4).** A terminally-failed `ai_grade_writing` job that carried a `job_deduction` gets a `+1 job_failed_refund` inserted in the **same tx** as the terminal status mark (existing `terminalFail` → `RefundJob`, `dispatcher.go:217`), `ref_job_id`=job. Assert this fires for the new job type on all three terminal paths: `invalid_band_scores`, `invalid_ai_response`, and `max_retries_exhausted`.
8. **Refund idempotency (R23).** The full unique index `(ref_job_id, reason)` on `ai_credit_ledger` makes a duplicate refund a no-op (`ON CONFLICT DO NOTHING`). Assert a double-refund attempt inserts exactly one refund row (SQL-seam test, mirrors 4.3a `TestAICreditLedger_DoubleRefundIsNoOp`). Transient Gemini errors retry (30/60/120s, max 3) and only refund after exhaustion — not per attempt.

### D. Reads

9. **Poll reuses `GET /api/jobs/{jobId}` unchanged — creator-private (D9).** The existing creator-scoped poll (`GetJobByID` filters `created_by = caller` → a non-creator, incl. a student OR a co-teacher who did not trigger the run, gets 404, no oracle) returns `status` + `result`. Live progress is the triggering teacher's only; a co-teacher/admin reads the *result* via AC10, not this poll. `Job.type` is a free `string`, so the generic poll + `EnvelopeJob` serve the grading job as-is; the `result` schema widens to a **structurally disjoint `oneOf` including `AIWritingGradeResult`, narrowed by `job.type`** (AC10 api.yaml; **6-2a owns the 4.3b consumer ripple** — D11). No new poll endpoint.
10. **Grading-read surfaces the latest suggestion — class-shared (D2/D11).** Extend `GET /api/submissions/{submissionId}/grading` → `TeacherGradingView.aiSuggestion: AIWritingGradeResult | null` = the latest **`complete`** `ai_grade_writing` job's result for this submission (new sqlc query: filter `type='ai_grade_writing' AND status='complete' AND params->>'submissionId' = $1`, RLS-scoped, **`ORDER BY completed_at DESC, id DESC LIMIT 1`** — deterministic tiebreak on same-instant completions). Authz = teacher-of-class (not `created_by`), so a co-teacher/admin sees the suggestion. `null` when no completed AI grade exists. The student `/result` path (`StudentGradeView`) is **not** touched.

### E. Security & tests

11. **Worker 3-pattern harness — MANDATORY (R3=9, WF-8 ATDD gate).** Using `test.SetupWorkerHarness` (`internal/test/workers/harness.go`), red-first before in-progress: **`TestGradeWriting_HappyPath`** (`ProcessSpecific` → assert `job.result` shape, validated bands, demoted orphan comment); **`TestGradeWriting_PayloadCenterIdIgnored`** (payload `centerId`=tenant B, job row=tenant A → handler reads from the row → RLS 0 rows → `NotFoundError`); **`TestGradeWriting_NullTenantContextRejected`** (`ProcessWithoutTenantContext` → every DB read returns 0 rows). TEST-BE-5: inject a mock Gemini — add per-test-constructable `valid_writing_grade` + `invalid_band_scores` modes to `internal/gemini/mock.go` with a `CallCount()` spy; **real Gemini banned in CI**.
12. **Party-review test additions — MANDATORY (map to risks ≥6 → WF-8 red-first).**
    - **R3-submission (R3=9; the generic harness does NOT cover this — Murat).** The 3 patterns prove the *job* read; this worker reads a *submission*. Seed submission S under tenant B; enqueue an `ai_grade_writing` job whose ROW is tenant A referencing S; run the real handler under tenant A → assert the **essay fetch returns 0 rows → terminal/NotFound**, the **Gemini mock is NEVER invoked** (`CallCount()==0` — the load-bearing tripwire that tenant B's essay never reached the model), and **no result is written**.
    - **R23-retry refund-exactly-once (R23=6).** Mock transient-fail ×3 then exhaust; **poll the ledger after attempt 1 → exactly 1 row (the deduct only)**; at end exactly 2 rows (`-1` deduct + one `+1 job_failed_refund`). The intra-retry poll catches "refunds every attempt but the `(ref_job_id,reason)` constraint hides it" (a final-balance-only test false-greens).
    - **Failure taxonomy table (type-based; D8).** One row per class → `{invalid_band_scores→terminal+refund, invalid_ai_response(malformed)→terminal+refund, invalid_ai_response(incomplete)→terminal+refund, transient→reschedule+0 refund rows, max_retries_exhausted→terminal+refund}`, plus an adversarial **transient-that-string-matches-"invalid"** row asserting it reschedules (not terminal) — proves classification is `errors.Is`, not `strings.Contains`.
    - **Zero-writes immutability (R16=6).** After a *successful* job, read back the submission row + any `grades` row → **byte-identical / absent** (positive proof the worker wrote neither — D1).
    - **oneOf consumer-contract (D11).** A golden `ai_grade_writing` result fixture through 4.3b's actual `GET /api/jobs/{jobId}` poll parser → no throw, unknown-type falls to a safe default (proves the `Job.result` widening is backward-compatible).
    - **Anchor/criterion parity (D10).** A parity fixture pins an AI-produced anchored comment to the exact 6.1 `AnchoredComment` shape the grade write consumes (mirror `essayAnchorParity`); **fixture-coupling: the mock payload's comment offsets are expressed relative to `len(fixtureEssay)`** (one at `len+5` = guaranteed orphan; one straddling a known emoji index) so the demotion assertion is not green-but-vacuous.
    - Plus (from AC11 base): deduct+enqueue single-tx rollback (→ no job AND no ledger row); **enqueue idempotency — a 2nd in-flight enqueue returns the existing job + inserts NO 2nd deduct (D6)**; refund on each terminal path + double-refund no-op (AC7/8); `NormalizeComments` surrogate/orphan demotion via a multibyte fixture (emoji+accent) round-tripped Go-side; enqueue authz negatives (teacher-of-other-class 403, non-writing 409); grading-read `aiSuggestion` latest-complete + absent from the student path; secret/prompt/response never logged (reuse the 4.3a R49 assertion).

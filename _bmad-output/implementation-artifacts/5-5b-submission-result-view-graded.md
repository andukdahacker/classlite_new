## Story

As a **student**,
I want **to see my released grade on my submission — the overall band, the per-criterion breakdown, and my teacher's feedback with the exact comments they pinned to the words in my essay, plus a clear, calm explanation of any late penalty**,
so that **I understand my performance and know precisely what to work on, reading the teacher's anchored comments in the exact place on my own writing where they left them (the reciprocity spine — anchored comments ARE the teacher↔student channel; there is no messaging product), on the same page where I already re-read my submission**.

**Scope:** Frontend-only. When the 5-5a "review my submission" page (`/assignments/:assignmentId/submission`) loads a submission whose grade has been **released** (`result.released === true`, `result.grade` non-null), render the **graded block above the existing read-back**: overall band (circular `band-ring` hero), per-criterion breakdown (four IELTS criteria, each annotated with its pinned-comment count), the teacher's feedback quote, and — for a **writing** submission — the anchored comments painted as inline highlights on the student's own essay (reusing 6.1's `buildEssayHtml`), read-only, with a comment rail (desktop) / inline-under-line expansion (mobile s79). Compose and show the neutral late-penalty math when `submission.isLate`. Register the reserved `/assignments/:id/result` route (D-ROUTE). Add a read-only acknowledgment line (D-ACK) and a client-tracked "new result" unread indicator on the `/assignments` list so a released grade is discoverable (D-DISCOVERY). **Out of scope:** any backend/api.yaml/codegen change (6.1 shipped it); the anchored-Q&A "Have a question?" card (FR-38/Epic 7); speaking (6.3) + quiz auto-grade (6.4) *graded* layouts — only WRITING can be `released` in v1.

## Acceptance Criteria

### A. Grade gating & the released/pending branch

1. **Released branch on the durable shell (5-5a AC5 seam).** Given a terminal submission read via the existing `useSubmissionReview` (`GET /api/assignments/{assignmentId}/result`), When `result.released === true` **and** `result.grade` is non-null, Then the **graded block renders ABOVE the read-back** and the quiet `NotReleasedNote` is **replaced** by a released-state header; When `result.released === false` (the pre-Epic-6 baseline — still the default for un-released or non-writing submissions), Then the page renders exactly as 5-5a does today (no regression). `released` is the ONLY gate — never branch on `submission.status` or "a grade object exists" (a stored-but-unreleased 6.4 grade must show pending). `grade` is typed `StudentGradeView | null` in the generated client (`client.ts:3132`, verified nullable — no codegen fix needed).
2. **`grade`/`released` threaded, not refetched.** `SubmissionReviewPage` already holds `result`; thread `result.released` + `result.grade` into `SubmissionReviewShell` props (extend `SubmissionReviewShellProps`). NO new query, NO new hook, NO new endpoint — 6.1 put the data on the wire type 5-5a already consumes.

### B. Overall band & per-criterion breakdown (epic AC #1, #2; UX-DR22 §6.4)

3. **Overall band hero — appears, does not perform (Sally BLOCKER).** Render `grade.overallBand` (server-authoritative IELTS half-band, `number` on the 1.0–9.0 / 0.5 grid) as the oversized hero — a **circular `band-ring`** on the student result (§6.4/s35), displayed to one decimal (`toFixed(1)`; mirror `formatBand` from `WritingGradingSurface.tsx:60`). NEVER recompute the band client-side (`overallBand` is authoritative; `computeOverallBand` is teacher-input-preview only). **NO celebratory motion** — the ring appears via a calm fade/scale that reads **identically at 4.0 and 8.0**; no sweep-fill, no count-up (a victory-lap animation over a disappointed student is grotesque — Sally). **One neutral ink stroke, all bands** — the ring stroke is NOT band-tinted (no green-high/amber-low; that would leak the never-red principle into a scarlet-letter ring).
4. **Per-criterion breakdown — strength-first, a REQUIRED focus area (Sally BLOCKER: MAY→MUST).** Render `grade.criterionScores` — `taskResponse`, `coherenceCohesion`, `lexicalResource`, `grammaticalRange` — as per-criterion bars/numerals (Geist Mono, §6.4), each labelled via the **existing** `criterion.*` i18n keys (`en.json:362-365` + vi parity — reuse, do not add). Each criterion **annotates its pinned-comment count** ("Lexical · 1 pinned") by grouping `grade.comments` by `criterion`; a criterion whose pins include an `error` is accent/red-bordered per §6.4 (the ONLY sanctioned red — a low *band* is never red). **Ordering is strength-first: name the relative strongest criterion as a strength AND the relative weakest as a "focus area" (REQUIRED, not optional — every essay has a relative min/max even at 4.0; a result with no next-step is a verdict, a result with a focus area is coaching).** Framing is neutral-positive, NEVER confetti and NEVER "you're weak here" — the focus area reads "keep pushing here". **Graceful degrade for the all-strong essay:** when scores are tied/uniform (e.g. straight 8.0), do NOT manufacture a weakness — degrade the focus-area to a neutral "keep it up" rather than flag the arithmetically-lowest as a flaw. IELTS terms wrapped `<span lang="en">` (spec line 279).

### C. Feedback & read-only anchored comments (epic AC #3; §6.3 reciprocity — THE keystone)

5. **Teacher feedback quote + read-only acknowledgment (Sally/John — no dead-end silence).** When `grade.feedback` is non-null/non-empty, render it as an attributed editorial quote block (`FeedbackQuoteBox` treatment, inventory line 148 — build it; doesn't exist yet). `feedback` is raw teacher free-text → render as **escaped text** (React text node — never `dangerouslySetInnerHTML`). No teacher identity is on the wire (`StudentGradeView` excludes `graded_by` by design) — attribute generically ("Your teacher"). **The student view is read-only — so it MUST (a) render NO dead reply affordance (no ghost "reply"/chevron/input-shaped box/"Have a question?" header — a read-only card must look settled, never like a form that failed to load) and (b) carry ONE quiet honest line acknowledging the channel is one-way here** (e.g. "Your teacher left these notes on your writing — bring any questions to your next class"), so the deferral of anchored-Q&A (Epic 7) is a *deliberate* end, not silence on the product's only teacher↔student channel. Copy in i18n, PM-blessed tone (see Decision D-ACK).
6. **Anchored comments on the essay — reuse `buildEssayHtml` (writing; STRONG, no re-index, no local re-derivation).** Given a **writing** submission with `grade.comments`, Then the student's essay (`submission.content.text`) renders with each anchored comment painted as an inline `<mark class="cl-anchor-{error|praise|suggest}">` highlight **via 6.1's `essayAnchors.buildEssayHtml(text, anchors)`** (from the shared tier per Task 0 / W1), which HTML-escapes BOTH the essay text AND the anchored spans, is UTF-16-surrogate-safe, and returns branded `SafeHtml`. **The student block MUST consume `buildEssayHtml` + `anchorToneClass` for ALL anchor visuals — it may NOT compute tone colors, mark boundaries, or offset slicing independently (Winston — that local re-derivation IS the teacher/student drift vector).** The `AnchoredComment` wire offsets (`anchorStart`/`anchorEnd`, UTF-16 code units into `content.text`, exclusive end) map straight to `EssayAnchor {start,end,type,index}`; **a comment with `anchorStart===null && anchorEnd===null` is a whole-essay comment** — not painted inline (see AC7a). The wire enum is `suggestion`; the tone class is `cl-anchor-suggest` — map it via an **exhaustive/`never`-checked** converter in `gradeComments.ts` (a future 4th wire enum must fail `tsc`, not silently drop a comment — Winston). CRITICAL: the highlighted essay REPLACES the plain `ResultWritingReadback` pre-wrap block when graded — do **not** render a second copy and do **not** re-derive offsets against a re-fetched/re-normalized text; feed the SAME `readWritingText(submission)` the 5-5a readback uses (see the AC7b XSS note: the injection vector is the *teacher comment text*, not the student essay).
7. **Read-only comment rail / cards (reuse `CommentCard` + additive `readOnly`; suppress ALL affordances).** Each anchored comment renders as a read-only card (tone chip error/praise/suggest, criterion label, escaped body) beside the essay (desktop rail) / inline-under-line (mobile — AC10). Reuse the shared domain `CommentCard` (`@/components/domain/CommentCard`) but it currently **always** renders a Resolve/Edit footer — add an **additive `readOnly?: boolean`** prop. When `readOnly`, it MUST suppress **every** interactive affordance, not just the footer — audit the card's full interactive surface (footer buttons, any body click/hover-edit, focusable controls) and gate ALL of it; a student must not trigger a no-op or teacher-context handler (Winston W3). Preserve the pin↔card click-to-scroll reciprocity read-only (click a highlight → its card scrolls into view via `data-anchor-index`/`data-testid="comment-card-{slug}"`). Default `readOnly=false` → teacher behavior byte-for-byte unchanged. Comment `body` (`text`) is escaped (CommentCard renders it as a React text node — assert, don't assume).
   - **7a. Every teacher comment is student-reachable — the reciprocity invariant (Sally + Murat BLOCKER).** No comment the teacher wrote may silently vanish (a dropped comment breaks reciprocity harder than anything). **Whole-essay (null/null) comments** collapse into a **"General notes" group pinned above the essay on BOTH breakpoints** (desktop rail top + mobile — there is no line to anchor under on mobile). **Overlapping/co-located inline comments on mobile:** a paragraph with N marks on one line does NOT accordion N cards inline (it tears the essay apart) — use a single tap-target opening a **count** ("N notes here") into a focused sheet, OR a defined stacking order (error → suggestion → praise) with "+K more". Assert: every element of `grade.comments` is reachable in the rendered DOM (count parity), and a null/null comment is in the General-notes group, NOT double-painted as a `<mark>`.
   - **7b. XSS — the vector is the teacher COMMENT text, not the essay (Murat/Winston BLOCKER).** The comment `text` (teacher-authored, cross-user) is composed into the `dangerouslySetInnerHTML` essay region and the card body. Tests assert the *dangerous capability is ABSENT* (not that a `<script>` string is escaped — jsdom won't execute it, false confidence): a comment `text = '"><img src=x onerror=alert(1)>'` → `container.querySelector('img[onerror]')` is null AND the `<mark>` has no `onerror`/injected attribute; a `text` containing `</mark><script>` → exactly N marks, no stray script node; `feedback` with a literal `<` → survives as `textContent`, no injected element. This is the single highest-value test in the story.

### D. Timing, penalty math, and the permanent omissions

8. **On-time / late status on the graded view (epic AC #4).** The 5-5a `SubmissionStatusBadge` (neutral, `submission.isLate`, muted never-red) continues to render; the graded view keeps it visible near the header.
9. **Late-penalty math — client ARRANGES server numbers, neutral (epic AC #5; FR-31).** Given `submission.isLate === true` and `submission.appliedPenalty > 0`, Then render the penalty breakdown in the exact FR-31 format — **"Original: 6.0 − Late penalty: 0.5 = Final: 5.5"** — from `grade.overallBand` (original) − `submission.appliedPenalty` (the immutable submit-time snapshot) = final, with a plain-language explainer ("applied because your work was submitted after the due date"). The client only *arranges/displays* server-authoritative numbers; **the "Original" is `grade.overallBand`, which is NOT penalty-adjusted by the backend** — VERIFY at Task 0 (John/Winston: a two-source composition across the API boundary; `overallBand` = pure IELTS mean of the four criteria per 6.1, `appliedPenalty` is a separate `submission` field, so no double-subtraction — but pin it as a tested contract, not a code comment). Framed **factually, never alarmed / never red** (spec line 507; muted tokens; 5-5a's badge already sets this precedent). Build `LatePenaltyBreakdown` (inventory line 225 — doesn't exist). **When on-time / `appliedPenalty === 0`, the block is ABSENT — never render a "Late penalty: 0.0" line** (a phantom zero-penalty line accuses an on-time student of a crime they didn't commit — Sally).
10. **Mobile s79 — hero + inline-under-line comments (epic AC #8; §s79).** Single-tree-per-breakpoint via `useIsDesktop()` (5-5a precedent). Mobile: **hero band at the top**, per-criterion **vertical stack**, and anchored comments that **expand inline under the line — NOT a side rail** (spec s79 line 622). Desktop MAY mirror the teacher two-column essay+rail. Touch targets ≥44×44, reading measure ≥16px (5-5a mobile investment precedent). No gold-plating — invest the split where the layout genuinely differs (comment placement), not in re-flowing the band chrome.
11. **Permanent omissions — DOM-negatives, render gate not visibility gate (epic AC #7; FR-32; §preamble; Murat BLOCKER).** Class/cohort average is **structurally absent** from the DOM in every state (not hidden). AI confidence is **absent** (teacher-only). Teacher identity (`graded_by`) is **absent**. No peer/roster comparison. Assert absence of the *element/attribute that would exist if it leaked*, not merely "not implemented": no `[data-grade]`/`[data-score]`/`[data-raw]`; no element whose attribute *value* contains `graded_by`/`gradedBy`; no `<script type="application/json">` hydration blob carrying the raw `StudentGradeView`; a band-ring/criterion node's `aria-label`/`title` resolves to *exactly* the band/label, nothing appended. **The released gate is a RENDER gate, not a visibility gate (defense-in-depth):** given a payload with `released:false` **and** a fully-populated `grade` (cannot happen from the real server — VERIFIED `attempt_service.go:132-145` nils it — but assert the client's own invariant), the band + criteria + comments are **absent from the DOM**, not CSS-hidden. Query the DOM text/attrs for the band value → null.

### E. States, i18n, a11y

12. **Trilogy extended + the released seam is ONE document (UX-1; Sally/John).** The 5-5a Loading skeleton (`ReviewSkeleton`, `role=status`), the 404→not-started / in_progress→resume / 403 non-retryable / transient-retry error shells all continue unchanged. Add a **skeleton region for the grade block** (band-ring + criteria placeholders — a skeleton, never a spinner; mirror the teacher `GradingSkeleton` shape), ordered so the hero resolves **before/with** the essay below it — never leave a grey pulse throbbing above an already-loaded essay (that pulse *is* anxiety — Sally). When `released===true`, the 5-5a `NotReleasedNote` ("grades not released yet") is **replaced/suppressed** — the student must NEVER see "grades not released yet" *above* their band score (the exact seam a split leaks — John). The graded hero and the read-back below read as **one continuous document** ("here's your grade, and below, your essay with notes"), not two features stacked; the read-back is NOT orphaned. **Invalid-state cell (Winston):** `released===true && grade===null` is a type-allowed contradiction — treat it as **pending** (render the 5-5a `NotReleasedNote` path), do not render an empty grade block. **Submission timestamp (FR-32):** verify the 5-5a read-back (which renders the timestamp/`SubmissionStatusBadge`) still renders in the released state — the graded block sits ABOVE it, never replaces it (John).
13. **i18n `submissionReview.grade.*` — both locales.** New keys in **both** `en.json` + `vi.json` (`assertI18nParity`, VN-length-checked on the tightest mobile chrome): overall-band label, feedback attribution, per-criterion pinned-count (`t('...pinned', {count})` — i18next plural), the late-penalty breakdown + explainer, focus-area label, comment tone labels if needed. Reuse existing `criterion.*` + `commentCard.*` + `grading.overall.*`/`grading.bands.*` keys (do not duplicate). Never concatenate a translated string with a raw band number — interpolate.
14. **a11y — axe clean every state; anchored reciprocity keyboard-reachable.** `axe` clean on: graded-writing, graded-with-penalty, released-but-no-comments, on-time graded, mobile graded, plus all 5-5a states (no regression). The essay highlights and their cards are keyboard-reachable and associated (a highlight and its comment are programmatically linked, not colour-only — the criterion label + tone chip carry the type for AT, mirroring `CommentCard`'s aria-hidden glyph pattern). Focus-on-heading + `<title>` (5-5a) still hold. Band/criteria numerals are not colour-only.

### F. Release-discovery signal (D-DISCOVERY — John BLOCKER, Ducdo-ratified in-scope)

15. **"New result" unread indicator on the `/assignments` list.** Given a student's assignment whose result is **released**, When they view the `/assignments` list (5.2c), Then the row carries a **"new result" unread indicator** (dot/pill) drawing the eye to the graded row — so a released grade is discoverable without a notification (Inbox is Epic 10). **Unread is client-tracked (frontend-only):** a small shared `@/lib` localStorage helper keyed by `assignmentId` (+ `gradedAt` when the list row carries it, so a re-grade re-arms — if the list row lacks `gradedAt`, key by `assignmentId` only and note the re-grade-rearm limitation as part of FU-5-5b-DISCOVERY). The indicator **clears when the student opens the result** (`SubmissionReviewPage` marks the assignment seen on mount of the released state). Per-device best-effort — **durable/cross-device unread is Epic-10 Inbox (FU-5-5b-DISCOVERY)**; do NOT add a backend `viewed_at` here (would break frontend-only). The row already distinguishes graded rows (`assignments/lib/assignmentRow.ts`); this adds the unread emphasis + the seen-clear. i18n both locales; a11y: the indicator has an accessible label (not colour-only); role-negative (teacher/owner list unaffected). Touches the `assignments` feature — thread via its public surface (TS-7), no deep import.

### The data contract (already on the wire — verified on HEAD)
- `GET /api/assignments/{assignmentId}/result` → `StudentSubmissionResult` (`client.ts:3124-3137`): `submission`, `assignment`, `exercise`, `audioUrl`, **`released: boolean`**, **`grade: StudentGradeView | null`**, `inProgress`. `released` flips true IFF the latest grade version has `released_at IS NOT NULL` (backend `attempt_service.go:130-145`) — NOT off `submission.status`.
- `StudentGradeView` (`client.ts:3200-3207`): `overallBand: number` (server-authoritative IELTS half-band, 1.0–9.0/0.5), `criterionScores: CriterionScores`, `comments: AnchoredComment[]`, `feedback: string | null`, `gradedAt: string`. **No `graded_by`** (privacy — student-safe projection). **No penalty field** (penalty lives on `submission.isLate` + `submission.appliedPenalty`).
- `CriterionScores` (`client.ts:3142-3151`): `taskResponse`, `coherenceCohesion`, `lexicalResource`, `grammaticalRange` (each `number`).

Both offsets null → whole-essay comment. `text`/`feedback` are raw teacher free-text → **escape on render (XSS)**.

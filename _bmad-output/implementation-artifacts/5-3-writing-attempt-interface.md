## Story

As a **student**,
I want to **compose a writing assignment in a distraction-free plain-text surface showing my live word count against the task minimum, my time-on-task, and a calm due-date countdown, that silently autosaves every pause with a local safety net which — even offline or after a crash — never loses or overwrites what I typed, and warns me plainly if I've already submitted in another tab**,
so that **I can write and submit my essay end-to-end without losing work, without under-writing the task by accident, and without a second tab or a flaky network clobbering my draft**.

**Scope:** Frontend only — desktop `s34` at `/assignments/:assignmentId/write` + mobile `s78`. Consumes the **shipped** backend (`POST /api/submissions` start/resume · `GET /api/submissions/{id}/attempt` draft+prompt · `PUT /progress` · `POST /submit`) and the **shared `src/features/attempts/` spine (5.2d)**. **No backend/api.yaml/schema/codegen change, no new dependency.** The writing `content` shape is FE-owned over the opaque `SubmissionContent` bag. The student `/assignments` list (5.2c, done) already deep-links here via `attemptRouteForSkill` (stubbed `null` for `writing` — Task 8 un-stubs). Graded Result view = 5.5; Speaking = 5.4. **Releases independently** — its entry point exists via the 5.2c un-stub (contrast 5.2b/D13, which had none). **Depends on 5.2d merging** (the shared spine); 5.4 depends on 5.2d too, not on 5.3.

## Acceptance Criteria

### A. Bootstrap, editor leaf & the plain-text contract (FR-29, D1)

1. **Two-call start/resume + resume-draft.** Given a student opens `/assignments/:assignmentId/write`, When the page mounts, Then it runs the shared bootstrap (`POST /api/submissions {assignmentId}` → 201 new / 200 resume, then `GET /api/submissions/{id}/attempt`). The **last-autosaved draft is read from `data.submission.content`**, the **prompt from `data.exercise.sections[].content`**. A terminal submission → **409** `SUBMISSION_EXISTS` on start → route to the confirmation end-state (AC19), not an error page.
2. **Plain-text editor as an ISOLATED, UNCONTROLLED leaf (D1; Winston BLOCKER 2 — architecture.md:255).** The writing surface is an accessible auto-growing plain **`<textarea>`** (NOT React Hook Form — FW-8; NOT rich-text; **no new dependency**). It is an **isolated leaf component with its own uncontrolled value** (`defaultValue` seeded once from the draft; `onChange` writes a ref, not per-keystroke `setQueryData`). Word count is computed **inside the leaf** so a keystroke re-renders only the leaf, never the whole shell/timers. The Query-cache draft slice and the localStorage mirror are written on a **debounce** (from the ref), not on every keystroke; `getContent` reads the ref at save time. **Never bind the textarea `value` to the cache draft** (that reintroduces the banned per-keystroke shell re-render + per-keystroke `JSON.stringify`/`localStorage.setItem`).
3. **Prompt block.** The prompt renders as a **blockquote above** the editor, carrying **`lang="en"`** on the whole block (Sally S8 — it is English prose read to a VN student; term-level `lang` is insufficient).
4. **Content contract (D1 — 5.3 OWNS the writing shape).** `submission.content = { schemaVersion: 1, text: string }` — plain text, opaque to backend, ≤256 KiB (413 guarded). Each save is a **full replace**. No HTML/structured doc/sanitizer (grading reads `text`, Epic 6). A resumed `content` with missing/old `schemaVersion` normalizes without throwing; every PUT body is `{schemaVersion:1, text}`. Downstream (AC19 confirmation, Epic-6 grading) must render with `white-space: pre-wrap` so paragraph `\n`s survive (Sally N3).
5. **No formatting toolbar (D1).** `WriteDocSurface`/`MobileWritingSurface` render with the additive **`showToolbar={false}`** (default `true` preserves the grading-surface consumers). Restore the header/body separator the toolbar's `border-y` provided (Sally N1).

### B. Word count (+ minimum), time-on-task, due-date (FR-29)

6. **Live word count vs minimum (Ducdo ruling 2026-08-05 — client-side minWords now).** A single canonical `countWords(text)` (whitespace-split; unit-tested for empty / whitespace / multi-space / tabs / CRLF-vs-LF / newline / leading-trailing / long-single-token / VN-diacritic words) updates **in real time** (tracks the live editor value, decoupled from the 30s autosave — updates before any PUT). Displayed as **"{count} / {min} min"** with an **"+N above / N below min"** delta, in the desktop footer and the mobile **sticky word-counter strip** (AC18). `min` comes from a **client-side default keyed to exercise/task type** (IELTS-style default, e.g. Task-1=150 / Task-2=250; a documented `WRITING_MIN_WORDS` map, no backend field — FU-5-3-A tracks migrating to an `exercise.minWords` field). `countWords` must be **IME-composition-safe** (respect `compositionstart`/`compositionend` so Vietnamese telex/VNI diacritic composition doesn't miscount — Sally S9).
7. **Under-length submit warning (Sally S1 / §7.2 no-ambush).** Given `countWords < min` at submit, Then the submit dialog/sheet (AC15) shows a **non-blocking under-length warning** ("below the {min}-word minimum — you can still submit") so a student never under-writes the task unaware. Does not block submission.
8. **Time-on-task tracker.** Elapsed since `submission.startedAt`, computed off the shared server clock (`serverNow()` = `meta.serverTime` + `performance.now()`-delta, **never `Date.now()`**), rendered `M:SS`/`H:MM:SS`. Wires the real timer the `WriteDocSurface.timeOnTaskSec` shell awaits (1d-4 deferred-work). The numerals are **`aria-live="off"`** (Sally S5 — no per-second SR narration). Label it honestly as open/elapsed time, not "active" time (Sally N2).
9. **Due-date countdown — calm, not urgent (Sally S5 / §7.2).** A **calm-informational** due-date countdown to `data.assignment.deadlineAt` off `serverNow()` (NOT the exam-timer amber/red-pulse ramp — brand §7.2 "calm over urgency"; distinct from a *timed* exam clock). Numerals `aria-live="off"`. **Crossing the deadline is announced once** via `aria-live="polite"` ("now past due — a late penalty may apply") and flips an overdue state — not a silent recolor. Late accepted until `hardDeadlineAt`/close (5.1). **Timed writing** (`submission.timeBudgetSeconds != null`) additionally runs the shared countdown-to-expiry + auto-submit + resume-finalize (AC16/17); **untimed** (`== null`) has time-on-task + due-date only, no auto-submit.

### C. Autosave, localStorage mirror & offline resilience (R42)

10. **Debounced autosave + prominent tri-state indicator (Sally S4).** Given `in_progress` + online, When the student pauses (debounced) and `content` is dirty, Then the draft saves via `PUT /progress` (shared `useAttemptAutosave`, 30s dirty-flush; NOT optimistic). The **Saving / Saved / Error** status is shown via the shared **prominent** `SaveStatusIndicator` (`role="status" aria-live="polite"`) — the shell's small header/appbar pill is decorative-only or removed; the prominent indicator is authoritative (AC10 "not a corner chip"). A failed save surfaces **Error** (never a false "Saved"). Autosave deps are stable primitives (FW-4). Pending edits flush on navigate-away/unmount (best-effort beacon) and before submit.
11. **localStorage crash-mirror (R42 a/c).** The draft **write-through mirrors to `localStorage`** (shared mirror, keyed by `submissionId`) **on the same debounce as AC2** (never per-keystroke `JSON.stringify` — Winston BLOCKER 2), recovers on reload/crash (tab closed mid-attempt → last content restored on return), and clears on successful submit. The mirror **seeds BEFORE the first write-through** (5.2b CRITICAL #2 ordering, re-proven at the writing page/shell wiring — Murat F3). If `localStorage` is unavailable, a **one-time non-blocking warning** surfaces. **Known cross-tab limitation (Winston S5, document it):** the mirror is `submissionId`-keyed, not tab-scoped — two tabs editing the same attempt last-write-wins the mirror before any submit; concurrent-editing merge is Out of Scope, but the mirror's cross-tab behavior is documented, not silent.
12. **Offline — never-lose-work (R42 b/d — BLOCKER, Sally B1 + Winston BLOCKER 1).** Given the network drops mid-attempt, When the student keeps typing, Then an **"Offline — changes saved locally"** reassurance appears **as its own visible line/banner** (NOT only a recolored `text-xs` pill — the "saved locally" half is the payload, ~40+ chars in VN; new `useOnlineStatus` over `navigator.onLine` + `window` `online`/`offline`), autosave **pauses**, and the draft holds in `localStorage`. When the connection resumes, Then: (a) a **live `online`-event handler re-reconciles and RESUMES** (the inherited plumbing is load-once — this reconnect path is net-new; the resume must **explicitly flush the mirrored content**, not just un-gate the hook, or a naive `enabled:false` leaves `dirty=false` and nothing saves — Winston S4); (b) **the reconcile pushes the LOCAL (newer) draft up — last-write-wins by the student's own edits** — because after single-tab offline typing the local copy is strictly newer than the server's stale pre-offline autosave. **Server-wins is reserved for a DETECTED FOREIGN change** (a real concurrent writer — the AC13 multi-tab path); it is NOT the default, and it is NEVER a silent dismissible toast over the student's own newer text. (Whole-document server-wins as the default would delete the offline paragraphs the indicator promised were "saved" — the exact ambush this AC forbids.)

### D. Multi-tab coordination (UX-DR19)

13. **BroadcastChannel submit-in-another-tab (Sally S6).** Given the same student opens the attempt in two tabs, When tab 1 submits/finalizes, Then a per-submission **`BroadcastChannel`** (`typeof BroadcastChannel !== 'undefined'` private-mode guarded; keyed `classlite:attempt:<submissionId>`; echo-guarded so the POSTING tab does not flip itself) notifies tab 2, which shows a **blocking "Submitted in another session — view result" overlay** and makes its editor **read-only** — autosave off, submit hidden, **and tab 2 issues ZERO further PUT** (cannot clobber the finalized submission). On the overlay, **move focus to its primary action** ("view result") and announce it (`aria-live`). If tab 2 had **unsaved newer text**, warn plainly that this in-progress draft was **not** included (Sally S6 — the orphaned-tab-2 loss must not be silent). Overlay = the multi-tab case; the AC16 read-only case uses an inline banner (distinct surfaces, chosen deliberately).

### E. Submit, finalization, read-only (shared spine)

14. *(reserved — merged into AC15/16)*
15. **Submit + serialized finalizer (shared).** On Submit, a dialog (desktop) / **slide-up sheet** (mobile s78) confirms **word count (+ under-length warning AC7) + late policy** (late warning + `data.assignment.latePenalty` when `serverNow()` ≥ `deadlineAt`). Confirming runs the shared **serialized finalizer** — supersede in-flight autosave → `await` latest-`saveSeq` flush → `POST /submit` — single-fire `alreadyFinalized` latch, terminal-409-on-flush **falls through to submit** (5.2b CRITICAL #1), no beacon path; a genuinely failed final flush surfaces "couldn't save everything — retry", never a silent lossy submit. Routes to the AC19 confirmation; cancel returns.
16. **Server-anchored timer + read-only, incl. UNTIMED hard-deadline (shared + BLOCKER 3, Winston).** A single `serverNow()` drives time-on-task, due-date, the timed-expiry gate, and the read-only gate — never `Date.now()`, injectable source. Read-only when `submission.status != 'in_progress'` OR `assignment.status == 'closed'` OR `serverNow() >= hardDeadlineAt`. **Crucially, the read-only derivation TICKS off the due-date clock so an UNTIMED attempt flips read-only the moment `hardDeadlineAt` passes mid-session** (the 5.2b-deferred edge — for writing, untimed+due-bound is the NORM, not rare; without this, autosave keeps firing until a PUT 409s and "overdue" is cosmetic). Read-only = textarea **`disabled`** (native — `toBeDisabled()` valid), autosave off, Submit hidden, via an **inline banner**. A racing write **409** flips read-only through the shared error map (`TIME_EXPIRED`/`SUBMISSION_LOCKED`/`SUBMISSION_NOT_EDITABLE`/`413`). **On the flip, move focus to the banner and announce it** (Sally S7 — the textarea disabling under the cursor must not strand a keyboard/SR user). No last-typed text is lost on the flip.
17. **Resume-finalize expired TIMED attempts (shared).** A **timed** attempt loading `in_progress` but past `startedAt + timeBudgetSeconds` immediately runs the AC15 finalizer (idempotent). Visible "submits only while this tab is open" note on timed attempts (FU-5-1-A accepted risk). **Untimed writing has NO auto-finalize** (only the due-date read-only flip, AC16).

### F. States, i18n, a11y, mobile

18. **Mobile writing surface (s78, UX-4; Winston S3 + Sally S2/S3).** Narrow viewports render the purpose-built `MobileWritingSurface` **de-framed to viewport-fluid** (the shipped shell hardcodes `h-[844px] w-[390px] border shadow` — a storybook frame; make it full-bleed). A **sticky bottom word-counter STRIP** (not the shipped floating `pointer-events-none` pill — strip ≠ pill), reconciling the now-empty bottom chrome left by `showToolbar={false}`. **Submit is an always-reachable affordance** (no shell currently has one) with an explicit, non-scrolling placement on both breakpoints (mobile: the bottom bar). Save-status pinned; ≥**44×44 CSS px** touch targets (verify the `size="icon-sm"` back button computes ≥44). Single-tree-per-breakpoint (`useMediaQuery`/`matchMedia`; never both trees in the DOM). **≥16px font on the `<textarea>` element itself** (not just the wrapper — iOS zoom-on-focus checks the input's own computed size — Sally S9).
19. **Submission confirmation end-state (shared).** Post-submit = the shared real confirmation ("submitted and saved ✓ · your teacher will release results" + safe primary action back to `/assignments`), `white-space: pre-wrap`. Not a placeholder. Graded result = 5.5.
20. **Loading / Empty / Error trilogy (UX-1).** Loading = writing-surface-shaped skeleton (not a spinner). "Empty" is N/A (an attempt always has a prompt; the blank textarea + placeholder is the baseline state — note it so the missing empty-state isn't read as an oversight — Sally N4). Load error = inline retry; `404 SUBMISSION_NOT_FOUND` / `403 NOT_ENROLLED` / `403 INSUFFICIENT_ROLE` (route guard) / unknown-terminal 4xx → **non-retryable** body (no retry loop). All copy i18n, no raw HTTP codes.
21. **i18n + a11y.** New `writing.*` strings (+ reused `attempt.*`/`writeDocSurface.*`/`mobileWriting.*`) in **both** `en.json`+`vi.json` (`assertI18nParity`), VN-length-checked on the tightest chrome (save indicator, offline reassurance line, due-date chip, word-count/min, submit sheet, submitted-elsewhere overlay). Route role-gated `['student']`; teacher/owner → 403 (editor **absent** in DOM, TEST-FE-6). `axe` clean on every state (loading/success/error/read-only/**offline**/**submitted-elsewhere**). Keyboard flow tested as a flow: textarea reachable; submit dialog focus-trap + focus-return; **read-only flip + submitted-elsewhere overlay focus moves + announcements** (AC13/16); `aria-live="off"` on the two ticking counters, threshold/deadline-crossing announcements only.

## Story

As a **student actively enrolled in a class**,
I want to **read the assignments set for my classes and open a single attempt payload that carries the exercise questions, passage/audio, and my in-progress answers — with the answer key never present**,
so that **the attempt UIs (quiz 5.2b, writing 5.3, speaking 5.4) can render an attempt end-to-end without a teacher-only endpoint and without ever exposing correct answers to me**.

**Scope:** Backend only. Ships the two student-facing READ endpoints the attempt UIs consume: (1) a student-scoped assignment list (`GET /api/assignments`) so the reserved `/assignments` student nav has data, and (2) an answer-stripped **attempt bundle** (`GET /api/submissions/{id}/attempt`) returning the submission + a student-safe assignment subset + the exercise content with `correctAnswer`/`acceptedVariants` structurally omitted. The write lifecycle (start/resume, save-progress, submit) already shipped in 5.1 and is **not** touched here. The four attempt UIs and the result view (5.5) are separate frontend stories. No grading (Epic 6).

## Acceptance Criteria

### A. Student assignment list (FR-27 read side, enables the `/assignments` nav)

1. **List — student-scoped.** Given a `student` caller, When they GET `/api/assignments` (page+pageSize, XL-2), Then only assignments whose `class_id` is a class the student is **actively enrolled** in (an `enrollments` row `status='active'`) return, each in the `{data, meta}` envelope with `PaginationMeta`. Rows order by `deadline_at ASC` (due-soonest first), stable tiebreak on `id`.
2. **List row shape.** Each row is a `StudentAssignmentListItem`: the student-safe assignment subset (AC7) **plus** `exerciseTitle`, `exerciseSkill` (the `ExerciseSkill` facet), and the caller's own submission summary `submissionId` (nullable) + `submissionStatus` (nullable `SubmissionStatus`; `null` = not started). The join to the caller's submission is a single `LEFT JOIN LATERAL … LIMIT 1` — **not** a per-row `EXISTS`/N+1 (PERF-2).
3. **List role gate.** Given a non-`student` caller (owner/admin/teacher), When they GET `/api/assignments`, Then **403** `INSUFFICIENT_ROLE` — teachers use the existing class-scoped list `GET /api/classes/{classId}/assignments` (5.1). (`GET /api/assignments` is the **student** collection; `POST /api/assignments` on the same path stays teacher/owner/admin create — role-branched by method, D4.)
4. **List isolation.** Given student A enrolled only in class X and student B's class Y in the same center, When A lists, Then A sees only class-X assignments (B's class-Y rows absent); a withdrawn (`status!='active'`) enrollment yields zero rows for that class. Cross-tenant rows never appear (RLS).

### B. Attempt bundle (FR-28/29/30 read payload)

5. **Bundle — owner + enrolled.** Given a `student` caller who **owns** an existing submission (`submission.student_id = caller`) and is **actively enrolled** in the assignment's class, When they GET `/api/submissions/{id}/attempt`, Then **200** with an `AttemptBundle` `{submission, assignment, exercise}` in the standard envelope. The bundle is assembled read-only in a single tenant tx (PERF-1).
6. **Bundle content.** The bundle carries: `submission` = the full `Submission` (5.1 schema: `status, startedAt, timeBudgetSeconds, submittedAt, isLate, appliedPenalty, schemaVersion, content` = the student's own saved answers); `assignment` = the student-safe subset (AC7); `exercise` = the answer-stripped `AttemptExercise` (AC9). The envelope `meta.serverTime` is the timer anchor (client computes remaining from `startedAt + timeBudgetSeconds` vs `serverTime`, never `Date.now()`).
7. **Student-safe assignment subset.** The assignment carried by both AC2 and AC6 is an explicit **whitelist** `StudentAssignmentView`: `{id, exerciseId, classId, status, deadlineAt, hardDeadlineAt, instructions, latePenalty, createdAt, updatedAt}`. It **omits** `centerId` and `createdBy` (internal). Nulls explicit (GO-5), no `omitempty`.
8. **Bundle gates.** Given the caller does **not** own the submission (`student_id != caller`), Then **404** `SUBMISSION_NOT_FOUND` (student-sees-nothing, never 403-that-confirms-existence). Given the owner is **no longer actively enrolled** (withdrawn mid-attempt), Then **403** `NOT_ENROLLED` (re-checked on read — a withdrawn student cannot keep reading content, mirrors 5.1 AC8). Given a non-`student` caller, Then **403** `INSUFFICIENT_ROLE`.
9. **Read is NOT lock-gated (D6).** Given the assignment is `closed` OR `now >= hard_deadline_at`, When the owning enrolled student GETs `/attempt`, Then the bundle **still returns 200** (the student must see their locked draft read-only per UX s64 — `submission.status` + the deadline fields let the FE render read-only; the write locks stay enforced by 5.1's start/progress/submit). `GET /attempt` never returns `SUBMISSION_LOCKED`.

### C. Answer-strip security — BLOCKING (the reason this keystone exists)

10. **Structural omission, not a runtime filter (D1).** `AttemptExercise/AttemptSection/AttemptQuestionGroup/AttemptQuestion` are **distinct OpenAPI + Go response types** that do not declare `correctAnswer` or `acceptedVariants` at all. The mapper `toAttemptExercise` reads `store.ExerciseContent` and constructs the stripped types **field-by-field (whitelist)** — `AttemptQuestion` = `{text, type, options}` only. A future field added to `ExerciseQuestion` is therefore **hidden by default** (never auto-exposed).
11. **No answer key on the wire — every type (D7).** Given an exercise with all five group types (`multiple_choice`, `true_false_not_given`, `fill_in_blank`, `short_answer`, `matching`), When the attempt bundle serializes, Then the response body contains **no `correctAnswer` and no `acceptedVariants` keys** anywhere (asserted by a golden negative test that greps the raw JSON, not just struct assertions). `options` **is** carried (MCQ choices / matching heading bank are student-visible); `text`, section `title`/`content` (passage or audio URL), and group `instructions` are carried.
12. **Skill-agnostic passthrough.** Prompt-only sections (`writing`/`speaking` — empty `questionGroups`) round-trip intact so 5.3/5.4 read the prompt from `section.content`. The mapper does not special-case skill; it strips answers uniformly and preserves section/group ordering.

### D. Multi-tenancy, integrity & no over-build (NFR-6)

13. **RLS isolation — read, both tables.** Given tenants A and B, Then for the list and bundle: a cross-tenant submission/assignment id yields **404** (not another tenant's row); null/unset tenant context = 0 rows; the queries run under `SET LOCAL app.current_tenant_id` in a tx (PERF-1). Reuse the 5.1 `assignments`/`submissions` RLS grid — **no schema change** (this story is read-only; no migration).
14. **No new tables / no mutation / no over-build.** This story ships **no migration**, **no** write path, **no** grading/result fields. It adds only api.yaml read paths + schemas, sqlc **read** queries, a mapper, service read methods, handlers, and routes. The exercise content is read through the existing `store.UnmarshalExerciseContent` ladder (read-transform-only, 4.5/D6); the submission content through `store.UnmarshalSubmissionContent` (5.1). `GET /api/exercises/{id}` and the teacher assignment endpoints are **unchanged** (still owner/admin/teacher-only — students continue to 403 there; this story does not widen them).

### Decisions (pinned at create time; ratify at pre-dev party-mode if run)
- **D1 — Answer strip is STRUCTURAL, not a runtime filter.** New `Attempt*` types omit the answer fields at the type level; the mapper whitelists. A blacklist/`json:"-"` over the existing `ExerciseQuestion` is rejected — it keeps the fields one refactor away from re-leaking and fails the "new field hidden by default" property. **(SEC core; AC10.)**
- **D2 — Attempt bundle is keyed off the submission (`GET /api/submissions/{id}/attempt`), not the assignment.** The submission is the attempt's identity and already carries the ownership + enrollment gate. Flow: student list → `POST /api/submissions {assignmentId}` (5.1 idempotent start/resume, returns the submission) → `GET /api/submissions/{id}/attempt` (render payload). GET stays pure (never creates). Two calls, cache-friendly; noted for the FE (5.2b).
- **D3 — Student-safe assignment subset is an explicit whitelist** (`StudentAssignmentView`), not the full `Assignment`. Omits `centerId`/`createdBy`. `latePenalty` **is** included (the s63 late-warning banner needs it). **(AC7.)**
- **D4 — `GET /api/assignments` is the student collection** (student-only, enrollment-scoped); `POST /api/assignments` on the same path stays teacher/owner/admin create. Method+role branch, no path collision (there is no existing `GET` on the bare collection). Teachers keep `GET /api/classes/{classId}/assignments`. Alternative `/api/assignments/mine` considered and rejected as redundant.
- **D5 — Enrollment re-checked on read** (AC8), mirroring 5.1 AC8's every-write gate: a student withdrawn mid-attempt loses read access to content too.
- **D6 — Read is NOT lock-gated.** `closed`/past-hard-deadline still returns the bundle (200) so the FE renders the locked draft read-only (UX s64). Write locks remain 5.1's job. `GET /attempt` never emits `SUBMISSION_LOCKED`. **(AC9.)**
- **D7 — Golden no-leak test greps the raw JSON body** across all 5 question types (not just struct assertions) — the belt-and-suspenders backstop for D1. **(AC11.)**

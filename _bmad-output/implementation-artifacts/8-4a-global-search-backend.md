## Story

As an authenticated user (owner, admin, teacher, or student), I want a single `GET /api/search?q={query}` endpoint that returns matches grouped by category — Classes, Students, Exercises, Assignments, and Knowledge Hub files — each capped at 5 (with a `hasMore` flag), accent-insensitive (so `"Nguyen"` finds `"Nguyễn"`), and scoped to exactly what my role is allowed to see,
so that a Cmd+K quick-switcher (8-4b) can find any resource fast without me ever seeing another teacher's, another student's, or another center's data (FR-67).

Backend keystone only. This story mints the net-new `/api/search` endpoint + the PROVISIONAL grouped `SearchResults` contract (8-4b co-finalizes), introduces the project's first `pg_trgm` + `unaccent` accent-insensitive trigram matching layer (extensions + an IMMUTABLE-wrapped functional `gin_trgm_ops` index per searched label path), role-branches the scope in-service through a single audited scope-param function over the reused `analyticsTeacherScope` idiom, and proves O(1)-in-rows + index-backed + full cross-tenant/cross-teacher isolation through the reused 8-1a R31 harness + a paired-control 4-role×5-type matrix + the 5-category J15 grid. NO frontend, NO palette, NO Q&A category (deferred FU-8-4-QA, D3), NO k6 load rig (deferred FU-8-4-PERF, D4).

## Acceptance Criteria (BDD)

### A. Endpoint, envelope, query handling & accent-insensitivity (AC ↔ FR-67, D5/D6/D7/D9)

1. **Given** any authenticated, email-verified, center-scoped user, **When** `GET /api/search?q={query}` is called with a `q` of ≥3 trimmed runes, **Then** `200` with `{data: SearchResults, meta}` (GFW-5); `SearchResults` carries `classes`/`students`/`exercises`/`assignments`/`files`, each a `SearchCategory {items: SearchResultItem[] (len ≤5), hasMore: bool}`.
2. **Given** a blank / whitespace-only / <3-rune `q` (or missing `q`), **Then** `200` with every category `{items:[], hasMore:false}` (never null) AND **zero category business queries issued** (short-circuit — the palette polls per keystroke, Murat C2); proven by a paired control (`q="Ab"` with a seeded class `"Ab…"` → the <3 result is empty because of the floor, not missing data), trim (`q="  abc  "` matches `"abc…"`), and rune-not-byte (`q=" é"`→ 1 rune → empty).
3. **Given** a `q` with LIKE metacharacters, **Then** they are escaped (`\` first, then `%`/`_`) before the ILIKE pattern so: a `q` of literal `"a_b"` matches a row `"a_b"` and NOT `"axb"`; a `q` of `"%"` alone does NOT return everything; a `q` ending in `\` returns `200` not `500`; a `q="50\% off"` matches the literal (escape-order correct); and `ORDER BY similarity(..., @q)` binds the RAW `q`, not the escaped pattern (Murat B6).
4. **Given** each populated category, **Then** each `SearchResultItem` carries `{id, type, title, subtitle:null, slug:null, classId:null}` (GO-5 explicit nulls, no `omitempty`, no href); `type` matches its array (`classes[].type=="class"` etc., value-scan asserted); `slug` non-null ONLY for `file`; `classId` non-null ONLY for `assignment`; items ordered `similarity DESC, id` (deterministic). A category with >5 matches returns 5 items + `hasMore:true` via `LIMIT 6` (no extra query); ≤5 → `hasMore:false`.
5. **Given** an accent-differing query (D9), **Then** `q="Nguyen"` matches a student `"Nguyễn Văn A"`, `q="Toan"` matches a class/exercise `"Toán…"`, and `q="Nguyễn"` still matches `"Nguyen"` (both sides unaccented) — accent-insensitive across ALL five categories.

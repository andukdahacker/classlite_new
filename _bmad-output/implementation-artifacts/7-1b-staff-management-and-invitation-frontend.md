## Story

As an Admin or Owner,
I want to see all my center's staff with their workload and status, drill into a staff member's detail, and invite new teachers and admins from a modal,
so that I can manage my center's team over the staff backend shipped in 7-1a.

Frontend slice only. The staff roster read model, aggregates, invite delivery, and the four Owner-only actions were built + tested in **7-1a** and are already generated into `src/lib/api/client.ts`. This story is the **sole consumer** and per D10 **co-finalizes** the provisional wire contract (mirrors 6-4b's contract co-finalization of 6-4a).

## Acceptance Criteria

### A. Route wiring + role gating (s39/s40)

1. **Given** an Owner or Admin clicks "People" in the sidebar, **When** `/people/staff` resolves, **Then** the s39 staff list renders (the previously-dead link now routes) behind `RouteRoleGate allowedRoles={['owner','admin']}`. **And** a Teacher or Student navigating to `/people/staff` or `/people/staff/:id` sees `<PermissionDenied>` with the `people`-section copy (new `app.permissionDenied.section.people.*` key, present in en + vi).
2. **Given** `/people/staff/:userId`, **When** it resolves for an Owner/Admin, **Then** the s40 detail renders; each page is deep-imported (its own chunk).

### B. s39 staff list (list-table + tabs)

3. **Given** the roster loads via `useQuery` → `apiFetch<StaffRoster>('/api/staff')`, **Then** columns render per UX line 464: Name (colored letter tile/avatar + name + mono meta line) · Role pill · Classes (count) · **Load** (`LoadMeter` mini bar + "N/cap") · Status (`StatusPill`) · Last active (mono timestamp via the i18n date formatter, TS-6 — never `new Date().toLocaleString()`).
4. **Given** the tabs, **Then** All / Active / Pending / Archived render with mono client-side counts (`countByStatus` over members + pendingInvites); Active/Archived list `members` filtered by `status`; **Pending lists `pendingInvites` with a dimmed `??` avatar**; default tab = first with count>0.
5. **Given** loading / empty / error (UX-1 trilogy, mandatory), **Then**: loading → row-shaped skeletons (never a centered spinner); empty → an empty-state shell with a role-appropriate headline + the "Invite staff" action; error → an inline `role="alert"` with a retry that calls `refetch` (not a full-page error).
6. **Given** the "Owner excluded (managed in Settings)" rule (7-1a D3/D11), **Then** the roster shows no owner row (the backend already excludes them) **and** a small note communicates it; owners never appear in any tab.
7. **Given** a member row click, **Then** it navigates to `/people/staff/{userId}` (s40). **And** a pending-invite row is non-navigable (no member detail exists yet).

### C. s40 staff detail (tabbed shell + Owner-actions card)

8. **Given** `useQuery` → `apiFetch<StaffMemberDetail>('/api/staff/{userId}')`, **Then** the head (crumb-back + name + `StatusPill` + meta) + a 6-up stat strip + tab-strip render; tabs = Overview / Classes / Schedule / Activity, body swapped per tab (URL-addressable or local — match the `/classes/:id` precedent). The trilogy (loading/empty/error) applies; a 404 `STAFF_NOT_FOUND` renders a not-found state (not a crash).
9. **Given** the tab bodies, **Then** Overview shows profile (name/email/avatar/`languagePref`) + role + `LoadMeter` (`load.heavy` → amber) + `lastActiveAt` ("—"/"never" when null); Classes lists `assignedClasses[]`; Schedule lists `scheduleGlance[]` (className + start/end via the i18n date formatter); Activity lists `recentActivity[]` (event + entityType + `at`), each with its own empty state.
10. **Given** an **Owner** on s40, **Then** a dashed "Owner actions" card shows: Assign to class · Reset password · Archive · Force-logout (D7). **Given** an **Admin** on s40, **Then** the detail renders read-only and the Owner-actions card is **absent from the DOM** (TEST-FE-6 negative — assert `queryByTestId('owner-actions')` is null, not merely hidden).

### D. Owner-only action wiring

11. **Given** the Owner clicks **Assign to class**, **Then** a class-picker dialog (populated from the shipped classes list) submits `POST /api/staff/{userId}/assign-class { classId }`; on 200 `AssignClassResult` invalidate `staffDetail` + `staffList` and toast success; 404 `CLASS_NOT_FOUND`/`STAFF_NOT_FOUND` → error surface (D13).
12. **Given** the Owner clicks **Archive**, **Then** a confirm dialog warns "still owns N classes" when `assignedClasses.length>0` (D14/D17c); on confirm `POST …/archive` → `ArchiveStaffResult`; success invalidates list+detail and toasts; 409 `CANNOT_ARCHIVE_SELF` and 409 `STAFF_ALREADY_ARCHIVED` map to distinct copy.
13. **Given** the Owner clicks **Reset password**, **Then** a confirm → `POST …/reset-password` → 204 → toast "reset email sent" (D15).
14. **Given** the Owner clicks **Force-logout**, **Then** a confirm → `POST /api/admin/users/{userId}/force-logout` → `{ forcedLogout, sessionsRevoked }` → toast "N sessions revoked" (reuse the shipped endpoint; no new backend, D15).
15. **Given** any Owner action fires while another is in flight, **Then** the triggering control is disabled during `isPending` (no double-submit); optimistic patches, if used, follow the FW-2 triple (cancel → snapshot → rollback → invalidate).

### E. s41 invite modal

16. **Given** the "Invite staff" CTA (or a `?invite=new` deep-link), **Then** a shadcn Dialog opens with RHF + `zodResolver` fields (D11): email (required, "recipient sets own password" helper) · name (optional) · role (`RoleChipGroup`) · classId (optional, teacher-role only) · welcomeNote (optional) · footer "Invite expires in 7 days."
17. **Given** submit, **Then** `POST /api/centers/{centerId}/invites` is called with `{ email, role, name?, classId?, welcomeNote? }` — `classId` sent **only** when role=teacher (D7); `centerId` read from the session cache. On 201 `InviteResult` close the modal, invalidate `staffList` (the invitee appears under Pending), and toast success.
18. **Given** invite errors, **Then** they map to i18n copy: 409 `INVITE_EMAIL_TAKEN` → `people.invite.error.emailTaken` (field=email, stub exists); 403 `ROLE_ASSIGNMENT_FORBIDDEN` → `people.invite.error.roleAssignmentForbidden` (stub exists); 422 `VALIDATION_ERROR` / 404 `CLASS_NOT_FOUND` → field/form errors. All new copy added to en + vi.
19. **Given** FR-11 (D12 RULED), **Then** the role toggle offers Teacher / Admin ONLY for both Owner and Admin senders — no Owner chip is rendered for anyone (Owner-invite deferred to Settings). A test asserts the toggle has exactly two options and no `owner` option is in the DOM for either sender role.

### F. i18n, contract co-finalization, tests

20. **Given** UX-2, **Then** every new string exists in BOTH `en.json` and `vi.json` under `people.staff.*` / `people.invite.*` (flat dotted keys); the i18n-parity test passes; no hardcoded English in components; dates via the i18n formatter (TS-6).

22. **Given** the test rules, **Then**: the roster + detail pages have the three-state trilogy tests (TEST-FE-1/2, MSW at the HTTP boundary — never mock `useQuery`); **TEST-FE-6 negative-render — an Admin's s40 has NO Owner-actions card in the DOM, and a Teacher/Student is denied both routes**; the invite modal has RHF validation + error-mapping tests + axe (TEST-FE-5); i18n key-existence asserted for en + vi (TEST-FE-4).

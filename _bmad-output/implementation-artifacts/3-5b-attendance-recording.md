## Story

As a Teacher,
I want to record each enrolled student's attendance (Present / Late / Absent) on the session detail page, with bulk "Mark all" and apply-to-selected shortcuts,
so that I can track participation per session — and so the center's at-risk detection and student performance views (Story 7.2) have real attendance data to compute from.

This story **restores the attendance slice deliberately carved out of the DONE Story 3-5** (FU-3-5-A in `deferred-work.md`). Story 3-5 shipped the s12 session detail page (info / materials / exercises / notes / actions) and left attendance as a dormant amber `AttendancePlaceholder`. 3.5b builds the `attendance` table + roster read + Present/Late/Absent recording + bulk actions and swaps the placeholder for a live section. The **ended-session Inbox reminder stays deferred** (FU-3-5-B → Epic 10 — no Inbox/notification surface exists yet).

## Decisions (D1–D10 — D1/D2 are Ducdo/scoping rulings 2026-09-03; the rest are SPEC grounded in recon)

- **D1 — Re-sequenced AHEAD of Story 7.2 (Ducdo ruling 2026-09-03).** 7.2 (Student Lists & Detail) depends on attendance for its at-risk **"attendance <70%"** signal and the s10 **"attendance rate %"** stat, but the `attendance` table does not exist (it was carved out of the done 3-5). Asked to choose how 7.2 handles the gap, **Ducdo ruled "pull 3.5b forward first"** — build attendance to completion before 7.2 is created. Consequence: this story is created + implemented now; the `7-2` sprint key stays `backlog` (re-keyed to `7-2a`/`7-2b` when its create-story runs, after this ships). Sequence: **3.4.5 (done) → 2.7 (done) → 3.5b (this) → 7.2**.
- **D2 — Single full-stack story, NOT a backend/frontend split.** The repo splits L keystones (7.1→7-1a/b, 6.x, 5.x) because their backends are net-new read models. Here the roster spine (3.4.5 `enrollments` + `ListEnrolledStudentsByClass`) and the entire backend pattern (3.5 `SessionContentService`/`session_content_handler.go`/`session_content.sql` + the `sessionChain` route wiring) and the s12 page already ship. 3.5b adds **one** table, session-scoped CRUD that mirrors session-content verbatim, and swaps **one** dormant component. It is a contained M vertical slice — build backend + frontend in one story.
- **D3 — `attendance` table + UPSERT semantics.** New tenant table `attendance`: `id uuid pk`, `center_id uuid NOT NULL → centers ON DELETE CASCADE`, `session_id uuid NOT NULL → sessions ON DELETE CASCADE`, `student_id uuid NOT NULL → users`, `status text NOT NULL CHECK (status IN ('present','late','absent'))`, `marked_by uuid NOT NULL → users`, `created_at`, `updated_at`. **`UNIQUE (session_id, student_id)`** → exactly one attendance row per student per session; recording is an **UPSERT** (`INSERT … ON CONFLICT (session_id, student_id) DO UPDATE SET status, marked_by, updated_at`). Standard **4-policy tenant RLS grid** on `center_id` (`USING (center_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid)`), mirroring `sessions`/`enrollments`. Index `idx_attendance_center_session ON attendance (center_id, session_id)`. `session_id` is `ON DELETE CASCADE` (attendance has no history value once the session is gone — unlike `sessions.class_id RESTRICT`). New migration timestamp **> `20260828120200`** (use `20260903120000`).
- **D4 — Roster = the session's class's ACTIVE enrollments, LEFT-JOINed to recorded attendance.** The read returns every active-enrolled student of `session.class_id` with their status **or null** (unmarked). New query `ListAttendanceRosterBySession` (`attendance.sql`): `enrollments e JOIN users u ON u.id = e.student_id LEFT JOIN attendance a ON a.session_id = @session_id AND a.student_id = e.student_id WHERE e.class_id = @class_id AND e.status = 'active' ORDER BY u.full_name ASC`. Derive `class_id` from the session inside the same tx (`GetSessionByID`) — never trust a client-supplied class_id. Unmarked students (no `attendance` row) surface with `status: null` so the UI shows an empty toggle.
- **D5 — Three session-scoped, teacher-facing endpoints, reusing the SessionContent chain + IN-SERVICE authz (CORRECTED at party-mode, Amelia).** (a) `GET /api/sessions/{id}/attendance` → `{ data: { roster: AttendanceRosterEntry[] } }` where each entry = `{ studentId, name, email, status /* 'present'|'late'|'absent'|null */, markedAt /* nullable */ }`. (b) `PUT /api/sessions/{id}/attendance/{studentId}` body `{ status }` → upsert one → returns the updated entry. (c) `POST /api/sessions/{id}/attendance/bulk` body `{ status, studentIds?: string[] }` → upsert many (see D6) → returns the full refreshed roster. All three register on `mux.Handle` with the **same `sessionChain`** the session-content routes use (`cmd/api/main.go:560-567`). **CORRECTION:** `sessionChain` is `extractTenant(requireVerified(requireCenter(...)))` — it has **NO `RequireRole`**. Role/teacher gating is entirely **in-service** via `authorizeSession` → `assertClassRole` (`class_lifecycle.go:85`, allows owner/admin/teacher — a **student** hits `ForbiddenError` → 403) → `assertSessionTeacherScope` (`session.go:134`, a teacher-not-of-this-class gets `sessionNotFound` → **404**, per the "teacher-sees-nothing, never 403" convention). Do NOT invent a chain allowlist. Attendance is an `AttendanceService` + `AttendanceHandler` pair modeled 1:1 on `SessionContentService`/`SessionContentHandler` (reuse `readInTenantTx`/`mutateInTenantTx`/`authorizeSession` shapes; do NOT fold into session-content — keep a clean file per concern, CQ-4).
- **D6 — Bulk = one atomic transactional upsert set (apply-to-selected CUT from v1, Ducdo 2026-09-03).** The bulk endpoint serves **"Mark all Present"** and **"Mark all Absent"** only. `studentIds` **omitted/empty** → apply `status` to **all active-enrolled** students of the session's class (resolve the roster in-tx, then upsert each). The `studentIds`-present (apply-to-selected) path is **cut from v1** (D12) — the endpoint still ACCEPTS an optional `studentIds` for forward-compat and MUST validate it (every id an active enrollment else **422 `NOT_ENROLLED`**, whole batch rejected before any write), but the FE ships no multi-select UI. The entire batch commits in one tx (all-or-nothing): **validate ALL ids against the in-tx roster BEFORE the first upsert — never upsert-then-check.**
- **D7 — Pagination DEFERRED to Story 7.2 (CR-3-4-5-3).** A per-session roster is single-class and bounded; returning the full active roster with no `LIMIT`/`OFFSET` is v1-acceptable here — identical rationale to the CR-3-5-1 session-content-list deferral. The genuinely unbounded consumer is **7.2's center-wide / teacher roster**, which owns adding `page`/`pageSize` + `{data,meta}` per CR-3-4-5-3. Do NOT speculatively paginate the class roster in 3.5b; state the deferral so 7.2 picks it up.
- **D8 — Ended-session Inbox reminder STAYS deferred (FU-3-5-B → Epic 10).** The epic-03 Story 3.5 AC "when an ended session is unmarked, generate an Inbox prompt" needs the Inbox surface + notification pipeline that only Epic 10 builds (no `jobs`/notifications table, `event.bus` unwired, no Inbox route). Explicitly OUT OF SCOPE for 3.5b — restore alongside Epic 10.
- **D9 — Frontend: swap `AttendancePlaceholder` → live `AttendanceSection` at the TOP of the s12 main column (Ducdo 2026-09-03).** Replace the placeholder mounted at `SessionDetailPage.tsx:90` (currently in the right `<aside>`). The live `AttendanceSection` moves to the **top of the main column, ABOVE Materials/Exercises/Notes** — attendance is the only time-boxed, end-of-session task on s12; burying it under three content sections (or cramping it in a 300px rail) strands the teacher (Sally). This is a deliberate reversal of 3.5's "attendance-last/in-rail" placeholder choice; the UX spec (line 479) already lists attendance first. The actions card stays in the rail. Net-new domain components: **`AttendanceToggle`** (Present/Late/Absent segmented control per row — green/amber/red, `aria-pressed`, keyboard-operable) and **`RosterTable`** (participants + attendance, a specialization of the list-table shell), both first-seen s12 per component-inventory. A **marked-count summary line** ("`{marked}/{total} marked · {present} present · {late} late · {absent} absent`") sits at the section head so the teacher can verify the reconciliation at a glance (Sally — the single cheapest high-value add). The **unmarked state (`status: null`) must be VISUALLY LOUD and distinct** from a selected segment — the teacher's real question is "who haven't I gotten to yet," so an untouched row reads unmistakably (not a subtly-empty toggle). Reads via a new `useSessionAttendance(sessionId)` query; writes via optimistic mutations. i18n: reuse the `session.attendance.*` namespace (note: locale keys are **FLAT dot-strings**, e.g. `session.attendance.title` at en/vi:1388–89 — new keys go in flat, not as a nested object) — add `.status.{present,late,absent}`, `.summary`, `.markAllPresent`, `.markAllAbsent`, `.undo`, `.markAllAbsentUndone`, `.empty.owner`, `.empty.teacher`, `.saved`, `.bulkError`, `.rowError` in **both** en.json + vi.json. Remove `.comingSoon` (placeholder deleted). Mobile (UX-4, D13): the three-segment toggle + a full name column does not fit beside ~1.4×-wider Vietnamese labels (Có mặt / Đi trễ / Vắng mặt) at 360px — the segments render **icon + accessible-label** (not text-only) at narrow widths, 44×44 touch min; bulk buttons wrap gracefully in VI.
- **D10 — On-row audit trail, no `audit_logs` spam, no history ledger (v1).** `marked_by` + `updated_at` on the attendance row ARE the audit trail (who last set it, when). Attendance is high-frequency (a class × many sessions) — do NOT write an `audit_logs` row per mark (it would drown the staff/student activity feeds 7-1a/7.2 read). **Accepted v1 limitation:** this stores *current* state, not *history* — a dispute ("I was marked absent, then it changed") has no trail. If a change-history requirement appears, revisit with an append-only ledger; for v1 the current-row + `updated_at` is the record. `marked_by` FK → `users` is **`ON DELETE RESTRICT`** (a deleted teacher must not orphan/cascade attendance rows), `NOT NULL`.
- **D11 — Attendance is WRITE-ONCE-EDITABLE — no un-mark / clear path (Ducdo 2026-09-03).** A teacher can change a student between `present`/`late`/`absent`, but there is **no path back to `null`** (unmarked). The store is INSERT + UPDATE only — **no DELETE endpoint, no "clear" affordance**. A mis-tap is corrected by re-tapping to the right status, not by clearing. The toggle is designed forgiving (large targets, instant re-select) so mis-taps are cheap to correct; accept that "accidentally marked" cannot be undone to "not marked." (Considered a 4th "clear" affordance/DELETE; ruled out for v1 simplicity.)
- **D12 — "Mark all Absent" gets an UNDO toast; apply-to-selected CUT (Ducdo 2026-09-03).** The two bulk directions are NOT symmetric: "Mark all Present" is the benign happy path; **"Mark all Absent" can atomically overwrite a hand-marked roster** (D6 all-or-nothing) and is destructive. Guard it with an **optimistic-apply + UNDO toast** ("All marked absent · Undo", ~5s) — fast for the happy path, reversible for the accident — NOT a blocking confirm dialog. Undo re-issues the prior per-row states (snapshot before the bulk). **Apply-to-selected (multi-select → status) is cut from v1** — for the common "all present, flip the 2 absentees" case, mark-all + 2 taps is fewer gestures, and the feature was under-specified (no selection affordance) and mobile-hostile. The bulk endpoint keeps the optional `studentIds` param (D6) for forward-compat; the FE ships no multi-select.
- **D13 — Atomic-bulk failure = ONE banner, per-row single-tap = quiet inline tick (Sally).** Single-tap optimistic writes show a quiet inline "saved" tick — NOT a toast per tap (30 rapid taps must not spawn 30 toasts). A **bulk** failure is different: D6 is all-or-nothing, so the FE optimistically flipped the whole roster and must snap **all rows back at once** → show ONE clear banner ("Couldn't save attendance — nothing was changed, try again"), not N row-level whispers. Design the broken promise explicitly.

## Acceptance Criteria (BDD)

### A. `attendance` table & RLS (migration)

1. **Given** migrations run, **When** the DB is inspected, **Then** an `attendance` table exists with `id, center_id, session_id, student_id, status ('present'|'late'|'absent' CHECK), marked_by, created_at, updated_at`, a `UNIQUE (session_id, student_id)` constraint, and `idx_attendance_center_session (center_id, session_id)`. **And** `session_id` FK is `ON DELETE CASCADE`, `center_id` FK is `ON DELETE CASCADE`, **`marked_by` FK → `users` is `ON DELETE RESTRICT` + `NOT NULL`** (D10 — a deleted teacher must not orphan/cascade attendance).
2. **Given** the 4-policy tenant RLS grid on `attendance`, **When** Tenant A reads/writes with its GUC set, **Then** it sees/writes only its own `center_id` rows. **[RLS read isolation]** A cross-tenant `SELECT` returns 0 rows; **[RLS write isolation]** a cross-tenant `UPDATE`/`INSERT` targeting Tenant B's session affects 0 rows / is rejected — adversarial test per TEST-BE-1 (both directions, deterministic tenant IDs, never `DISABLE ROW LEVEL SECURITY`).
3. **Given** the down migration, **When** it runs, **Then** it exactly reverses the up (drops index, table) — WF-2 rollback safety.

### B. Roster read — `GET /api/sessions/{id}/attendance`

4. **Given** a Teacher (of the session's class) or Admin/Owner calling `GET /api/sessions/{id}/attendance`, **When** it runs, **Then** it returns `{ data: { roster: [{ studentId, name, email, status, markedAt }] } }` — one entry per **active** enrollment of the session's class, `ORDER BY name`, with `status`/`markedAt` = `null` for students not yet marked (D4). **And** the class_id is derived from the session in-tx, never from the request.
5. **Given** a session whose class has no active enrollments, **Then** `roster` is `[]` (empty, not an error) — the FE renders a **role-aware** UX-1 empty state (D9): Owner/Admin see an actionable enrolment link; a Teacher (who cannot self-enroll — enrolment is s43 Admin/Owner-only) sees "No students enrolled yet — ask your center admin to add them" (no dead-end CTA).
5b. **Given** a session with `status = 'cancelled'` (D14), **When** any attendance endpoint is called, **Then** it behaves exactly as for a `scheduled` session — attendance is recordable on cancelled (and past) sessions, mirroring the session-content sibling precedent (`main.go:557` — content is addable on past/cancelled). No `status`-based guard, no now-floor.

### C. Single set — `PUT /api/sessions/{id}/attendance/{studentId}`

6. **Given** a Teacher-of-class / Admin / Owner calling `PUT …/attendance/{studentId}` with `{ status: 'present'|'late'|'absent' }` for an active-enrolled student, **When** first called, **Then** an `attendance` row is INSERTed (`marked_by` = caller); **When** called again for the same `(session, student)`, **Then** the row is UPDATEd (status + `marked_by` + `updated_at`), never duplicated (UPSERT on `UNIQUE (session_id, student_id)`). The response is the updated `AttendanceRosterEntry`.
7. **Given** a `studentId` that is NOT an active enrollment of the session's class, **Then** 422 `NOT_ENROLLED` (no row written). **Given** an invalid `status`, **Then** 422 `VALIDATION_ERROR`.

### D. Bulk mark — `POST /api/sessions/{id}/attendance/bulk`

8. **Given** a body `{ status: 'present' }` with **no** `studentIds`, **When** posted, **Then** every active-enrolled student of the session's class is upserted to `present` in **one transaction**, and the full refreshed roster is returned ("Mark all Present"; same for `'absent'`).
9. **Given** a body `{ status, studentIds: [...] }` (the forward-compat path — no v1 FE surfaces it, D12), **When** every id is an active enrollment, **Then** only those students are upserted, atomically. **[MANDATED atomicity proof]** **Given** `studentIds = [valid_1, …, valid_{N-1}, BAD_id]` with the invalid id **positioned LAST**, **When** posted, **Then** 422 `NOT_ENROLLED` **and** `SELECT count(*) FROM attendance WHERE session_id = X` is unchanged (0 new rows) — proving validate-all-before-write, not upsert-then-check (D6). Real-DB integration test, NOT the mock seam (a mock cannot witness a rollback). Add a bad-id-in-the-middle variant too.

### E. Authorization & scoping

10. **[CORRECTED at party-mode — the story previously mis-stated this against the reused code.]** **Given** a Teacher who is NOT the teacher of the session's class calling any attendance endpoint, **Then** **404 `SESSION_NOT_FOUND`** — via `assertSessionTeacherScope` (`session.go:134`) which returns `sessionNotFound` (the "teacher-sees-nothing, never 403" convention), owner/admin bypass. **Given** a Student calling any attendance endpoint, **Then** **403 `INSUFFICIENT_ROLE`** — via the in-service `assertClassRole` (`class_lifecycle.go:85`), **NOT** a `sessionChain` allowlist (`sessionChain` has no `RequireRole`; the role gate is entirely in-service, D5). Verify `ForbiddenError{Reason:"insufficient role"}` maps to code `INSUFFICIENT_ROLE` (not `FORBIDDEN`).
11. **Given** every attendance DB access, **Then** it runs inside a `SetTenantContext` transaction (PERF-1) with the tenant GUC set — reads included.

### F. Frontend — live `AttendanceSection` on s12

12. **Given** the s12 SessionDetailPage renders, **When** the attendance section mounts, **Then** the dormant `AttendancePlaceholder` is GONE and a live `AttendanceSection` renders at the **top of the main column** (above Materials/Exercises/Notes, D9) via `useSessionAttendance(sessionId)` with a per-row `AttendanceToggle` (Present/Late/Absent, green/amber/red, `aria-pressed`, keyboard-operable). **And** an **unmarked row (`status: null`) is visually LOUD/distinct** from a selected segment (D9). **And** a **marked-count summary** ("`{marked}/{total} marked · {present}/{late}/{absent}`") renders at the section head. Implements the UX-1 trilogy: skeleton loading, **role-aware** empty state (AC5), retry-able error alert (all i18n, both locales). The placeholder test assertion (`session-attendance-placeholder`) is replaced by a live-roster assertion.
13. **Given** the teacher taps a student's toggle, **When** clicked, **Then** an optimistic mutation fires the full FW-2 triple (cancel → snapshot → set → rollback onError → invalidate onSettled) against `PUT …/attendance/{studentId}`, with a **quiet inline "saved" tick — NOT a toast per tap** (30 rapid taps must not spawn 30 toasts, D13). **And** the toggle offers **no un-mark/clear affordance** — a student can only move between present/late/absent, never back to null (write-once-editable, D11).
14. **Given** "Mark all Present" / "Mark all Absent" (the only bulk controls — apply-to-selected is cut, D12), **When** the teacher clicks one, **Then** it calls `POST …/attendance/bulk`; **and** "Mark all Absent" (destructive) applies optimistically then shows an **UNDO toast** ("All marked absent · Undo", ~5s) that restores the pre-bulk per-row snapshot (D12). **[Bulk failure]** If a bulk write fails, the whole optimistic roster snaps back and **ONE banner** ("Couldn't save — nothing was changed, try again") shows, not N row-level errors (D13). **[Negative]** A non-owning teacher / student sees no attendance write controls — assert absent from DOM per TEST-FE-6 (the real negative case is the non-owning teacher, whose API path 404s but whose FE must still not render write controls).
15. **Given** i18n, **When** the section renders in `en` and `vi`, **Then** all attendance strings resolve from the flat `session.attendance.*` keys in both locales (TEST-FE-4 / UX-2 co-primary), with no hardcoded English; the Vietnamese three-segment toggle fits at 360px via icon+label rendering (D9/UX-4).

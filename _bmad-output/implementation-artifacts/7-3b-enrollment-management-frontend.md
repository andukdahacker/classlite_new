## Story

As an Admin or Owner,
I want a `/people/enrolment` console where I can add, transfer, and withdraw students between classes, see which students/classes need attention, and read the complete immutable enrollment history,
so that student placement is controlled, every change is traceable, and I can act on gaps — over the enrollment backend shipped in 7-3a.

Frontend slice only. The Add/Transfer/Withdraw state machine, the immutable `enrollment_history`, the enrollable/self-transfer/future-date guards, the best-effort notify email, the `event.EnrollmentChanged` publish, and the two read APIs (`/history`, `/attention`) were built + tested in **7-3a** and are already generated into `src/lib/api/client.ts` as a **STABLE** contract (no PROVISIONAL markers — verified 2026-09-09). This story is the **sole consumer**: no `api.yaml` change, no `codegen.sh` run, no Go change (D13).

## Acceptance Criteria

### A. Route + role gate + NEW sidebar entry (s43)

1. **Given** an Owner or Admin, **When** `/people/enrolment` resolves, **Then** the `EnrolmentPage` renders behind `RouteRoleGate allowedRoles={['owner','admin']}` (deep-imported named export → own chunk); **And** a Teacher or Student navigating there sees `<PermissionDenied>` with owner/admin-worded copy from the NEW `app.permissionDenied.section.enrolment.header` (`sectionNameKey="enrolment"`), NOT the console.
2. **Given** the sidebar, **When** an Owner or an Admin renders it, **Then** a NEW "Enrolment" item appears under the People group (`sidebar.owner.enrolment` / `sidebar.admin.enrolment`, an `ArrowLeftRight`/`Repeat` icon, `href='/people/enrolment'`); **And** it is absent for Teacher and Student sidebars (TEST-FE-6 — assert absent from the DOM, not merely hidden).

### B. Compose row — Add / Transfer / Withdraw (compose-row workspace, §6.5)

3. **Given** the compose row, **Then** it renders: a searchable **student** combobox (D9), an **Add/Transfer/Withdraw** `ToggleGroup` (single-select, default `Add`), a **target-class** picker (Add/Transfer), an **effective-date** `<Input type="date">` (default today, `max` today — D10), an optional **note** `<Textarea>` (labelled teacher-only per the epic), and a **Submit** button. RHF + `zodResolver` (D6); Submit disabled until the current action's schema validates and while `isPending`.
4. **Given** the action toggle, **Then** the visible/required fields switch per action: **Add** → target-class only; **Transfer** → source (read-only or picker per D8) + target-class; **Withdraw** → source only (no target). Switching action re-validates (no stale required-field errors).
5. **Given** a student is selected with `activeEnrollmentCount===0` (unassigned), **Then** Transfer and Withdraw are disabled with an inline hint (only Add applies); **Given** the student has exactly 1 active class, **Then** the source class is auto-selected + shown read-only for Transfer/Withdraw; **Given** >1 active class, **Then** a source-class picker is shown (D8).
6. **Given** a valid Add/Transfer/Withdraw submit, **When** `POST /api/enrollments` succeeds (201 add / 200 transfer·withdraw), **Then** `useEnrolmentAction` fires the `EnrollmentActionRequest` with an explicit `action` (+ `toClassId`/`fromClassId`, never the legacy `classId` alias); on success the history + needs-attention + student roster + classes caches invalidate (D7), an action-specific success toast shows, and the composer resets.
7. **Given** a server rejection, **Then** the mapped error surfaces as an i18n toast: `CLASS_NOT_ENROLLABLE`/`NOT_ENROLLED_IN_SOURCE`/`NOT_A_STUDENT_MEMBER`/`VALIDATION_ERROR` (422), `ALREADY_ENROLLED` (409), `CLASS_NOT_FOUND` (404), `INSUFFICIENT_ROLE` (403) — via `ApiError.code`, never a raw HTTP code or English string (CQ-5/UX-1). The client self-transfer guard (D6 refine) blocks `fromClassId===toClassId` **before** submit (mirrors the server 422).

### C. Needs-attention list (two zones, §6.5)

8. **Given** `useQuery` → `apiFetch<NeedsAttention>('/api/enrollments/attention')`, **Then** two zones render: **unassigned** students (amber left-border, name + email) and **over-capacity** classes (red left-border, className + mono `activeCount/capacity` badge); each zone independently paginated off its nested `pagination` (D11).
9. **Given** an unassigned-student row, **When** its "Add" affordance is clicked, **Then** the composer prefills that student with `action='add'` and focuses the target-class picker (no submit — the Admin still picks the class).
10. **Given** the over-capacity zone, **Then** it is informational only (no enrollment is blocked from the console — 7-3a surfaces, does not enforce). **And** each zone shows the UX-1 trilogy: row/skeleton loading, a role-appropriate empty state ("nothing needs attention"), and an inline `role="alert"` retry on error.

### D. Immutable history table (audit trail, action pills)

11. **Given** `useQuery` → `apiFetchWithMeta<EnrollmentHistoryEntry[], EnvelopeMetaPagination>('/api/enrollments/history')`, **Then** a raw `<table>` renders newest-first with columns When · Student · Action (`Badge` pill per action) · From (`fromClassName` ?? "—") · To (`toClassName` ?? "—") · Effective · By (`performerName` **?? "System"**) · Note (D12); dates via the i18n formatter (TS-6); a null performer renders "System" (genesis rows).
12. **Given** `meta.pagination.total > pageSize`, **Then** a pager renders and drives `?page`; **And** the optional class filter (`?class_id`) and student filter (`?student_id`) issue server-side reads and are clearable (never client-only filtering that breaks the pager).
13. **Given** loading / empty / error, **Then** the table shows row-shaped skeletons / an "no enrollment actions yet" empty state / an inline `role="alert"` retry (UX-1, mandatory).

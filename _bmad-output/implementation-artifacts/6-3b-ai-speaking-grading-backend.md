## Story

As a **Teacher**,
I want **the backend to run AI over a Speaking submission on demand — deduct a credit, transcode + send the audio recording + IELTS Speaking rubric to Gemini, auto-transcribe, and return proposed band scores (rationale + confidence) plus timestamp-pinned "moments" (hesitations, errors, strong delivery) as reviewable *suggestions*** ,
so that **the s24 speaking-grading UI (6-3c) can let me review AI suggestions against the waveform and grade faster — while I remain the one who commits the final grade.**

**Scope:** The backend AI speaking-grade pipeline, riding the **4.3a async spine**, the **6-3a speaking domain** (criterion set, `TimestampedComment`, `NormalizeTimestampComments`, `SpeakingDurationMsFromContent`, audio-key content), and the **6-3b0 transcoder** (webm/mp4 → `audio/ogg`). New: the `ai_grade_speaking` job type + params; the **additive Gemini client audio extension** (inline audio part); the `GradeSpeakingHandler` that downloads the audio from R2 (SEC-8), **transcodes it (6-3b0) to a Gemini-ingestible ogg**, calls Gemini, validates + normalizes, and stores **suggestions in `job.result`** (never a `grades` row); the **`partial_success`** outcome (transcription failed but bands proposed → credit **NOT** refunded — a *complete* job); skill-branching the 6-2a enqueue so `POST …/ai-grade` mints `ai_grade_speaking`; automatic refund-on-terminal-failure; and the latest speaking suggestion surfaced through the teacher grading-read. Poll reuses `GET /api/jobs/{jobId}` **unchanged**.

**Explicitly NOT in this story:** the audio transcode capability + ffmpeg/image change (→ **6-3b0**, prerequisite keystone); any frontend (→ **6-3c**: transcript panel, "View transcript", timestamped AI moments on the timeline rail, per-moment Accept/Edit/Dismiss, confidence badges, the `partial_success` "Transcript unavailable — bands proposed below" copy); the grade write (shipped — 6-3a); the additive `transcriptRef` on the committed grade (6-3c); the 402 insufficient-credit gate (6.5). See **Out of Scope**.

## Decisions (D1–D10 from context recon; D11–D16 folded from party-mode 2026-08-23; D17 folded from party-mode re-review 2026-08-24 after 6-3b0 shipped — all spec, not suggestion)

- **D1 — The AI worker produces SUGGESTIONS, never a grade (inherited 6-2a D1).** No grade-write, no submissions UPDATE. Result → `job.result` as `AISpeakingGradeResult`. The teacher commits via the shipped 6-3a `POST …/grade` speaking branch (re-validates via `ValidateSpeakingCriterionScores`, re-normalizes via `NormalizeTimestampComments`, computes the authoritative overall via `OverallBandFromFour`). The worker never writes the submission → cannot trip the immutability trigger (R16, discharged 6.1).

- **D2 — Gemini AUDIO input: extend the client additively AND transcode first (revised by party-mode).** Two moving parts: (1) **Transcode is mandatory** — Gemini inline audio accepts only wav/mp3/aiff/aac/ogg/flac and **rejects the webm/mp4** our recorder produces (verified [ai.google.dev/gemini-api/docs/audio](https://ai.google.dev/gemini-api/docs/audio)); the worker calls **`media.Transcode` (6-3b0)** on the downloaded bytes → `audio/ogg` (voice-Opus, small) BEFORE Gemini. (2) **Extend `gemini.Client`** with additive `GenerateRequest.AudioData []byte` + `AudioMimeType string`, and model an `inlineData` alternative on `geminiPart`. **Wire traps (Winston, verified):** `geminiPart.Text` (`client.go:76-78`) has **no `omitempty`** → an audio part would marshal `"text":""` alongside `inlineData` → malformed/400; add `omitempty` (or emit distinct text-only vs audio-only parts). The `AudioMimeType` is the **transcoder's output MIME (`audio/ogg`)** — NOT derived from the R2 key extension. Base64 inflates bytes ×1.33, but because 6-3b0 re-encodes to voice-Opus the transcoded payload is small (a 20-min mock ~3–5 MB → base64 well under Gemini's 20 MB inline cap), so the Files API is unnecessary for v1; keep a defensive `maxInlineAudioBytes` guard on the **transcoded** bytes. The shared `http.Client{Timeout:60s}` (`client.go:59`) is text-tuned — use a **longer per-request timeout for the audio path**, don't bump the global that authoring/writing share.

- **D3 — `partial_success` is a `nil`-error SUCCESS carrying a flag in `job.result` — NEVER a terminal fail (RATIFIED credit model, D15).** The dispatcher refunds **only** in `terminalFail` (`dispatcher.go:211-234`); success (`MarkJobComplete`) never refunds and nulls `error_details`. The worker returns `(result, nil)` for partial_success, encoding `transcriptionStatus ∈ {available, unavailable}` (+ `transcript: string|null`) in the result. **Seam invariant:** bands are REQUIRED for any `complete` result; the transcript is OPTIONAL. Detection: parseable JSON with all four valid+on-grid bands + confidence → `complete`; transcript present → `available`; transcript null/empty → `unavailable` (partial_success, no refund). **Bands absent/invalid → terminal (refund), NOT partial.**

  | **transcode: corrupt/undecodable clip / deadline blown / empty/over-cap output (6-3b0 `media.ErrTranscodeFailed`)** | terminal | ✅ | `audio_unavailable` — Gemini never called |
  | **transcode: TRANSIENT infra — ffmpeg start-fail / OOM-signal-kill / disk-full / parent-ctx cancel / output-read I/O (6-3b0 `media.ErrTranscodeUnavailable`, NEW)** | **retry ×3 (30/60/120s) → terminal** | ✅ **(once, at exhaustion — NOT on attempts 1–3)** | `max_retries_exhausted`. **Worker wraps it in `ErrTransientGeneration` so the dispatcher reschedules; a still-valid student recording is NOT thrown away on an infra blip (D17).** Gemini `CallCount()==0` every attempt. |

- **D17 — 6-3b0 shipped a THREE-class transcode error contract; the worker maps each onto terminal-vs-reschedule at its OWN boundary (party-mode 2026-08-24, post-6-3b0-ship; Winston/Murat/John/Amelia unanimous).** The v0.1/v0.2 spec was written against a TWO-class transcoder and collapsed all transcode failure into `terminal audio_unavailable + refund`. 6-3b0 as SHIPPED exposes three `errors.Is`-able classes; mapping them literally-as-old-spec would **terminal-fail + refund a retryable infra blip, discarding a valid student recording** — the exact refund-vs-retry mistake the ratified credit model exists to prevent (John). The contract:
  | 6-3b0 error (as shipped) | Worker maps to | Dispatcher does |
  |---|---|---|
  | `media.ErrUnsupportedAudio` (bad MIME/empty/oversize) | `TerminalReasonError{Reason:"audio_unavailable"}` | refund now (dead-defense — see D8 enqueue guards) |
  | `media.ErrTranscodeFailed` (corrupt/undecodable/deadline/empty/over-cap) | `TerminalReasonError{Reason:"audio_unavailable"}` | refund now |
  | `media.ErrTranscodeUnavailable` (**NEW** — transient infra: start-fail/OOM-kill/disk/parent-cancel/read-I/O) | wrap `ErrTransientGeneration` (double-`%w`: `Is`-able as transient AND carries the `media` cause for the log) | reschedule ×3 (30/60/120s) → refund only at exhaustion |
  | unclassified transcoder error | wrap `ErrTransientGeneration` (fail-safe default) | reschedule → refund at exhaustion |
  - **Boundary rule (Winston):** the translation lives in the worker `generate()` — the dispatcher/4.3a spine MUST NOT `import internal/media` (keep the stable generic core ignorant of the churny infra package; every future infra sentinel would otherwise force a shared-spine edit + re-review). Add an explicit AC/DoD line pinning this so nobody "helpfully" refactors it into the dispatcher.
  - **Timeout-ordering invariant (Winston — the sharpest catch):** 6-3b0 classifies **parent-ctx cancel → `ErrTranscodeUnavailable` (retry)**. If the job-attempt budget is what cancels the transcode, a "too slow" condition masquerades as a retryable infra transient → burns the full 30/60/120s ladder to the same dead end every round. **The transcode's own deadline MUST be strictly less than the remaining job-attempt budget** (after download, before Gemini) so a genuine timeout surfaces as `media.ErrTranscodeFailed` (terminal), not `ErrTranscodeUnavailable`. Assert it, don't leave it to config.
  - **Anti-hostage guarantee (John — the line he won't move):** a deducted credit that is neither refunded nor converted-to-grade is silent theft. The `ErrTranscodeUnavailable` retry ladder MUST be provably bounded: 3 attempts, then a GUARANTEED terminal `audio_unavailable` + refund — no fourth path, no dead-letter/queue-purgatory that never fires the refund. The exhaustion→refund case is a red-first ATDD requirement, not a hope. Refund IS the right terminal when OUR infra failed 3× (we didn't deliver the grade → the teacher doesn't pay).
  - **Orthogonal to partial_success (John):** transcode retry is an EARLIER stage than the Gemini bands question. Exhaustion-refund is coded a TERMINAL refund, NEVER miscoded as `partial_success` (which would wrongly WITHHOLD a refund the teacher is owed). The D15 partial_success no-refund counter is untouched.
  - **MIME single-source (Winston):** the worker reads `AudioMimeType` from a 6-3b0-exposed output-MIME constant (`media.OutputMIME == "audio/ogg"`), NOT a hardcoded literal — zero drift the day the transcoder's output changes.
  - **Per-attempt temp cleanup (Winston):** `defer` temp-output removal on EVERY attempt so an `ErrTranscodeUnavailable` disk-full retry ladder doesn't itself worsen disk pressure.
  - **Mock placement (Murat, Amelia deferred):** the per-class-error + attempt-aware `media.MockTranscoder` capability is CONSUMER test infrastructure — extend it **test-only, charged to 6-3b, NO 6-3b0 production re-open** (6-3b0 already shipped its real typed errors; only the mock's ability to *simulate* them is new). A settable `Err error` field is the clean seam (superset; lets the fail-safe default arm be tested with a bare `errors.New`).

### B. Worker — `ai_grade_speaking` (transcode + Gemini audio)

4a. **Transient transcode retry — infra faults do NOT burn the credit (D17, NEW).** `media.ErrTranscodeUnavailable` (ffmpeg start-fail / OOM-signal-kill / disk-full / parent-ctx cancel / output-read I/O) and any unclassified transcoder error are wrapped in `ErrTransientGeneration` (double-`%w` — `Is`-able as transient AND carrying the `media` cause for the log).

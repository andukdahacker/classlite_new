## Story

As a **student**,
I want to **take a quiz-style attempt in a distraction-free split-pane — passage or audio on the left, questions on the right, with per-question flagging, a Prev/Next + jump navigator, a server-anchored timer that warns me before it expires, silent 30-second autosave with a local safety net, and a submit-confirmation that counts my answered / unanswered / flagged questions**,
so that **I can complete Reading, Listening, and Vocabulary assignments end-to-end without losing work, without being ambushed by the clock, and without ever seeing the answer key**.

**Scope:** Frontend only, **attempt screen only** (s33, Reading/Listening/Vocabulary) at `/assignments/:assignmentId/attempt`. The student assignments-**list** page is **Story 5-2c**; **5.2b does not release to prod independently of 5-2c** (John-B1). Consumes the **already-shipped** backend: `POST /api/submissions` (start/resume, 5.1), `GET /api/submissions/{id}/attempt` (answer-stripped bundle, 5.2a), `PUT /api/submissions/{id}/progress` (5.1), `POST /api/submissions/{id}/submit` (5.1). **No backend change, no schema, no codegen** — every type already exists in `src/lib/api/client.ts`. Writing (5.3), Speaking (5.4), and the graded Result view (5.5) are separate stories.

## Acceptance Criteria

### A. Attempt bootstrap & split-pane shell (FR-28)

1. **Two-call start/resume (D2).** Given a student opens `/assignments/:assignmentId/attempt`, When the page mounts, Then it calls `POST /api/submissions {assignmentId}` (idempotent start/resume → `Submission`; **201** new / **200** existing `in_progress`) then `GET /api/submissions/{submissionId}/attempt`. `GET` never creates. A terminal submission → **409** `SUBMISSION_EXISTS` on start → route to the confirmation end-state (AC23), not an error page. Start **409** `SUBMISSION_LOCKED` → read-only (AC15).
2. **Split-pane loads (desktop).** Given the bundle resolves on a wide viewport, Then a **draggable** two-column split-pane (`react-resizable-panels`, D3) shows the passage (`AttemptSection.content`) **or** the listening audio player on the **left** and questions on the **right**, with a keyboard-operable resize handle + a sensible default ratio. Narrow-viewport behavior is AC21 (a distinct mobile tree, **not** a squish).
3. **Variant routing.** Given a `listening` section, Then the left pane renders the audio player (AC9); otherwise (`reading`, `vocabulary`) it renders passage text. **Vocabulary** has no dedicated section type or interaction — it renders through the **same** reading pane + the same radio/text/matching inputs (AC4–6), keyed off exercise `skill` (5.2a Dev Notes). *Acceptance example: a `skill:'vocabulary'` exercise with an `fill_in_blank` group renders the reading pane + `GapInput`, no audio.* (John-c: vocabulary is covered by shared primitives, not a separate design.)

### B. Question inputs, navigation, flagging (FR-28)

4. **Radio inputs — TFNG & MCQ.** `true_false_not_given` → radio over **`true` / `false` / `notGiven`** (`TFNG_ANSWERS` order from `exercises/lib/questionTypes.ts`); `multiple_choice` → radio over `AttemptQuestion.options`. Reuse `components/ui/radio-group.tsx`.
5. **Text inputs — gap-fill & short-answer.** `fill_in_blank` / `short_answer` (empty `options`) → text input (`components/ui/input.tsx`). No client-side correctness/case logic (grading is Epic 6).
6. **Matching — accessible-first, drag as enhancement (Sally-S3, D5).** Given a `matching` group (each question is a row; `options` = replicated heading bank), Then **the native per-row single-select/radio is the DEFAULT interaction on touch and the keyboard path (WCAG 2.1.1)**; pointer drag-and-drop (`@dnd-kit/core`) is a **desktop enhancement** over the same control, plainly labelled ("Match each item →"). Each row's answer reduces to one selected heading string. The interaction never *requires* a pointer.
7. **Prev/Next + navigator rail.** Prev/Next moves sequentially; a `QuestionNavigatorRail` shows a numbered dot per question — **done / current / flagged / pending** — and clicking a dot jumps to it, moving focus to that question's first input (Sally-I5).
8. **Flag toggle.** A per-question **⚑ flag** (thumb-reachable on mobile, not colliding with Prev/Next — Sally-I4) marks it for review, switches the navigator dot to `flagged`, and persists in `content.flagged` (AC10) across autosave/reload.

### C. Timer, autosave, persistence contract

9. **Listening audio player.** A native-`<audio>` player (play/pause, seek, playback-rate; D4 — no waveform, no new dep) plays the audio URL parsed from `AttemptSection.content`. **Open product decision (Sally-I3):** IELTS listening plays once — v1 allows replay/seek (native default); single-play enforcement is a follow-up if product requires. Flagged, not blocking.
10. **Answer persistence contract (D1 — this story OWNS the `content` shape).** `submission.content` = `{ schemaVersion: 1, answers: Record<Handle, string>, flagged: Handle[] }`, `Handle = "${sectionIndex}:${groupIndex}:${questionIndex}"` (index-addressed — questions have no id, 5.2a; handles are **stable** because the exercise is `EXERCISE_LOCKED` once any submission exists, 5.1 AC15/D5 — see Dev Notes). Every answer is a **string**: TFNG ∈ `{true,false,notGiven}`; MCQ/matching = chosen option/heading string; gap-fill/short-answer = free text. **Answered predicate (per Murat-e, unit-test oracle):** a handle is *answered* iff present with a non-empty, non-whitespace value; a multi-question group is counted per-question, not per-group; flagged-and-answered counts in both. Each save is a **full replace** of `content`.
11. **Server-anchored monotonic timer (Winston-S3, Murat-a).** Given a time limit (`timeBudgetSeconds != null`), Then a single `serverNow()` = `meta.serverTime`(at load) + `performance.now()`-delta drives **both** the countdown and the AC15 read-only gate — **never `Date.now()`**. `remaining = startedAt + timeBudgetSeconds − serverNow()`. **AC11a — the tick's time source is injectable** (production wires it; tests drive it manually — no wall-clock read in the tick, so it is deterministically testable without fake timers). `timeBudgetSeconds == null` → untimed (no timer, no auto-submit). On tab re-focus, `serverNow()` re-reconciles and the "welcome back — N left" delta is shown, not a silent jump (Sally-I1).
12. **30s autosave + prominent status (Sally-B1).** Given `in_progress`, When 30s elapse since the last save **and** `content` is dirty, Then answers save via `PUT /progress`. The three-state **Saving / Saved / Error** indicator (`aria-live="polite"`) is **prominent inline** — a failed save is not a corner chip. The autosave effect's deps are stable `useCallback` primitives / a dirty-flag only — the 1s countdown tick is **never** a dep (avoids the onboarding self-perpetuating-save loop, FW-4). Pending edits also flush on navigate-away/unmount (best-effort beacon) and before submit.

### D. Submit & finalization

13. **Submit confirmation dialog (Sally-S1).** On Submit, a dialog shows counts of **answered / unanswered / flagged**; **the unanswered/flagged counts are clickable** — tapping jumps to the first such question (closes the dialog). Confirming runs the serialized finalizer (AC18) then routes to the confirmation end-state (AC23); cancel returns.
14. **Timer-expiry auto-submit (D6).** At `remaining <= 0` the client finalizes via the serialized sequence (AC18), narrated by the full-screen "Time's up — submitting" state (AC20) — no confirm dialog. Fires **exactly once** (AC18 latch).
15. **Read-only / lock handling (D7, Winston-I4).** Given the bundle 200s but `submission.status != 'in_progress'` OR `assignment.status == 'closed'` OR `serverNow() >= hardDeadlineAt`, Then the draft is **read-only** — inputs disabled, autosave off, Submit hidden — shown via an **inline banner** (not only a toast — Sally-I2). Given a racing write **409**, Then a shared error-code→message+action map flips to read-only: `TIME_EXPIRED` → "time's up"; `SUBMISSION_LOCKED` → "closed by your teacher"; `SUBMISSION_NOT_EDITABLE` → "already submitted"; `413 PAYLOAD_TOO_LARGE` → the Error saveStatus (Winston-I3). No last-rendered answers are lost on the flip.

### E. Party-mode folds — finalizer integrity, resilience, states (2026-08-04)

16. **Loading / Empty / Error trilogy (UX-1).** Loading = split-pane-shaped skeleton (not a spinner). Load error = inline retry. `404 SUBMISSION_NOT_FOUND` → "attempt not found"; `403 NOT_ENROLLED` → "no longer enrolled"; `403 INSUFFICIENT_ROLE` → route guard. All copy via i18n, no raw HTTP codes.
17. **i18n + a11y.** All strings `attempt.*` in **both** `en.json` and `vi.json` (UX-2, `assertI18nParity`) — **designed for VN length** on the tightest elements: timer chip, save-status chip, warning banners, submit-dialog counts (icon+number, text as tooltip/aria; verify no wrap-break at 360px — Sally-S4). Route role-gated `['student']`; teacher/owner → 403 with answer controls **absent** (TEST-FE-6). `axe` clean on every state; keyboard flow (tab order, matching keyboard path, dialog focus-trap + focus-return) tested as a flow (TEST-UX-2).
18. **Serialized finalizer + single-fire latch (Winston-B3, Murat-b/6).** The finalizer is an ordered async sequence: **supersede any in-flight autosave**, `await` a flush that resolves on the **latest `saveSeq` ack**, **then** `POST /submit` — guarded by an `alreadyFinalized` latch so it fires **exactly once** (whether triggered by AC13 confirm or AC14 expiry). **No beacon path for the timed finalizer** (beacon is unmount-only best-effort — you cannot beacon a PUT then reliably POST after it). If the final flush fails, surface a "couldn't save everything — retry" fallback rather than a silent lossy submit.
19. **Resume-finalize expired attempts (Winston-B2, Murat-d, John-d — Ducdo-ratified).** Given the loaded attempt is `in_progress` but `serverNow() >= startedAt + timeBudgetSeconds` (expired-but-unsubmitted), When the page loads, Then the client **immediately runs the AC18 finalizer** (idempotent; a racing 409 is treated as already-final). The genuinely-never-returns case is the deferred **server sweep FU-5-1-A** — a **signed-off accepted risk** (Ducdo 2026-08-04); timed attempts render a visible "your exam submits only while this tab is open" note (Murat-d).
20. **Timer warnings + narrated expiry (Sally-B2).** The timer chip goes **amber at ≤5:00** and **red + gentle pulse at ≤1:00** (respecting `prefers-reduced-motion`), each announced via `aria-live` ("5 minutes remaining"). At `0:00` a **full-screen "Time's up — submitting your answers"** state narrates the finalize — never a silent blink.
21. **Mobile component tree (Sally-B3, UX-4).** On narrow viewports the attempt is **not** stacked scroll: passage/audio and questions are **switchable segments/tabs**, the navigator is a **bottom-sheet** (or a "12/40" pill that opens the grid), the timer + save-status stay **pinned**, flag + Prev/Next thumb-reachable, touch targets ≥ **44×44 CSS px**. The draggable split-pane (AC2) is desktop-only.
22. **localStorage draft mirror (Sally-B1, Winston-S2 — Ducdo-ratified into 5.2b).** Answers **write-through to `localStorage`** (keyed by `submissionId`) on change, **recover on reload/crash**, **clear on successful submit**, and **reconcile on reconnect** (server-state wins on conflict, student warned via non-blocking toast). This is the real single-tab no-data-loss guarantee (not the up-to-30s window of autosave alone). Multi-tab `BroadcastChannel` stays deferred to 5.3.
23. **Submission confirmation end-state (Sally-S2, John-b).** Post-submit is a **real confirmation** — "Your answers are submitted and saved ✓ · your teacher will release results" + a **safe primary action** (back to assignments) — **not** a bare "pending" placeholder/`<div>TODO</div>`. The graded result view is Story 5.5.

### Backend contracts consumed (all in `src/lib/api/client.ts` — do NOT hand-write types, TS-2/XL-1)
- **Start/resume:** `POST /api/submissions` `CreateSubmissionRequest {assignmentId}` → `Submission`. 201 new / 200 resume (idempotent, `started_at` set once, never reset). 409 `SUBMISSION_EXISTS`/`SUBMISSION_LOCKED`; 403 `NOT_ENROLLED`/`INSUFFICIENT_ROLE`.
- **Read bundle:** `GET /api/submissions/{id}/attempt` → `EnvelopeAttemptBundle {data:{submission,assignment,exercise}, meta}`. `meta.serverTime` = timer anchor. Read **NOT lock-gated** (D6) — always 200; FE derives read-only (AC15). `AttemptExercise` **answer-stripped** — `AttemptQuestion={text,type,options}`; `correctAnswer`/`acceptedVariants` structurally absent.
- **Save:** `PUT /api/submissions/{id}/progress` `{content}` (full replace) → `Submission`. 409 `SUBMISSION_NOT_EDITABLE`/`TIME_EXPIRED`/`SUBMISSION_LOCKED`; 413 `PAYLOAD_TOO_LARGE`.
- **Submit:** `POST /api/submissions/{id}/submit` — **no body** → `Submission`. 409 `SUBMISSION_NOT_EDITABLE`/`SUBMISSION_LOCKED`.
- **Enums:** `SubmissionStatus=in_progress|submitted|ai_processing|graded`; `AssignmentStatus=open|closed`; `QuestionGroupType=multiple_choice|true_false_not_given|fill_in_blank|short_answer|matching`; `ExerciseSkill=reading|listening|writing|speaking|grammar|vocabulary|general`.

So index-addressed handles **cannot drift mid-attempt**; the `schemaVersion` on `content` is the only version guard needed. (This is why Winston-B1's mid-attempt-edit corruption is a non-issue here — confirm the guarantee holds in Task 0.)

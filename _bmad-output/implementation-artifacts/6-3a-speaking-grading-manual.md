## Story

As a **Teacher**,
I want **to grade a Speaking submission with an audio player (waveform, seek, playback-speed) and comments pinned to specific timestamps on the recording, scoring the four IELTS Speaking criteria**,
so that **I can give precise, moment-anchored feedback on spoken responses and release a band the student can review.**

**Scope:** The **manual** speaking grading path end-to-end, mirroring 6.1 (Writing) but for audio. **Backend:** branch `POST /api/submissions/{id}/grade` by exercise skill (writing → shipped path; speaking → new `GradeSpeaking`), reusing the generic `grades` table / immutability trigger / `current_grades` view / `OverallBand` scorer **unchanged**; add the speaking criterion set + a timestamp-comment validate/normalize sibling; inject `StorageService` into `GradingService` to mint a teacher audio presigned URL on the grading read (SEC-8) + a teacher audio-refresh route. **Frontend:** a from-scratch Web-Audio **waveform player** (decode → peaks → render → seek → speed → pin-at-playhead) wiring the shipped `SpeakingGradingSurface` shell into a new `SpeakingGradingPage` (s24), reached via a skill-dispatching route parent, with the same durable-draft, band inputs, comment taxonomy, queue nav, and release/revise flow as 6.1.

**Explicitly NOT in this story (→ 6-3b / 6-3c):** anything AI. No Gemini audio input, no `ai_grade_speaking` worker, no `POST …/ai-grade` speaking enqueue, no transcription, no `aiSuggestion`/transcript panel, no timestamped-moments review, no `partial_success`. This story ships **manual grading only** — the teacher listens, pins comments, scores, and releases. See **Out of Scope**.

## Decisions (resolved during context recon + party-mode pre-dev review — treat as spec, not suggestion)

- **D1 — Reuse the generic grade persistence layer UNCHANGED; no grades migration.** The `grades` table (`criterion_scores jsonb`, `overall_band numeric(2,1)`, `comments jsonb`, `feedback`, `version`, `released_at`, append-only RLS + `UNIQUE(submission_id, version)`), the `submission_immutable_after_release` P0001 trigger, the `current_grades` `security_invoker` view, the submitted→graded flip (`GradeSubmission`), the grade-release outbox email, and the 23505/P0001 translation are **submission-type-agnostic** and reused byte-for-byte. Speaking's four criterion keys + timestamp comments fit the existing JSONB columns → **zero schema change**. `grading.OverallBand` works for any four half-bands — but it takes the concrete *writing* `CriterionScores` struct, so extract a small `overallBandFromFour([4]float64) Band` core (reuse-by-abuse — packing speaking bands into writing-named fields — is REJECTED). *(Party: Winston — the reuse is real but `OverallBand`'s signature is writing-typed; extract, don't abuse.)*
- **D2 — Grade path branches by exercise SKILL; the handler decodes the body AFTER skill resolves.** `POST /api/submissions/{submissionId}/grade` (+ `/grade/revise`) stays one operation. **The current handler strict-decodes the writing-shaped body (`DisallowUnknownFields`) BEFORE any DB access (`grading_handler.go:184` → `decodeClassJSONBody`), then calls `GradeWriting` — a speaking body (`timestampMs`, `fluencyCoherence`) would 422 as unknown-field before dispatch.** So the handler MUST: (1) read the raw body to `json.RawMessage`; (2) resolve `exercise.skill` (lightweight RLS-scoped probe, or resolve inside the service tx and pass the raw body down); (3) strict-decode the raw body into the skill's struct (`gradeRequestBody` for writing, new `speakingGradeRequestBody` for speaking); (4) dispatch → `GradeWriting` / `GradeSpeaking`. Add `assertSpeakingExercise` (skill=`speaking`) as the sibling of `assertWritingExercise` (`grading_service.go:650`). SEC-7: the branch is chosen from the submission's DB skill, **never a client field**; a client cannot force the branch. A body whose shape doesn't match the resolved skill → `409 SUBMISSION_SKILL_MISMATCH`. *(Party: Winston — decode-before-DB is the biggest rework risk; name the raw-body-then-resolve mechanism.)*
- **D3 — Speaking criterion set = `fluencyCoherence, lexicalResource, grammaticalRange, pronunciation`; TWIN the validator, don't parameterize.** `grading.ValidateCriterionScores` (`validation.go:52`) validates four **named struct fields** of the writing `CriterionScores` — it cannot be parameterized over a key set without abandoning the struct. So add a **twin**: `SpeakingCriterionScores` struct + `validSpeakingCriteria` map + key constants + `ValidateSpeakingCriterionScores(SpeakingCriterionScores)` + a speaking `criterionScoresWire` marshal twin, all in a `internal/service/grading/` sibling. `OverallBand` core reused via the D1 `overallBandFromFour` extraction. *(Party: Amelia + Winston — "parameterize or twin" resolved to TWIN.)*
- **D4 — Comments are TIMESTAMP-pinned; bound leniently against `max(persistedDurationMs, maxPinMs)`.** New `TimestampedComment` shape `{ type: error|praise|suggestion, criterion: <speaking key>, timestampMs: int|null, text: string }`. `timestampMs = null` ⇒ a **general (unpinned)** comment (the analog of writing's whole-essay null anchors). New `NormalizeTimestampComments(comments, durationMs)` sibling of `NormalizeComments`. **The BE has NO `durationSec` parser today** (only `speakingAudioKeyFromContent`) — add a `speakingDurationMsFromContent(content)` extractor. **Duration-source divergence (party: Murat):** the FE composes pins against the *decoded* `AudioBuffer.duration`; the BE knows only the *persisted, possibly-rounded* `content.durationSec` (5.4 stores an estimate). To avoid silently demoting a legitimate pin at t=59s when persisted=58s, the BE bounds against **`max(persistedDurationMs, maxCommentTimestampMs) + 1s slack`** — demote to null ONLY a negative or absurdly-out-of-range (> that bound) timestamp, never a plausible one. Degenerate persisted duration (absent / 0 / negative / fractional) is handled: absent/≤0 falls back to `maxCommentTimestampMs` (so pins are kept, not all-demoted); fractional `durationSec × 1000` rounds, never truncates-to-error. Same three comment types as writing.
- **D5 — Teacher audio presign on the grading read (SEC-8); inject StorageService into GradingService.** **`GradingService` has NO storage dependency today** (`NewGradingService(pool, auditSvc, clk)`, `main.go:580`) — unlike `SubmissionService.WithStorage(...)`. Task 5 MUST add a `StorageService` field + constructor param + rewire `main.go:580` to `.WithStorage(uploadStorage)`. `GetSubmissionForGrading` then mints `audioUrl` via `StorageService.PresignGetOwned(ctx, audioKey, tc, submissionAudioURLExpiry=5min)` **outside the committed read tx** (PERF-1 — the exact placement 5-5a uses at `attempt_service.go:154-162`). Add a teacher on-demand refresh route (mirror the student `GET …/submission/audio`, but **teacher-of-class authz** via `assertTeacherOfSubmissionClass`, not owner-student) returning `{ url }`, consumed by the FE re-sign pattern. **SEC-8 is structurally enforced:** `PresignGetOwned` re-asserts the key under `tc.CenterID + "/"` before signing (`storage.go:79`) → a foreign key is rejected pre-mint. In practice a cross-tenant attempt dies earlier at the RLS-scoped submission read (404); the *novel* authz surface is **same-tenant, wrong-teacher** → `assertTeacherOfSubmissionClass` → 403, zero mint. *(Party: Winston — GradingService has no StorageService; that's a required wiring change.)*
- **D6 — Missing/corrupt audio is FE-driven; NO server-side HeadObject probe.** *(Party: Winston + Murat converge.)* Drop the D6-original server HEAD (it was a mandatory synchronous R2 round-trip per read, risked a PERF-1 in-tx placement, and needed a typed-NotFound classification the code lacks today). `TeacherGradingView.audioStatus` is now **`hasAudio | none`** — `hasAudio` = speaking submission with a non-empty `audioKey`; `none` = non-speaking / empty key (no `audioUrl` minted). **The FE detects "missing" from the signed GET:** a `404/NoSuchKey` on the R2 object (after one re-sign retry to rule out expiry) ⇒ render **"Ask student to re-record"** (UX-DR16); a **transient 5xx / network error ⇒ inline retry, NEVER "re-record"** (a blip must not tell a teacher a good recording is gone — party: Murat's false-positive). A client-side `decodeAudioData` throw on a fetched-OK-but-corrupt file routes to the same "Ask student to re-record" state (the file is unusable either way).
- **D7 — Web-Audio waveform player: from-scratch, no npm dep; playhead-is-the-pin-cursor.** No audio/waveform lib in the repo (confirmed — no wavesurfer/howler/peaks). Build `AudioWaveformPlayer` in a shared domain leaf: fetch presigned URL → `AudioContext.decodeAudioData` → **pure `computePeaks(channelData: Float32Array, buckets): Float32Array`** downsample → `<canvas>` render (played bars darker) → play/pause/seek → speed cycle 0.5×/1×/1.5×/2× via `HTMLMediaElement.playbackRate`. **Gesture model (party: Sally — AC1 "click to seek" vs AC6 "click to pin" is a real collision):** click/drag on the waveform = **seek only** (moves playhead); a dedicated **"Pin here" transport button + `P` key** drops a comment **at the current playhead time**, whether playing or paused. Fix the tip copy accordingly (not "click the waveform to pin"). **Pin time = `audio.currentTime` (equivalently `fraction × intrinsicDuration`) — speed-INDEPENDENT** (never elapsed-listening-time × rate). Pin lifecycle: edit text/criterion, delete, drag-to-nudge a pin; clicking a rail card seeks the playhead to that pin + highlights it (bidirectional). Long-recording de-collision: cluster adjacent pins into an expandable count-badge; **no zoom in v1** (deferred, stated). **Keyboard model (canvas is not natively operable — party: Sally):** a focusable transport where **←/→ seek ±5s, Shift+←/→ ±30s, Space play/pause, `P` pin-at-playhead**, plus an `aria-live` time read-out ("1:24 of 4:38"); focus arbitration with the queue's arrow-key prev/next — **arrows seek when the player is focused, navigate the queue otherwise** (state it, or the two features fight over the arrow keys). No new dependency; if a lib is ever proposed it MUST get a Rolldown/Vite-8 review. **Net-new components — `AudioPlayer`/`TimestampedNote` are catalog entries (inventory 150-151), NOT shipped code**; only `SpeakingGradingSurface.tsx` exists. The player + rail are built here. **CommentType seam:** the shipped `CommentCard` uses `'error'|'praise'|'suggest'` (`CommentCard.tsx:18`) — `'suggest'`, not the wire `'suggestion'`; `WritingGradingPage.buildGradeInput` already crosses this seam, reuse it.
- **D8 — Route dispatches by skill via a fetch-before-dispatch parent; the speaking draft is a DISCRIMINATED variant.** The `/classes/:id/grading/:aid/:sid` route (`routes.tsx:856`, today hardcoded to `WritingGradingPage` in a loader-less `index` child) cannot branch at route-resolution (skill isn't known there). Add a thin `GradingRoute` **parent component** that runs `useGradingSubmission(submissionId)`, reads `view.exercise.skill`, then **dynamically imports** `WritingGradingPage` vs `SpeakingGradingPage` (keeps separate lazy chunks; the child page re-runs the same query — TanStack cache dedups, acceptable). The dispatcher owns the first skeleton. **DraftComment (party: Amelia — the conflict is `criterion`, not `timestampMs`):** `DraftComment.criterion` is typed `keyof CriterionScores` (writing keys, `gradingDraft.ts:29`); a speaking criterion isn't assignable, and adding `timestampMs` alone doesn't fix it. Use a **discriminated speaking draft variant** (its own `criterion` union + `timestampMs` instead of `anchorStart/anchorEnd`) rather than widening the shared type. **FE band math must be TWINNED too (party: Amelia — spec flagged only the Go side):** `computeOverallBand`/`overallBandMath` iterate the hardcoded writing `CRITERION_KEYS` (`computeOverallBand.ts:19,35,56`) — parameterize them over a key array OR twin for speaking; `isValidBand` is per-scalar → reused. Note the real export names: `MIN_BAND | MAX_BAND | BAND_STEP`.
- **D9 — The notes rail is TIMELINE-SHAPED now, so 6-3c slots AI in without a rebuild.** *(Party: Sally — highest-leverage scope call.)* §9.2 describes the rail as a mixed teacher+AI thread. Even though all AI is deferred, 6-3a's rail MUST already: (1) sort pinned comments by `timestampMs`; (2) carry a `source: 'teacher'` discriminator on each item; (3) zone general (null-timestamp) comments separately. Then 6-3c interleaves `source:'ai'` items instead of re-architecting. Manual-only queue: the UX-DR23 prev/next nav is reused from 6.1; the open "does AI run on queue-open or on-demand?" question (spec line 672) and the quick-action bar's "Accept AI grade" affordance are **6-3c** concerns — 6-3a resolves nothing about AI prefill.
- **D10 — api.yaml: the grade `requestBody` becomes a `oneOf`; no codegen risk.** The operation's `requestBody` currently `$ref`s `GradeInput` alone (`api.yaml:5194`) — to accept writing-or-speaking it MUST become `oneOf: [GradeInput, SpeakingGradeInput]` (same for revise). **`openapi-zod-client` is DISABLED** (`codegen.sh:16-24`, Zodios/`zod@4` peer conflict, TODO story-1-8) — only `openapi-typescript → client.ts` runs and the Go server hand-decodes, so the `oneOf` emits a clean `A | B` TS union with **zero codegen risk**; the FE builds the right member by skill. The epic's "optional transcript reference" is **deferred to 6-3c** (additive, GO-5 explicit-null, non-breaking) — state it so a reviewer doesn't read it as a dropped epic AC.

## Acceptance Criteria

### A. Audio player + waveform (s24)

1. **Player renders (epic AC; §9.2; D7).** Opening the Speaking grading view for a submitted speaking submission renders an audio player with **waveform** (played bars darker), **play/pause**, **seek** (click/drag on the waveform moves the playhead — **seek only, never pins** — D7), and **playback-speed** cycling **0.5× / 1× / 1.5× / 2×**, plus a current/total time read-out. Decoded from `audioUrl` via Web Audio, no library.
2. **Audio URL freshness (D5; 5-5a pattern).** The player consumes `TeacherGradingView.audioUrl`; on a play-intent when the URL is >4 min old it re-signs via the teacher audio-refresh route before playing (mirror `ResultSpeakingPlayback`'s stale/refresh state machine); a 404/expiry mid-session triggers one re-sign then a recoverable retry.
3. **Missing/corrupt audio (epic AC; D6).** A `404/NoSuchKey` on the signed GET (after one re-sign retry) — or a `decodeAudioData` failure on a fetched-but-corrupt file — renders the UX-DR16 error state with a **"Ask student to re-record"** primary action (i18n), no waveform. A **transient 5xx/network error shows an inline retry, NOT "re-record"** (D6 — no false positives).

### B. Band scoring (4 speaking criteria)

4. **Four criterion inputs + overall (epic AC; §9.1/§9.2; D8).** Band inputs render for **Fluency & Coherence, Lexical Resource, Grammatical Range & Accuracy, Pronunciation**, each 1.0–9.0 in 0.5 increments, in the 2×2 grid. The **overall band is computed client-side** via the twinned `overallBandMath`/`computeOverallBand` over `SPEAKING_CRITERION_KEYS` and rendered in the shipped s23 overall-band treatment (Fraunces display).
5. **Server band authority (D1/D3).** `POST …/grade` (speaking branch) validates the four speaking bands (1.0–9.0, 0.5 grid → else `422`) via `ValidateSpeakingCriterionScores` and computes the authoritative `overall_band` via `overallBandFromFour` — the client value is advisory. Persisted to the existing `grades.criterion_scores`/`overall_band` columns.

### C. Timestamp-pinned comments

6. **Pin-at-playhead (epic AC; §9.2/§6.3; D7).** A **"Pin here" control (button + `P` key)** creates a comment at the **current playhead time** (`audio.currentTime`, **speed-independent**); the comment carries one of **Error / Praise / Suggestion** + a speaking criterion tag; pins appear along the waveform timeline and as cards in the notes rail (reuse `CommentCard`'s `timestamp` prop). Clicking a rail card seeks the playhead to that pin + highlights it. A teacher can edit, delete, or drag-nudge a pin.
7. **General (unpinned) comments + lenient bounds (D4).** A comment with `timestampMs === null` renders as a general/unpinned note (zoned separately in the rail — D9). On persist, `NormalizeTimestampComments` demotes to null ONLY a negative or `> max(persistedDurationMs, maxPinMs)+1s` timestamp — a plausible pin past a rounded-down persisted duration is **kept, not demoted** (D4). Never dropped.
8. **Grade write + revise (epic AC; D1/D2/D4).** `POST …/grade` (speaking) accepts `{ criterionScores: SpeakingCriterionScores, overallBand, comments: TimestampedComment[], feedback? }` → comments persist to `grades.comments`; submission flips `submitted → graded` with `released_at`; student gets the grade-release notification (reused outbox); the released grade is **immutable** (reused trigger → re-grade → `409`). **Revise happy-path:** `POST …/grade/revise` on a released speaking grade inserts a **new version row** (version=2, reason, audit_logs — mirror `ReviseGrade`) and re-releases; the prior version is retained.

### D. Queue + navigation (UX-DR23)

9. **Queue nav (epic AC; §9.4).** The shared topbar Prev/Next-student queue navigator (reused from 6.1, `useGradingQueue` — modality-agnostic rows) works on s24 without returning to the list; arrow-key nav + Escape-to-queue per UX-DR23, with focus arbitration against the player's own arrow-seek (D7 — player-focused arrows seek, else navigate). The queue includes speaking submissions.

### E. Reads + routing

10. **Grading read + audio authz (D2/D5/D6).** `GET /api/submissions/{submissionId}/grading` for a speaking submission returns `TeacherGradingView` with `audioUrl` (presigned, 5-min, SEC-8, minted outside the tx) + `audioStatus` (`hasAudio|none`) + the four speaking criterion scores + timestamp comments of any existing grade. **Teacher-of-class authz** (not creator); a same-tenant wrong-teacher → `403`, **zero presign minted**. The student `/result` path is untouched.
11. **Skill-dispatched route (D8).** `/classes/:id/grading/:aid/:sid` renders (via the `GradingRoute` fetch-before-dispatch parent) `SpeakingGradingPage` when `exercise.skill==='speaking'`, `WritingGradingPage` when `'writing'` — reusing the role-gate/full-bleed/lazy/desktop-seam. Desktop-only (no mobile speaking-grading tree — §11; the seam blocks *grading*, not playback — D-note).

### F. States + i18n + a11y

12. **Loading/Empty/Error trilogy (UX-1/UX-DR24).** A **labeled** waveform skeleton ("Preparing audio…") while decoding (decode of a long file is multi-second — not a mute skeleton); inline retry on transient audio-load error; the "Ask student to re-record" state for missing/corrupt audio (AC3); all copy via i18n.
13. **i18n parity (UX-2/TEST-FE-4).** Every new string is a `speakingGrading.*` (surface) or reused `grading.*`/`criterion.*` key added to **both** `en.json` AND `vi.json` in the same change; a `STORY_6_3A` closed-literal list + prefix-ratchet parity test asserts both locales.
14. **Accessibility (TEST-FE-5/UX-DR16, UX-DR23; D7).** The player + comment composer pass axe; play/pause/speed/Pin-here reachable by role/label; **full keyboard operability of the waveform** — ←/→ ±5s, Shift+←/→ ±30s, Space play/pause, `P` pin — with an `aria-live` time read-out (a labeled `<canvas>` is described, not operable — the keyboard model is the real requirement, not just `aria-label`).

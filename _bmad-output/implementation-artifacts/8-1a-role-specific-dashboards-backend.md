## Story

As a teacher, admin, owner, or student,
I want a single `GET /api/dashboard` endpoint that returns exactly the aggregate data relevant to my role — my teaching triage, my center's pulse, or my own work and feedback — sourced from the tables we already have,
so that the role-specific dashboards (Story 8-1b) render in one round-trip without N+1 query amplification.

Backend slice only. This is the **keystone** of Epic 8: it delivers the role-scoped dashboard read AND the R31/PERF-2 performance-test harness (query-count assertion + EXPLAIN-ANALYZE plan check) that Stories 8.2 and 8.4 will reuse. No frontend, no new UI. The endpoint composes **mostly-existing scoped queries** (reuse map in Dev Notes) plus a handful of new lightweight aggregates, and reuses `AtRiskDetector.Classify` unchanged.

- **D7 — R31/PERF-2 KEYSTONE harness (net-new, reusable). [test-design-architecture R31 item #5]** No query-counting pool / tracer / EXPLAIN helper exists. Build BOTH, as reusable `internal/test` helpers (8.2/8.4 consume them). **Both mechanisms below are CORRECTED from the naive design (party-mode 2026-09-11) — the obvious approaches false-green.**
  - **(1) query-count — the counting boundary is the tx the SERVICE runs on, NOT the pool.** The service does `tx, _ := s.db.Begin(ctx); q := generated.New(tx)` (`student_service.go:240`) — every dashboard query runs on that `tx`. A decorator wrapping only `TxDB.Exec/Query/QueryRow` (or the `SetupRawPool`) sees **zero** business queries (`TxDB.Begin` returns the raw nested `pgx.Tx`, `helpers.go:44-46`) → counter ≈ 0 → "≤N" false-passes. **Two sound routes:** (a) wrap the `generated.DBTX` (`generated/db.go:14` = `{Exec,Query,QueryRow}`) that the service's `Begin` returns — a decorator counting each call — this is the preferred, savepoint-safe route; OR (b) a **dedicated pool built with `pgxpool.Config.ConnConfig.Tracer`** (a tracer CANNOT be attached to the existing `sync.Once` singleton post-hoc, `helpers.go:48-63`) that counts at the wire on `TraceQueryStart`. Assert count per `GET /api/dashboard` `≤ N`, **N a fixed named const per role, documented as `1 (the SET LOCAL app.current_tenant_id Exec, store/db.go:46) + k sqlc calls`** — the tracer/decorator also sees tx plumbing (`BEGIN`/`SAVEPOINT`/`SET LOCAL`/`RELEASE`/`COMMIT`), so either FILTER non-business statements or bake the documented offset. sqlc pgx-v5 emits exactly one `Query/QueryRow/Exec` per generated method (no implicit batching/pipelining) → "≤N" is a stable, meaningful assertion. **Prove it fails on a synthetic N+1** (a loop that re-queries per row). Evidence artifact: `evidence/query-count.json` (P0).
  - **(2) EXPLAIN — MUST `SET LOCAL enable_seqscan = off` before EXPLAIN, or it false-REDS on tiny data.** Postgres picks Seq Scan on small seeded tables regardless of indexes; the in-repo idiom that fixes this ALREADY exists — model on `audit_logs_rls_test.go:241-262` (`SET LOCAL enable_seqscan = off` then `EXPLAIN …`), which makes "no Seq Scan" prove an index is *usable*. Assert **no `Seq Scan`** for each role's plan: on the tenant-filtered index columns (`center_id`/`class_id`/`teacher_id`) AND on the **driving `submissions` relation** of the new grading-backlog query (a `status`-filter seq scan of all-center submissions would otherwise pass the join-column check while being O(all submissions) — Winston). If a plan regresses, Task 6 flags a partial index `submissions(status) WHERE status IN ('submitted','ai_processing')` (a MIGRATION → WF-2, flag before adding). Both harnesses run in CI on the endpoint.
- **D8 — Clock injection + CENTER-TIMEZONE day bucketing.** Bind `@now` as an arg; NEVER SQL `now()` (reuse the `clock.Clock` already threaded into `AtRiskDetector` + the services, so a fixed test clock drives all boundaries deterministically — `students.sql` uses a bound `@now`). **AND: every absolute day/week/"today" boundary MUST bucket in `centers.timezone`, NOT UTC.** `centers.timezone text NOT NULL DEFAULT 'Asia/Ho_Chi_Minh'` exists (`create_auth_tables` migration :34) — resolve it in the service and compute `startOfWeek(now)`/`sessionsToday`/`sessionsThisWeek`/`staffActiveToday`/the `dueSoon` window against it (e.g. `@now AT TIME ZONE @center_tz` truncation, or compute the bounds in Go from the loaded tz and pass them as args). A UTC-truncated boundary misfiles a UTC+7 center's evening sessions into the wrong day, and the FE **cannot** repair it — `sessionsToday` is a server scalar and `weekSessions`/`todaySessions` are pre-filtered lists (Sally/Winston). This SUPERSEDES the `class.go:523` UTC-truncate precedent for these day-bucketed dashboard reads. (Relative elapsed/countdown stays FE-side via `meta.serverTime` — TZ-agnostic — which is correct.)
- **D9 — No caching (arch MVP decision, `architecture.md:207`); one tx per request (PERF-1).** The dashboard hits Postgres directly and relies on set-based aggregation + existing composite indexes (`idx_questions_class_status`, `idx_sessions_*`, enrollment/`center_id`/`class_id` indexes). Open ONE tx, `SetTenantContext`, run all the role's reads inside it, commit. Do not fan out per-row queries; do not add a Redis/in-proc cache.
- **D-ROUTE — one role-branched `/dashboard`, retire the `/student` stub — is an 8-1b (frontend) concern. [RULED Ducdo 2026-09-11]** Recorded here so 8-1b picks it up; NOT this story. 8-1a is endpoint-only and role-agnostic at the URL (a single `/api/dashboard`; the payload varies by the caller's DB role).
- **D10 — Typed custom errors only (GO-2); envelope via `WriteEnvelope`.** The single-object payload uses `WriteEnvelope(w, 200, clk, data)` (`response.go:34`, auto-injects `meta.serverTime`). No pagination on the dashboard (aggregate/top-N, not list — D6 caps each rail at a documented N). Any misuse returns a typed `model.*`/`service.*` error → `ErrorMapper`.
- **D11 — Reads only; zero writes, zero new tables, zero migrations.** Every table already exists. This story adds `.sql` query files + regenerates sqlc, and edits `api.yaml` + regenerates the TS/Go/Zod artifacts. No schema change → no `migrate.sh`; `codegen.sh` IS run (sqlc + openapi) since `.sql` and `api.yaml` change (WF-3).
- **D12 — PROVISIONAL read contract (mirror 7-2a D14 / 7-1b D16).** Banner-mark the new `Dashboard*` schemas PROVISIONAL in `api.yaml`; 8-1b co-finalizes (strips markers + regen after the UI consumes every field). This lets 8-1b tune field shapes without a breaking mid-epic contract churn.

## Acceptance Criteria

### A. Endpoint, chain, role branch, envelope

1. **Given** an authenticated, email-verified user with a center context, **When** `GET /api/dashboard` is called, **Then** it resolves through the ungated Q&A-style chain (`extractTenant → requireVerified → requireCenter → settingsLimit → ErrorMapper`, **no `RequireRole`** — D2) and returns `200` with a `{ data: DashboardData, meta: { serverTime } }` envelope (`WriteEnvelope`, D10). **And** a request with no/expired token → `401`; missing center context → the standard `requireCenter` error; never a `403` purely for role.
2. **Given** the caller's DB-resolved role (`tc.Role`, re-fetched from `center_members` by `ExtractTenant`, never the raw JWT — SEC-1/EDGE-2), **When** the service builds the payload, **Then** `DashboardData.role` = that role and **exactly one** of `teacher` / `owner` / `student` is non-null: `student → student`; `teacher → teacher`; `owner|admin → owner` (both center-wide; discriminator distinguishes them — D3). **Falsifiable test (AC2, WF-8 red):** for EACH of the 4 role values, assert the populated block is non-null **AND the other two blocks are explicit `null`** (GO-5) — a test that only checks "the teacher block is present for a teacher" passes even if the service wrongly populates all three; the null-half is mandatory.
3. **Given** the whole handler, **When** any DB access happens, **Then** it runs inside a **single tx** with `SetTenantContext` set once (PERF-1/D9); the injected `clock.Clock` supplies `@now` to every window predicate (D8); no `context.Background()` (GO-4).

### B. Teacher payload (FR-52, s06)

4. **Given** a teacher caller, **Then** `data.teacher` carries: **`weekSessions`** — the teacher's own-class sessions in `[startOfWeek(now), startOfWeek(now)+7d)` (reuse `ListSessionsByRange` with `teacher_id` = own id; each item: sessionId, classId, className, color, topic, startsAt, endsAt, status); **`needsGrading`** `{ count, items[≤N] }` — submitted/ai_processing-but-not-released submissions across the teacher's classes, each item: submissionId, studentName, assignmentTitle (exercise/assignment label), className, `overdue` flag (past `assignment.hard_deadline_at`/`deadline_at` vs `@now`); **`unansweredQuestions`** `{ count, items[≤N] }` — `status='open'` questions in the teacher's classes (reuse `Count/ListQuestionsForReader` unanswered, `reader_id`=own id), each: questionId, content (or excerpt), anchorExcerpt, classId/className, `elapsed` source = `createdAt` (FE computes elapsed via serverTime); **`atRiskStudents`** `{ count, items[≤N] }` — `AtRiskDetector.Classify` == `at_risk` over the teacher's students (D5), each: studentId, name, attendanceRate (nullable), pendingCount, overallBand (nullable), reasons[] slugs.
5. **Given** the teacher has no upcoming sessions / empty queue / no at-risk students, **Then** each block returns `count: 0` + `items: []` (never null arrays; GO-5) — a valid empty payload, not an error.

### C. Owner/Admin payload (FR-51, s48)

6. **Given** an owner or admin caller, **Then** `data.owner` carries: a **`pulse`** `{ activeClasses, studentsEnrolled, staffActiveToday, sessionsThisWeek, sessionsToday }` (center-wide counts, day/week bucketed in `centers.timezone` — D8; `staffActiveToday` = center staff whose `last_active_at = MAX(refresh_tokens.created_at)` falls within today per `@now`, reuse the 7.1a `staff.sql` last-active idiom — document that this is login/rotation time, a proxy for "active", NOT true last-seen); a **`todaySessions`** `SessionLite[]` — the center's sessions today (reuse `ListSessionsByRange` center-wide, `[startOfDay, startOfDay+1d)` in `centers.timezone`), each with `teacherName` + `enrolledCount` so 8-1b renders the s48 "Today across the center" cards + derives "live now" (`startsAt ≤ serverTime < endsAt`); and a **`needsAttention`** card. (Sally — s48's left column is a first-class element; without `todaySessions` the FE cannot build it or "live now".)
7. **Given** the `needsAttention` card, **Then** it carries: **`unassignedStudents`** `{ count, items[≤N] }` (reuse `Count/ListUnassignedStudents`, `enrollments.sql:105/121`); **`atRiskStudents`** `{ count, items[≤N] }` (`AtRiskDetector`, NULL-scoped center-wide — D5); **`capacity`** `{ storageUsedBytes, storageLimitBytes, percentUsed, approaching }` (storage-% only — D-CAP; `approaching = percentUsed >= STORAGE_APPROACHING_THRESHOLD`, a named const); **`pendingInvites`** `{ count }` (`invites WHERE accepted_at IS NULL AND expires_at > @now` — new count query, D6). **And** there is **NO** unanswered-Q&A element and **NO** plan/seat capacity field (D-QA / D-CAP; plan-limit language already owned by FU-4-4-4/FU-4-4-1 → Epic 9).
8. **Given** the owner payload, **Then** it is center-wide aggregates and **distinct from the teacher payload** (no personal teaching queue) — `data.teacher` is `null` for an owner/admin caller (D3). `over-capacity classes` MAY be surfaced via the existing `ListOverCapacityClasses` (`enrollments.sql:132`) as an additional needs-attention signal (dev discretion; document if included).

### D. Student payload (FR-53, s29)

9. **Given** a student caller, **Then** `data.student` carries: **`upcomingSessions`** — sessions for the student's actively-enrolled classes in `[now, now+7d)` (RLS + enrollment-scoped; each: className, topic, startsAt, endsAt); **`dueSoon`** — the student's open assignments ordered by deadline with the deadline timestamp (reuse `ListStudentAssignments`, `assignments.sql:58`, enrollment-scoped, LEFT-join own submission; each: assignmentId, title, className, deadlineAt, submissionStatus, **`skill`/exercise `type`** and the in-progress **`submissionId`** — so the s74 "Continue writing" hero picks the right CTA verb/route AND deep-links to resume the existing draft, Sally); **`recentFeedback`** — the student's most-recent RELEASED grades (`current_grades` where `released_at IS NOT NULL`, own submissions, `ORDER BY released_at DESC, id DESC LIMIT N` — new query D6; each: submissionId, assignmentTitle, overallBand, releasedAt); **`myQuestions`** — the student's own `status='open'` question threads awaiting reply (reuse `ListQuestionsForReader`, `reader_id`=own id, unanswered; each: questionId, content/excerpt, className, createdAt).
10. **Given** the student payload, **Then** it contains **no class averages and no other students' data** (FR-50 invariant; every query is `student_id = tc.UserID`-scoped or enrollment-scoped) — asserted adversarially (G). Empty states = `[]`, never null. **And** `data.teacher` / `data.owner` are `null`. **First-run (s62) is NOT inferred from all-empty arrays** — 8-1b gates the guided-welcome on onboarding-completion state (Story 2.4/2.5a shells), NOT dashboard emptiness (else a returning student between terms wrongly gets the day-one welcome); no dashboard signal is added for it (handoff note for 8-1b, Sally).

### E. Reuse, new queries, clock

11. **Given** the reuse table (Dev Notes), **Then** the implementation REUSES `ListSessionsByRange`, `ListStudents` (at-risk inputs), `GetStudentAttendanceStats`, `ListStudentAssignments`, `Count/ListUnassignedStudents`, `ListOverCapacityClasses`, `ListStaffMembers`/staff last-active, `Count/ListQuestionsForReader`, the `current_grades` view, and `files` `used_bytes` — and adds ONLY the new aggregates named in D6 (grading-backlog count+queue, student recent-grades, owner pulse counts + `todaySessions`, pending-invites count). Every new `.sql` follows the LATERAL/set-based idiom; every window uses the bound `@now` bucketed in `centers.timezone` (D8); `codegen.sh` (sqlc) run (WF-3). **Every `≤N`/top-N rail (needsGrading, unansweredQuestions, atRiskStudents, dueSoon, recentFeedback) MUST have a deterministic TOTAL order — append `, id` as the final tiebreak** (the 7-2a `released_at`-nondeterminism lesson: `LIMIT N` over a non-unique sort key makes the *slice membership* flaky, not just order — copy `ListGradingQueue`'s `ORDER BY submitted_at ASC NULLS LAST, id ASC`). The reused `ListSessionsByRange` orders `starts_at ASC` with **no id tiebreak** (`sessions.sql:60,73`) and is not LIMIT-capped, so `weekSessions`/`todaySessions`/`upcomingSessions` membership is stable — but tests MUST NOT assert positional order on same-start ties (Murat).
12. **Given** `AtRiskDetector`, **Then** it is reused UNCHANGED (no new copy of the 0.70 / 2 / 1.0 thresholds; import the consts) and classifies each role's student set in Go with no per-student query fan-out (D5).

### F. R31/PERF-2 performance harness (KEYSTONE — D7)

13. **Given** the new reusable query-count harness (counting boundary = the tx the service runs on, NOT the pool — D7(1)), **When** `GET /api/dashboard` is exercised per role against a seeded multi-tenant dataset, **Then** it asserts the query count per invocation is `≤ N` — **N a fixed named constant per role, documented as `1 (SET LOCAL) + k sqlc calls`** with tx plumbing filtered or offset — and it is PROVEN to fail on a synthetic N+1 (WF-8 red). The helper lives in `internal/test`, reusable by 8.2/8.4.
14. **Given** the EXPLAIN harness, **When** each role's plan is captured against the seeded dataset **with `SET LOCAL enable_seqscan = off`** (model: `audit_logs_rls_test.go:241-262` — without it, Postgres seq-scans tiny seeded tables and the assertion FALSE-REDS), **Then** it asserts **no `Seq Scan`** on the tenant-filtered index columns (`center_id`/`class_id`/`teacher_id`) **and on the driving `submissions` relation of the grading-backlog query** (a `status`-filter seq scan would otherwise pass the join-column check, Winston) — a missing/unused index fails it; if a plan regresses, flag a partial `submissions(status)` index (Task 6, WF-2). Runs in CI. (EXPLAIN is green-phase, not in the red set — plan tests are environment-brittle; the red gate is AC13/AC15-17.)

### G. Security — per-role & cross-tenant isolation (WF-8 red-first)

Every negative below MUST carry a **POSITIVE control in the same test** (house rule + 7-2a idiom): first assert the caller's OWN row IS present, THEN assert the other party's is absent — otherwise a scoping bug that returns "empty for everyone" silently passes both the isolation AND the ≤N assertions.

15. **Given** two teachers in the same center, **When** teacher A calls `GET /api/dashboard`, **Then** `needsGrading`/`unansweredQuestions`/`atRiskStudents`/`weekSessions` contain teacher-A's own-class rows (positive) and **exclude** teacher-B's (negative) — teacher-scope, D4. Adversarial test.
16. **Given** a student caller, **Then** the payload includes that student's own sessions/assignments/grades/questions (positive) and exposes **no class averages and no other student's rows** (negative; seed a second student with graded work, assert absence) — FR-50.
